## 1. 背景与目标

家教对接平台 MVP 已完成 M1、M2、M3、M4、M5 阶段验收。M5 托管环境最终验收确认，CloudBase Run 测试服务已在真实公网地址下完成 `npm run m5:hosted:verify` 复验，HTTP flow 与 50 虚拟用户 load 均通过。

MVP 发布前收口阶段已围绕产品说明、生产环境变量清单、测试账号管理、上线回滚预案、正式生产禁用测试登录确认、代码底层架构和规范性进行了集中治理。当前项目可以从“测试托管环境验收通过”推进到“正式生产环境小范围试运行”。

本阶段目标是完成 MVP 的正式生产小范围试运行上线，而不是扩大 MVP 业务范围或直接公开大规模推广。

核心目标：

- 建立独立生产环境。
- 配置正式生产环境变量。
- 禁用所有测试登录能力。
- 使用生产专用强随机密钥。
- 明确正式登录或受控试运行登录方案。
- 明确测试账号、试运行账号、真实用户账号边界。
- 完成生产部署、生产冒烟、回滚演练和上线验收。
- 形成上线说明、生产配置清单、回滚预案、验收报告。
- 将公开列表约 1000 条近期公开记录分页上限纳入后续技术债或 vNext 性能优化清单。

## 2. 上线口径

本阶段采用“小范围生产试运行”，不是直接公开上线。

定义：

- 使用真实生产环境或正式试运行生产环境。
- 使用生产配置与生产密钥。
- 禁用测试登录。
- 面向内部人员和少量受邀种子用户开放。
- 不做大规模公开推广。
- 允许收集真实业务反馈，但必须保留回滚和人工干预能力。

不建议直接公开上线的原因：

- 正式登录方案、运营处理机制、监控告警、用户协议和隐私说明仍需进一步完善。
- vNext 的真实性、认证、审核和风控能力尚未进入当前阶段。
- 当前更适合先验证真实生产环境下的 MVP 闭环和运营响应能力。

## 3. 试运行时间窗口与退出标准

本 Spec 将“小范围生产试运行”定义为有时间盒、有退出标准的生产阶段，避免试运行无限期停留。

默认建议：

- 首轮试运行时间窗口建议为 30 天。
- 时间窗口从生产 URL 对首批受邀用户开放当日开始计算。
- 项目总控制人可在上线前确认更短或更长窗口，但必须在上线验收报告中记录。

从“小范围生产试运行”升级为“公开上线”前，至少满足：

- 正式登录方案已稳定可用，不依赖 M5 测试登录、`000000` 测试验证码或临时测试身份头。
- 生产核心流程完成至少一轮真实用户冒烟或种子用户试用验证。
- 未出现联系方式未授权泄露、非参与者读取会话、测试登录可在生产使用等 P0/P1 安全问题。
- 已完成基础隐私说明展示，并明确用户退出或试运行结束后的数据处理方式。
- 已归档生产上线验收报告和试运行观察记录。
- 公开列表约 1000 条近期公开记录分页上限已进入技术债或 vNext 性能优化清单。

试运行应停止新增用户或触发回滚评估的情况：

- 生产登录不可用且 30 分钟内无法定位。
- 核心发布、筛选、聊天或联系方式交换流程不可用。
- 联系方式保护失效。
- 数据权限出现越权。
- 生产环境出现可用测试登录路径。
- 生产环境大面积 5xx 或服务不可访问。

## 4. 用户与运营范围

| 用户类型 | 说明 | 本阶段开放策略 |
| --- | --- | --- |
| 内部测试人员 | 产品、开发、运营或业务方指定人员 | 开放 |
| 种子家长/学生 | 少量受邀真实需求方 | 可控开放 |
| 种子大学生老师 | 少量受邀可授课大学生 | 可控开放 |
| 普通公网用户 | 未经邀请的自然访问用户 | 暂不主动推广 |

种子用户机制要求：

- 上线前必须形成试运行账号名单或识别方式。
- 建议首轮种子家长/学生和种子大学生老师都保持小规模，具体人数由项目总控制人确认后写入上线检查清单。
- 邀请发起人、审批人和名单维护人必须明确。
- 种子用户如出现骚扰、虚假信息、绕过授权索要联系方式、恶意发布等行为，应允许运营侧移出试运行名单并记录处理原因。

## 7. 生产环境与安全边界

### 7.1 生产上线定义

本阶段的“正式生产上线”必须同时满足：

- 服务部署在正式生产 CloudBase Run 或等价生产环境。
- 使用生产环境变量。
- 使用生产独立数据环境，或明确隔离的正式试运行数据环境。
- `APP_ENV=production`。
- 不启用 `M5_ENABLE_HOSTED_TEST_LOGIN=true`。
- 不启用 `NEXT_PUBLIC_ALLOW_TEST_LOGIN=true`。
- `/api/auth/test-login` 在生产环境不可用。
- `x-ungradu-test-user-phone` 备用测试身份路径在生产环境不可用。
- 生产 `AUTH_SESSION_SECRET` 独立强随机，不复用测试密钥。
- 完成生产 URL 下核心流程冒烟。
- 有回滚预案和回滚验收路径。
- 有上线验收报告归档。

### 7.2 生产环境变量

生产必须配置：

```text
APP_ENV=production
AUTH_SESSION_SECRET=<生产专用强随机密钥>
CLOUDBASE_ENV_ID=<生产 CloudBase 环境 ID>
TENCENTCLOUD_SECRETID=<生产环境腾讯云 SecretId>
TENCENTCLOUD_SECRETKEY=<生产环境腾讯云 SecretKey>
```

生产必须关闭或不设置：

```text
M5_ENABLE_HOSTED_TEST_LOGIN
NEXT_PUBLIC_ALLOW_TEST_LOGIN
```

禁止事项：

- 禁止将真实密钥写入 Git。
- 禁止将真实密钥写入规划文档正文。
- 禁止在聊天记录、报告正文中记录完整 SecretId、SecretKey、AUTH_SESSION_SECRET。
- 禁止复用测试环境 `AUTH_SESSION_SECRET`。
- 禁止使用 M5 测试登录作为真实用户登录方式。

### 7.3 生产禁用测试登录

必须验证：

- 生产环境 `APP_ENV=production` 生效。
- `/api/auth/test-login` 返回拒绝结果。
- 即使误配 `M5_ENABLE_HOSTED_TEST_LOGIN=true`，生产仍拒绝测试登录。
- 即使误配 `NEXT_PUBLIC_ALLOW_TEST_LOGIN=true`，生产仍拒绝测试登录。
- 通过 `x-ungradu-test-user-phone` 请求头伪造测试用户时，生产仍拒绝。
- 前端页面不展示“测试验证码 000000”“测试账号登录”等测试入口。
- 登录态 Cookie 使用生产密钥签发。
- 生产密钥轮换影响已说明：轮换后现有在线用户会被强制登出。

### 7.4 联系方式与数据权限保护

联系方式保护仍是正式生产试运行的核心安全主线。

必须保证：

- 未授权前，任何页面和接口都不得返回对方联系方式。
- 需求详情和家教信息详情不得展示联系方式。
- 聊天接口在未授权前不得返回对方联系方式。
- 同意交换联系方式必须二次确认。
- 只有完成双方授权和二次确认后，才允许在对应聊天会话中返回双方存档联系方式。
- 非会话参与者不能读取会话、消息、交换请求或授权联系方式。
- 用户不能通过改 URL、改 ID、抓包或枚举接口查看他人聊天、联系方式、需求或家教信息。

## 8. 正式登录方案

生产环境不能依赖 M5 测试登录。

上线前必须明确真实用户登录方式，并形成执行记录。若正式短信登录尚未接入，则不得进行完全公开上线，只能做受控试运行或生产预发布。

最低执行细则：

- 明确验证码或确认信息发送渠道：正式短信网关、人工微信、邮件或其他项目总控制人确认的渠道。
- 明确白名单手机号维护主体。
- 明确白名单存储位置。
- 明确新增试运行账号审批流程。
- 明确临时登录方案有效期。
- 明确临时登录方案退出条件。
- 明确不得使用 `000000` 测试验证码作为生产登录手段。

推荐口径：

- 优先使用“受邀手机号白名单 + 正式验证码”。
- 如正式短信服务暂未就绪，可在小范围试运行内采用“受邀手机号白名单 + 运营确认机制”，但必须记录风险、有效期和退出条件。
- 临时运营确认机制不得扩大到未受邀公网用户。

上线前待项目总控制人确认：

- 本次试运行采用哪一种登录渠道。
- 白名单由谁维护。
- 白名单存储在哪里。
- 新增或移除试运行账号由谁审批。
- 临时方案最长有效期。

## 9. 测试账号与试运行账号管理

必须区分：

| 账号类型 | 用途 | 可否在生产使用 |
| --- | --- | --- |
| M5 测试账号 | 自动化验收、测试托管环境验证 | 不可 |
| 本地开发账号 | 本地开发调试 | 不可 |
| 试运行账号 | 受邀真实用户或内部试运行人员 | 可 |
| 真实用户账号 | 小范围真实业务使用 | 可控开放 |

必须说明：

- 测试账号不得迁入生产。
- 测试数据不得混入生产。
- 试运行账号应有名单或识别方式。
- 生产问题排查不得直接读取或公开用户敏感联系方式。
- 清理测试数据时不得误删真实用户数据。
- 用户退出试运行或试运行结束后，必须说明其数据删除、匿名化或留存策略。

## 10. 隐私与数据合规说明

生产试运行前必须提供最简版隐私说明。

至少说明：

- 平台收集手机号、身份入口选择、家长需求、大学生家教信息、站内聊天内容、存档联系方式和反馈内容。
- 收集目的为账号登录、供需发布、站内沟通、联系方式交换、问题处理和安全追查。
- 存档联系方式默认不公开，仅在双方同意并二次确认后展示给对应会话双方。
- 用户退出试运行、要求删除数据或试运行结束后的数据处理方式。
- 生产问题排查不得在非必要场景公开或复制用户敏感联系方式。

上线前阻塞要求：

- 基础隐私说明已在页面或试运行说明中展示给受邀用户。
- 若隐私说明暂不能完整产品化展示，至少应通过试运行邀请说明或上线说明同步给受邀用户，并在上线验收报告中记录。

## 11. 上线前待完成事项

正式生产试运行完成前，必须完成：

- 创建或确认生产 CloudBase 环境。
- 创建或确认生产 CloudBase Run 服务。
- 配置生产数据库集合。
- 配置生产环境变量。
- 配置生产域名或正式公网访问地址。
- 确认生产部署镜像或提交版本。
- 确认生产环境日志查看入口。
- 确认生产环境权限管理人员。
- 确认正式登录或受控试运行登录方案。
- 完成测试账号与试运行账号管理说明。
- 完成基础隐私说明。
- 完成生产禁用测试登录确认。
- 完成生产冒烟验收。
- 完成基础稳定性检查。
- 完成回滚预案和桌面演练或真实演练。
- 完成上线验收报告。

以下任一未完成，不得宣布生产试运行上线完成：

- 生产环境未配置 `APP_ENV=production`。
- 生产环境仍可使用 `/api/auth/test-login`。
- 生产页面仍展示测试登录入口。
- 生产 `AUTH_SESSION_SECRET` 复用测试密钥。
- 生产环境真实密钥被写入 Git 或文档正文。
- 核心流程无法在生产 URL 跑通。
- 联系方式未授权读取保护失败。
- 非参与者可读取会话或联系方式。
- 没有回滚预案。
- 没有生产环境变量清单。
- 没有测试账号与试运行账号边界说明。
- 没有基础隐私说明。
- 没有上线验收报告。
- 若正式短信登录未接入，却试图完全公开上线。

## 12. 生产冒烟验收

生产 URL 下必须完成以下路径。

核心访问与登录：

- 首页访问。
- 登录入口检查。
- 生产测试登录禁用检查。
- 登出。
- 重新登录后数据仍可读取。

核心发布与浏览：

- 家长身份入口进入。
- 大学生身份入口进入。
- 家长发布需求。
- 大学生发布家教信息。
- 家长浏览家教信息广场并筛选。
- 大学生浏览需求广场并筛选。
- 进入详情页。

聊天与联系方式交换：

- 发起站内聊天。
- 双方发送文字消息。
- 发起联系方式交换请求。
- 接收方同意。
- 二次确认后双方查看授权联系方式。

权限与反馈：

- 未授权用户不能读取他人联系方式。
- 非参与者不能读取会话。
- 反馈入口可访问并可提交或打开真实反馈渠道。
- 基础隐私说明可被受邀用户看到，或已通过试运行说明发送给受邀用户。

## 13. 生产性能与稳定性验收

最低要求：

- 生产环境完成一次小规模 HTTP flow。
- 生产环境完成一次基础并发验证。
- 可参考 M5 的 50 虚拟用户 load，但生产试运行阶段应根据云资源谨慎执行。
- 若不在生产执行压测，必须说明原因，并以测试托管压测结果作为参考，不得混称为生产压测。

建议指标：

| 指标 | 目标 |
| --- | --- |
| HTTP flow 成功率 | 100% |
| 基础 load 成功率 | 99% 以上 |
| 核心 API 错误率 | 1% 以下 |
| 首页可访问 | 必须 |
| 核心流程可完成 | 必须 |
| 联系方式未授权读取 | 必须拒绝 |

## 14. 回滚与问题处理要求

必须形成可执行回滚文档。

至少包含：

- 当前上线提交。
- 当前上线镜像。
- 上一稳定提交。
- 上一稳定镜像。
- CloudBase Run 回滚方式。
- 环境变量回滚方式。
- 数据库变更是否可逆。
- 回滚触发条件。
- 回滚执行人。
- 回滚后验收步骤。
- 回滚通知口径。

回滚触发条件：

- 生产登录不可用。
- 核心发布流程不可用。
- 聊天不可用。
- 联系方式保护失效。
- 出现测试登录可在生产使用。
- 数据权限出现越权。
- 生产环境大面积 5xx。
- 无法在 30 分钟内定位的核心路径故障。

问题处理最低要求：

- 能查看 CloudBase Run 服务状态。
- 能查看服务运行日志。
- 能查看部署版本。
- 能查看环境变量配置但不泄露真实值。
- 能定位核心 API 5xx。
- 能人工确认反馈入口收到的问题。
- 能记录生产问题处理过程。
- 工作时间内收到试运行反馈后建议 2 小时内确认收到；核心路径故障必须立即进入定位或回滚评估。
- 必须明确值守人或兜底负责人。

## 15. 上线说明

面向用户说明：

- 平台是家教自助撮合 MVP。
- 当前免费。
- 平台不做支付担保。
- 平台不做线下交易保障。
- 平台不做老师资质强审核。
- 用户需自行判断授课风险。
- 联系方式需双方同意后交换。
- 遇到虚假信息、骚扰、联系方式滥用可通过反馈入口联系平台。
- 当前处于小范围试运行，功能可能持续调整。
- 基础隐私说明应告知用户收集信息范围、用途和退出后的数据处理方式。

面向内部说明：

- 当前上线范围。
- 当前不包含范围。
- 种子用户规模和名单维护方式。
- 已知技术债。
- 试运行观察指标。
- 问题反馈路径。
- 应急联系人和响应方式。

## 16. 风险与后续迭代

### 16.1 公开列表约 1000 条近期公开记录分页上限

当前状态：

- M5 已修复新发布公开记录不可见问题。
- 当前公开列表读取约 1000 条近期公开记录。
- 当有效公开记录超过约 1000 条时，较旧记录可能退出公开列表窗口。

本阶段处理：

- 不阻塞生产小范围试运行。
- 必须写入技术债清单。
- 必须在 vNext 性能优化中规划游标分页、数据库索引或服务端分页 API。

### 16.2 证明图片能力边界

当前状态：

- MVP 不应暗示已具备正式证明图片审核能力。

本阶段处理：

- 产品说明中明确边界。
- 页面文案不得夸大。
- 真实图片上传、查看、审核进入 vNext 真实性迭代。

### 16.3 正式短信登录能力

当前风险：

- 如果未接入正式短信服务，则生产公开登录不可直接开放。

本阶段处理：

- 小范围试运行前必须确认真实登录方案。
- 若暂不接短信，只能做受控试运行。
- 公开上线前必须补正式登录方案 Spec 或修订本 Spec。

### 16.4 运营审核与风控

当前状态：

- MVP 仅提供基础规则和联系方式保护。
- 不提供完整审核、举报封禁、实名认证。

本阶段处理：

- 试运行期间采用人工观察和反馈入口处理。
- vNext 再设计真实性、认证、审核后台、举报封禁。

### 16.5 vNext 候选方向

以下能力不进入本阶段，但应进入后续产品迭代讨论：

- 双端初步认证。
- 实名认证。
- 聊天图片上传。
- 管理系统。
- 风险追查。
- 认证材料审核。
- 更完整日志和审计。
- 公开列表可扩展分页方案。

## 20. 产品经理判断

当前不建议直接大规模公开上线。

建议采用：

```text
MVP 完结
-> 正式生产环境上线
-> 小范围生产试运行
-> 收集真实问题
-> vNext 真实性与风控迭代
-> 再考虑公开推广
```

## 1. 阶段目标

本阶段目标是把已完成 M1-M5 验收的 MVP 推进到“正式生产环境小范围试运行”。

本阶段不是 vNext，不扩大 MVP 范围，不新增支付、评价、审核后台、实名认证、举报封禁、自动推荐、复杂排课、合同、图片聊天等能力。

交付目标：

- 生产环境可访问。
- 生产环境变量按 Spec 配置。
- 生产测试登录禁用验证通过。
- 生产核心流程冒烟通过。
- 回滚预案和问题处理机制可执行。
- 上线验收报告可归档。
- 项目进入小范围生产试运行，而不是公开大规模上线。

## 2. 任务分工

### 2.1 代码开发员 Agent 负责

代码开发员 Agent 只处理代码、脚本、工程验证和技术执行材料，不负责替业务方拍板账号、密钥、用户规模和登录渠道。

代码侧待办：

1. 读取正式上线 Spec 和本执行说明。
2. 核查生产环境安全边界是否仍满足：
   - `APP_ENV=production` 时拒绝 `/api/auth/test-login`。
   - `APP_ENV=production` 时拒绝 `x-ungradu-test-user-phone`。
   - 即使误配 `M5_ENABLE_HOSTED_TEST_LOGIN=true` 或 `NEXT_PUBLIC_ALLOW_TEST_LOGIN=true`，生产仍拒绝测试登录。
   - 前端生产页面不展示测试登录入口、测试验证码或测试账号提示。
3. 运行本地工程验证：
   - `npm run typecheck`
   - `npm test`
   - `npm run lint`
   - `npm run build`
4. 运行或补充生产预检：
   - 优先运行 `npm run release:production:preflight`。
   - 若预检脚本缺少 Spec 要求的关键检查，应补齐脚本或测试，再复跑。
5. 配合生产部署：
   - 确认生产部署使用的提交、镜像和运行环境。
   - 不在 Git、文档正文或聊天记录中写入真实 Secret。
   - 不把 M5 测试托管环境变量复制到正式生产。
6. 配合生产冒烟：
   - 在生产 URL 可用后，按本文件第 7 节执行或协助执行冒烟验证。
   - 若生产环境不适合压测，记录原因；不得把测试托管压测说成生产压测。
7. 修复代码偏差：
   - 若出现生产测试登录可用、联系方式未授权泄露、非参与者可读取会话、核心流程不可用等问题，必须优先修复。
   - 修复后重新运行工程验证和生产相关验证。

代码开发员 Agent 不负责：

- 创建腾讯云账号或开通 CloudBase 权限。
- 决定生产 Secret 明文。
- 决定正式登录渠道。
- 决定首轮种子用户规模。
- 决定是否从小范围试运行升级公开上线。
- 修改产品范围或引入 vNext 能力。

## 4. 代码侧待办拆解

### 4.1 生产安全边界复核

目标：证明生产环境不会启用任何测试登录能力。

代码开发员需核查：

- `/api/auth/test-login` 在 `APP_ENV=production` 下不可用。
- `x-ungradu-test-user-phone` 在 `APP_ENV=production` 下不可用。
- `M5_ENABLE_HOSTED_TEST_LOGIN=true` 和 `NEXT_PUBLIC_ALLOW_TEST_LOGIN=true` 即使误配也不能打开生产测试登录。
- 前端生产构建不展示测试验证码、测试账号登录入口或测试用户提示。

建议验证命令：

```powershell
Set-Location Code文档
npm run release:production:preflight
npm test
npm run build
```

如需模拟误配生产构建：

```powershell
Set-Location Code文档
$env:APP_ENV='production'
$env:M5_ENABLE_HOSTED_TEST_LOGIN='true'
$env:NEXT_PUBLIC_ALLOW_TEST_LOGIN='true'
npm run build
Remove-Item Env:\APP_ENV
Remove-Item Env:\M5_ENABLE_HOSTED_TEST_LOGIN
Remove-Item Env:\NEXT_PUBLIC_ALLOW_TEST_LOGIN
```

验收期望：

- 预检通过。
- 生产测试登录仍被拒绝。
- 构建通过不代表测试登录可用；必须以预检和测试断言确认硬拒绝。

### 4.2 生产部署前工程验证

代码开发员需在 `Code文档` 目录运行：

```powershell
npm run typecheck
npm test
npm run lint
npm run build
```

验收期望：

- 四项全部通过。
- 若失败，必须记录失败命令、失败原因、修复提交和复跑结果。

### 4.3 生产环境变量检查

代码开发员需协助形成 `生产环境变量清单.md`。

清单只能记录变量名、用途、是否已配置、配置位置、是否需要轮换，不记录真实值。

生产必须配置：

```text
APP_ENV=production
AUTH_SESSION_SECRET=<生产专用强随机密钥>
CLOUDBASE_ENV_ID=<生产 CloudBase 环境 ID>
TENCENTCLOUD_SECRETID=<生产环境腾讯云 SecretId>
TENCENTCLOUD_SECRETKEY=<生产环境腾讯云 SecretKey>
```

生产必须关闭或不设置：

```text
M5_ENABLE_HOSTED_TEST_LOGIN
NEXT_PUBLIC_ALLOW_TEST_LOGIN
```

### 4.4 生产 URL 冒烟协助

生产 URL 可访问后，代码开发员需配合执行：

- 首页访问。
- 登录入口检查。
- 测试登录禁用检查。
- 家长发布需求。
- 大学生发布家教信息。
- 双边广场筛选。
- 详情页不展示联系方式。
- 发起聊天。
- 双方发送文字消息。
- 请求交换联系方式。
- 同意并二次确认。
- 授权后查看联系方式。
- 未授权联系方式读取拒绝。
- 非参与者读取会话拒绝。
- 反馈入口可用。
- 登出可用。

如果使用脚本验证：

```powershell
Set-Location Code文档
$env:M5_BASE_URL='<生产或预发 URL>'
npm run m5:hosted:verify
Remove-Item Env:\M5_BASE_URL
```

注意：

- 只有在生产或预发登录方案允许脚本账号登录时，才可使用自动化脚本。
- 不得为了跑 `m5:hosted:verify` 在正式生产打开 `M5_ENABLE_HOSTED_TEST_LOGIN=true`。
- 如果生产不允许自动化测试登录，应改为人工冒烟或专门的受控试运行账号验证，并记录原因。

### 4.5 正式登录方案相关代码工作

若项目总控制人确认使用正式短信登录，则代码开发员需按独立技术任务实现或验证短信登录。

若项目总控制人确认使用受邀手机号白名单 + 运营确认机制，则代码开发员只做必要的登录入口、会话、安全边界验证，不得自行创造新的认证业务流程。

任何登录方案变更都必须先明确：

- 渠道。
- 账号名单维护方式。
- 审批流程。
- 有效期。
- 退出条件。
- 风险说明。

未确认前，不得把 `000000` 测试验证码或 M5 测试登录作为生产登录手段。

## 7. 阻塞条件

以下任一未完成，不得宣布生产试运行上线完成：

- 生产环境未配置 `APP_ENV=production`。
- 生产环境仍可使用 `/api/auth/test-login`。
- 生产页面仍展示测试登录入口。
- 生产 `AUTH_SESSION_SECRET` 复用测试密钥。
- 生产环境真实密钥被写入 Git 或文档正文。
- 核心流程无法在生产 URL 跑通。
- 联系方式未授权读取保护失败。
- 非参与者可读取会话或联系方式。
- 没有回滚预案。
- 没有生产环境变量清单。
- 没有测试账号与试运行账号边界说明。
- 没有基础隐私说明。
- 没有上线验收报告。
- 若正式短信登录未接入，却试图完全公开上线。

## 8. 必须暂停确认项

以下事项必须由项目总控制人、业务方或运维负责人确认。确认前，代码开发员可以做本地工程验证和文档草案，但不得宣布生产上线完成。

| 暂停确认项 | 为什么需要确认 | 未确认时允许继续做什么 |

| 生产 CloudBase 环境与服务 | 代码开发员无法替业务方创建或授权生产云资源 | 本地验证、文档草案、预检脚本验证 |

| 生产独立强随机 `AUTH_SESSION_SECRET` | 涉及生产会话安全，且不得复用测试密钥 | 只确认变量要求和轮换影响 |
| 正式登录渠道 | 影响用户能否进入生产系统 | 先完成安全边界和页面无测试入口验证 |
| 白名单手机号维护主体与存储位置 | 影响受邀试运行账号管理 | 先起草账号管理说明 |
| 试运行账号新增 / 移除审批流程 | 影响运营边界和责任追溯 | 先起草流程模板 |
| 首轮试运行时间窗口和种子用户规模 | 属于产品与运营决策 | 使用 Spec 默认建议作为草案，不替业务方拍板 |
| 值守人、兜底负责人、回滚执行人 | 涉及生产事故响应责任 | 先起草回滚预案和问题处理记录模板 |

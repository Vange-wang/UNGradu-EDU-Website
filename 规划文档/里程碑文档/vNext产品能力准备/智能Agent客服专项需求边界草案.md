# 智能 Agent 客服专项需求边界草案

日期：2026-06-30

关联阶段：S5 vNext 产品能力拆解

关联任务：`RELEASE-S5-VNEXT-2026-06-30-001`

## 1. 背景

S3 / S4 已确认当前没有客服与人工介入能力。业务方也确认该角色后期可能需要另外搭建智能 Agent 客服承担。

智能 Agent 客服涉及用户资料、聊天、联系方式交换、举报投诉、未成年人信息和争议处理，不能直接作为简单页面功能上线。

## 2. 当前定位

本专项当前只做需求边界和风险定义，不接入真实用户数据，不上线对外客服，不承诺人工介入。

## 3. Agent 可处理范围草案

未来 Agent 可考虑处理：

- 平台使用说明。
- 登录、发布需求、发布家教信息、聊天、交换联系方式的操作指引。
- 风险提示说明。
- 举报 / 投诉入口引导。
- 常见问题解释。
- 引导用户不要公开手机号、微信、详细地址等敏感信息。

## 4. Agent 不可处理范围草案

未来 Agent 不应直接处理：

- 判断老师真实资质。
- 判断交易责任。
- 承诺退款、担保、赔偿或仲裁。
- 直接查看或披露用户联系方式。
- 直接读取完整聊天记录并给出争议裁决。
- 代替平台作出封禁、认证、付款、退款决定。
- 对未成年人安全问题作出最终处置承诺。

## 5. 必须先确认的数据边界

在进入实现前，必须明确：

- Agent 是否可以读取用户基础资料。
- Agent 是否可以读取当前会话上下文。
- Agent 是否可以读取历史聊天内容。
- Agent 是否可以读取联系方式交换记录。
- Agent 是否可以读取举报 / 投诉记录。
- Agent 的回答是否需要留存。
- Agent 会话记录保存多久。
- 用户是否可以知道自己正在和 Agent 对话。

## 6. 必须先确认的权限边界

在进入实现前，必须明确：

- Agent 是否只读。
- Agent 是否能创建举报 / 投诉记录。
- Agent 是否能修改用户资料、老师资料或需求状态。
- Agent 是否能触发人工升级。
- Agent 是否能标记风险等级。
- Agent 是否能向用户展示其他用户信息。

## 7. 验收前置条件

进入代码实现前至少需要：

- 独立智能 Agent 客服 Spec。
- 数据读取权限清单。
- 禁止回答清单。
- 用户提示文案。
- 会话记录与责任追溯规则。
- 高风险问题升级规则。
- 测试集：隐私、误答、越权、未成年人、联系方式、投诉争议。

## 8. 当前结论

智能 Agent 客服可以作为 S5 后续 P0 专项，但当前阶段只允许进入 Spec 与风险边界设计，不允许直接对外上线。

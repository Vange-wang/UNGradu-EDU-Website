## 验收判断

1. CSS 约束满足“窗口固定，消息列表内部滚动”。
   - `.dplus-chat-page .conversation-main` 已设置为三行 grid：`auto minmax(0, 1fr) auto`，并通过 `height: clamp(560px, calc(100vh - 180px), 760px)` 控制聊天主窗口高度。
   - `.dplus-chat-page .message-list` 已设置 `max-height: 100%`、`overflow-y: auto` 和 `overscroll-behavior: contain`，长消息和多消息会在消息列表内部滚动，不再继续撑高聊天主面板。

2. 输入区保持可用。
   - 聊天页 JSX 中消息区和输入表单是同一个 `.conversation-main` grid 的不同子区域。
   - `.chat-compose` 位于第三行，消息列表位于中间 `minmax(0, 1fr)` 区域；历史消息滚动不会把输入区持续挤走。

3. 390px 移动端布局风险可接受。
   - 980px 以下 `.conversation-workspace` 改为单列，避免三栏在窄屏横向挤压。
   - 720px 以下聊天主面板高度调整为 `clamp(520px, calc(100vh - 140px), 680px)`，消息列表 `min-height` 降为 `260px`，输入区改为单列按钮。
   - 消息气泡在移动端限制为 `max-width: min(100%, 320px)`，并保留 `overflow-wrap: anywhere`，长文本横向溢出风险可控。

4. 开发员未能进入真实聊天数据页的冒烟限制：接受。
   - 本问题根因和修复点集中在聊天页 CSS 布局约束，真实数据页与验证夹具使用同一组核心类名：`.dplus-chat-page`、`.conversation-main`、`.message-list`、`.message-bubble`、`.chat-compose`。
   - 总负责人记录显示：真实登录链路受本地邮箱登录和浏览器安全策略限制，未进入真实聊天数据页；开发执行代理使用真实 `globals.css` 和聊天 DOM 验证夹具完成桌面与 390px 冒烟，结果为无横向溢出，消息列表 `overflow-y: auto` 且 `scrollHeight > clientHeight`。
   - 从 UI 验收角度，该限制不阻塞本次 `ISSUE-0018` 关闭流程；后续如生产真实聊天页发现数据内容导致的新溢出，应另行登记或重开 Issue。

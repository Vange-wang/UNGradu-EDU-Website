## 2. 总体验收口径

本批页面是核心业务页，视觉目标不是“把所有东西都画得更漫画”，而是在 D+ 高对比风格下保持可读、可扫、可操作。

复核时优先级如下：

1. 业务闭环和信息层级清楚。
2. 公开页不展示联系方式。
3. 站内沟通 / 双方同意后交换联系方式的边界稳定可见。
4. 广场页列表扫描效率不被粗描边和硬阴影破坏。
5. 发布页表单清楚、分组明确，不鼓励用户把联系方式写进公开说明。
6. D+ token、粗黑描边、硬阴影、橙色主按钮、黄绿辅助色有落地，但不过量。
7. 桌面和移动端无明显文字出框、按钮挤压、横向溢出。

## 3. 广场页复核口径

适用页面：

- `/parent-needs`
- `/tutor-profiles`

### 3.1 必须符合

- 页面标题清楚区分“需求广场”和“家教信息广场”。
- 筛选区与列表区关系明确：桌面端建议左筛选、右列表；移动端可折叠或单列堆叠。
- 筛选项可读、可点击，不出现小按钮文字出框。
- 列表卡标题、元信息、状态标签、行动按钮层级清楚。
- 主行动按钮优先使用橙色，例如“查看详情”“站内沟通”等。
- 辅助标签可使用黄绿，但不要每个小字段都做粗黑框。
- 列表卡之间间距稳定，列表整体仍能快速扫描。
- 公开列表不展示手机号、微信号、邮箱等直接联系方式。

### 3.2 风险点

- 每条列表卡都加过强硬阴影，导致页面噪音过高。
- 筛选栏内部全是粗框，画面碎且拥挤。
- 标签过多，标题和关键信息被挤压。
- 主按钮和状态标签颜色层级混乱，用户不知道下一步点哪里。
- 移动端筛选按钮横向挤爆或产生横向滚动。

### 3.3 建议判定

- 如果列表可扫、筛选清楚、公开页不展示联系方式：可通过。
- 如果 D+ 风格存在但列表扫描效率下降明显：有条件通过，要求降噪。
- 如果公开展示联系方式或暗示自动推荐/评分排名：不通过。

## 4. 详情页复核口径

适用页面：

- `/parent-needs/[id]`
- `/tutor-profiles/[id]`

### 4.1 必须符合

- 主内容区与下一步行动区分开，不能混在一堆卡片里。
- 页面要稳定显示“联系方式未公开”或同等保护状态。
- “站内沟通”作为下一步主行动要明显，优先橙色按钮。
- 文案必须说明双方同意后再交换联系方式。
- 详情正文可读，不被标签、色块或插画压过。
- 不展示公开联系方式。
- 不使用“已认证”“平台审核通过”“高匹配度”“评分排名”等未实现能力口径。

### 4.2 风险点

- 行动侧栏在桌面端不明显，用户找不到下一步。
- 移动端行动区被放到很靠后的位置，联系方式状态不可见。
- D+ 视觉过重，正文阅读困难。
- 家教详情页出现认证徽章或资质暗示。
- 需求详情页出现平台推荐/匹配百分比。

### 4.3 建议判定

- 如果“主内容 + 下一步行动 + 联系方式保护”三件事稳定可见：可通过。
- 如果视觉风格到位但行动区不明显：有条件通过，要求强化行动区。
- 如果展示联系方式或暗示认证/担保/推荐：不通过。

## 5. 发布页复核口径

适用页面：

- `/parent-needs/new`
- `/tutor-profiles/new`

### 5.1 必须符合

- 表单是清楚的分组表单，不做复杂 step 动画。
- 发布需求至少能看出：基本信息、时间预算、补充说明等分组。
- 发布家教资料至少能看出：个人介绍、授课信息、补充说明等分组。
- 输入框、下拉框、文本域文字完整在容器内。
- 主提交按钮明显，优先橙色。
- 必须提示公开说明里不要填写联系方式，或以同等文案说明公开页不展示联系方式。
- 不鼓励用户在公开说明中填写手机号、微信号、QQ、邮箱等直接联系方式。

### 5.2 风险点

- 每个字段都变成强卡片，导致表单太重、太长。
- 文字说明过多，移动端输入区域被压缩。
- 按钮在移动端被硬阴影挤出屏幕。
- placeholder 使用手机号/微信号示例。
- 发布家教资料出现实名认证、资质审核、平台审核等暗示。

### 5.3 建议判定

- 如果表单分组清楚、字段可读、联系方式边界明确：可通过。
- 如果视觉过重但不影响功能理解：有条件通过，建议表单降噪。
- 如果鼓励填写公开联系方式或暗示审核认证：不通过。

## 6. D+ 视觉一致性检查

本批页面应延续第 1 批已通过的 D+ 系统：

- 纸白底：`#fffdf0` 或接近值。
- 黑色描边：主要组件约 `3px`，强视觉块可 `4px`。
- 硬阴影：桌面可 `8px 8px 0 #111111` 或 `6px 6px 0 #111111`；移动端建议收敛到 `5px 5px 0 #111111`。
- 主按钮：橙色 `#ff6b2b`，黑描边，高对比。
- 辅助状态：黄绿 `#b8ff42`、奶黄 `#fff7cf`。
- 背景：黄 / 青绿渐变可以保留，但内容区不要满屏高饱和。
- 字体：中文标题粗，但不得撑爆容器；正文和元信息保持可读。

不过量标准：

- 广场页和发布页不应把每个字段、每个 chip 都做成强阴影卡。
- 同屏强硬阴影组件过多时，应优先保留主容器、列表容器、主按钮，减少内部元素阴影。
- 黑色大面积块只用于少量强调，不应成为列表主体背景。

## 7. 移动端复核口径

移动端重点看以下问题：

- 是否存在横向溢出。
- 筛选区是否压缩按钮文字。
- 列表卡标题是否超过容器或被按钮挤压。
- 主按钮是否最小高度不低于约 `44px`。
- 硬阴影是否导致卡片实际宽度超出视口。
- 详情页“联系方式未公开 / 站内沟通”是否不需要滚动太久才能看到。
- 发布页字段间距是否足够，文本域是否可输入长内容。
- 标签、按钮、状态 pill 是否允许换行或有足够最小宽度。

如果总负责人只做桌面冒烟，正式复核结论中应注明移动端证据不足；若已有移动端 `/parent-needs`、`/tutor-profiles`、详情和发布页截图或冒烟结果，应纳入最终结论。

## 8. 禁止项检查

本批任何页面不得暗示：

- 支付。
- 担保。
- 退款。
- 合同。
- 实名认证。
- 资质认证。
- 平台人工审核。
- 人工客服仲裁。
- 自动推荐算法。
- 评分排名。
- 匹配百分比。

联系方式边界：

- 公开广场页和详情页不得展示手机号、微信号、QQ、邮箱等直接联系方式。
- 发布表单不得鼓励用户把联系方式写入公开说明。
- 详情页和发布页应稳定提醒：先站内沟通，双方同意后再交换联系方式。

## 10. 预设结论规则

- **通过**：视觉系统一致，业务边界无误，无明显出框/溢出/拥挤，移动端无明显风险。
- **有条件通过**：主体可用，但存在 1-3 个可快速修复的视觉或文案问题，不影响业务边界。
- **不通过**：出现公开联系方式、未实现能力暗示、严重移动端溢出、关键按钮不可读、核心流程信息混乱等问题。

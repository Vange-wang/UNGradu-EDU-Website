# 智能 Agent 客服专项占位说明

日期：2026-06-30

阶段：发布阶段 S3

## 1. 结论

当前 S3 不实现客服与人工介入，也不实现智能 Agent 客服。

智能 Agent 客服应作为后期独立专项，不得在当前发布验收中写成已具备能力。

## 2. 后期专项需先明确的问题

- Agent 客服能回答哪些问题，不能回答哪些问题。
- Agent 是否允许读取用户资料、聊天记录、联系方式交换记录、反馈记录。
- 涉及未成年人、联系方式、投诉、退款、资质争议时如何升级。
- Agent 输出是否需要人工复核。
- 如何记录 Agent 会话。
- 如何追溯处理责任。
- 如何避免误答、越权答复、隐私泄露和误导用户。
- 是否需要人工工作台配合。

## 3. 数据权限边界草案

后续设计前，默认最小权限：

- 不读取密码、验证码、密钥。
- 不输出完整联系方式，除非用户本身已在授权场景中可见。
- 不替用户承诺退款、认证、合同、平台担保。
- 不给出法律、医疗、财务等高风险确定性建议。

## 4. 与 S3 的关系

S3 只记录该能力缺口和后期规划入口。

公开推广前如仍未建设客服 / 人工介入 / 智能 Agent 客服，S4 必须在风险清单中明确：平台不具备即时客服承接能力，公开推广范围应受限。

## 2. 协作原则

- 每个会话线程对应一个专业 Agent。
- 每个 Agent 必须先完成身份注册，再接收正式任务。
- 每个任务必须明确任务来源、目标、输入边界、输出边界、产出目录和验收方式。
- 项目总负责人 Agent 负责分发和编排任务，但不替专业 Agent 输出越权产物。
- 独立代码复核 Agent 仅按固定点、限定 diff、canonical Issue/Spec 和开发验证证据执行 Standards/Spec 两轴只读复核，输出 `TECH_REVIEW_PASS` 或 `TECH_REVIEW_REWORK_REQUIRED`，不实现修复、不自我批准、不替其他角色产出。
- 业务方后续提供的工作流程 Markdown 文档，将作为正式任务编排依据。
- 任何关键沟通必须归档到 `协同工作文档/交流记录/`。
- 阶段任务执行默认遵守 `协同工作文档/阶段任务闭环工作流.md`，除非项目总控制人另行覆盖。

## 3. 任务分发最小字段

后续总负责人向专业 Agent 下发任务时，至少包含：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 任务 ID | 是 | 用于跨 Agent 追踪 |
| 发起方 | 是 | 通常为业务方或项目总负责人 |
| 执行 Agent | 是 | 指定唯一主责 Agent |
| 任务目标 | 是 | 本轮要完成什么 |
| 输入材料 | 是 | 需读取的文档、Issue、代码路径或用户确认 |
| 输入边界 | 是 | 哪些内容可以作为依据，哪些不能越权使用 |
| 输出要求 | 是 | 交付物格式、路径、验收材料 |
| 输出边界 | 是 | 明确不能输出什么 |
| 验收标准 | 是 | 判断完成的条件 |
| 阻塞回报格式 | 是 | 缺少信息时如何回报 |

## 4. 责任溯源规则

| 问题类型 | 首查方向 | 修复动作 |
| --- | --- | --- |
| 需求不清 | 任务目标、业务规则、输入材料、验收标准是否缺失 | 由总负责人召回任务；产品经理补清需求；业务方确认关键问题 |
| 实现偏差 | 产出是否偏离已确认 Spec、任务命令或输入边界 | 退回执行 Agent 最小修复；补验证证据；更新工作日志 |
| 验收缺失 | 是否缺少测试、报告、截图、部署验证或验收结论 | 指派验收 Agent 补验；补齐验收记录；必要时重开 Issue |
| 消息协议不完整 | 交接字段、任务 ID、会话 ID、责任字段是否缺失 | 总负责人修订协议模板；重新下发任务；归档协议变更 |

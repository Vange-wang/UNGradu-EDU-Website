# 风控与审核 Spec

日期：2026-06-30

阶段：发布阶段 S3

状态：正式规则 Spec

## 1. 目标

建立当前 MVP 小范围生产试运行所需的最低可信边界，降低未成年人信息、联系方式、老师资料真实性、公开展示和站内沟通带来的风险。

## 2. 适用对象

- 家长 / 学生。
- 大学生老师。
- 平台总负责人 / 后续运营角色。
- 后期可能建设的智能 Agent 客服。

## 3. 风险分类

| 风险 | 说明 | 当前 S3 处理方式 |
| --- | --- | --- |
| 未成年人信息 | 家长 / 学生可能填写年级、地址、联系方式、学习情况 | 页面和规则提示避免公开敏感信息；联系方式通过交换机制控制 |
| 联系方式泄露 | 用户可能在公开内容或聊天中主动留下电话、微信 | 规则提示、联系方式交换、反馈入口、后续人工 / Agent 专项 |
| 老师资料真实性 | 老师身份、学校、资质、经验可能不真实 | 当前不承诺认证，只做资料审核规则和风险提示 |
| 私下交易风险 | 双方可能线下交易、退款或纠纷 | 当前不做担保交易，必须提示平台不承担支付担保 |
| 骚扰 / 不当内容 | 聊天或发布内容可能出现违规信息 | 当前保留反馈入口和 Issue 记录，后续需要审核 / Agent 能力 |

## 4. 当前 S3 最小规则

- 公开页面不展示用户联系方式。
- 公开页面不展示 ownerUserId、集合名、验证码、密码 hash、内部请求 ID。
- 联系方式必须通过联系方式交换链路展示。
- 老师资料不应被表述为“平台已认证”，除非后续真实认证能力落地。
- 页面或规则文案应提醒用户谨慎线下交易、谨慎提前付款、注意隐私保护。
- 当前无客服和人工介入时，不得承诺平台可即时处理纠纷。

## 5. 后续进入开发的最小范围

后续若进入 S3 代码任务，优先级建议：

1. 在发布表单和详情页补充风险提示文案。
2. 在反馈入口增加“举报 / 风险反馈”分类。
3. 在联系方式交换确认处强化隐私提醒。
4. 在老师资料展示处避免“认证”暗示。

上述代码任务需要单独执行包和验收报告，不在本次文档收口中直接实现。

## 6. 不做范围

- 不做实名认证。
- 不做资质认证等级。
- 不做人工审核后台。
- 不做智能 Agent 客服。
- 不做支付担保。
- 不做退款、投诉仲裁。

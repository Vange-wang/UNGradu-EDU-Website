## 1. 背景

项目总控制人已确认当前网站核心功能正常，准备进入下一轮迭代。

本轮新增明确要求：

- 迭代版本需要删除 UI 界面中多余的说明文字。
- 负责人只做任务分配、跟进和验收，不直接改业务代码。
- 本轮应持续跟进，直到产品经理验收通过后再收口。

结合 S5 vNext 既有结论，本轮优先选择低风险可见能力：

- UI 文案精简。
- 风险提示组件统一化。
- 举报 / 投诉或风险反馈最小记录能力。

本轮不包含：

- 智能 Agent 客服对外上线。
- 人工客服工作台。
- 老师认证体系。
- 支付、担保、退款、合同、人工仲裁。
- 自动推荐、评分排名或复杂运营后台。

## 2. 总体验收口径

本轮只有在以下条件全部满足后，才视为完成：

1. 产品经理确认本轮迭代 Spec / 执行包边界清晰。
2. UI 设计师完成 UI 文案精简清单和页面视觉验收标准。
3. ISSUE 管理员确认是否需要登记新 Issue；如登记，从 `ISSUE-0016` 起编号。
4. 代码开发员在前台完全访问线程完成实现、验证、提交和推送。
5. 代码开发员回报验证证据，至少包括 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`。
6. 涉及页面必须完成移动端和桌面端冒烟，重点检查反馈页、首页、登录页、规则页、发布需求页、发布家教信息页、联系方式页、聊天页。
7. 产品经理给出最终验收通过结论。
8. 项目总负责人汇总验收证据并收口。

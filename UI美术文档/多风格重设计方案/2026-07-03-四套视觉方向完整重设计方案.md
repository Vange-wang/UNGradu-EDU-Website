## 1. 任务口径

本文件为“家教对接 website”的多风格 UI 重设计交付稿。目标不是修改业务代码，而是为代码开发员后续可行性审查提供 4 套完整视觉方向、桌面端与移动端预览图、页面映射、业务边界和实现复杂度判断。

## 1.1 2026-07-04 视觉修订口径

根据用户反馈，第一轮预览图取消“细线条框 + 大字体直接摆出来”的线框排版感。新版预览图已覆盖原文件，修订原则如下：

- 卡片从细描边框改为面状卡片、柔和阴影、玻璃层叠或粗体插画块，仅在必要时保留边界。
- 标题字号收敛，改为更像正式产品视觉稿的标题 / 说明 / 行动层级，不再用超大字堆满首屏。
- 四套风格不再只换颜色，而是分别体现玻璃拟态、青蓝工具感、蓝紫轻拟态、高对比插画潮玩。
- 继续保持中文业务文案和 MVP 边界，不加入支付、担保、认证、人工审核、客服仲裁等未确认能力。

### 字体修订

根据用户反馈“字体太丑”，已重新学习 4 张参考图的字体气质并覆盖预览图字体。参考图中的字体共同特点是：标题偏现代几何无衬线，笔画厚但不笨重，正文比标题轻，整体更像产品界面而不是办公文档。第 4 张参考图则更偏粗黑、卡通、移动端品牌展示字。

本轮预览图已将渲染脚本字体优先级调整为：

- 标题 / 展示字：优先使用 `Noto Sans SC Bold` / `NotoSansSC-VF`，避免微软雅黑的大字笨重感。
- 正文 / 标签：优先使用 `Noto Sans SC Medium` / `Noto Sans SC`，让中文信息更清楚、更现代。
- 潮玩方向：仍使用更重的中文标题层级，但不再使用系统默认黑体直摆。

落地到代码时，建议优先使用 `Noto Sans SC`、`Source Han Sans SC`、`PingFang SC`、`HarmonyOS Sans SC`、`MiSans` 或 `Alibaba PuHuiTi` 这一类现代中文无衬线字体栈，而不是只依赖 `Microsoft YaHei`。

### 画面降噪与构图修订

根据用户进一步反馈“信息很杂很乱、文字位置不合理、文字框或者图形违和、画面太拥挤”，已再次覆盖预览图。新版预览图不再试图把所有页面细节塞进一张画面，而是采用更像参考图模板的展示逻辑：

- 桌面端只保留：顶部导航、主叙事标题、右侧风格化业务视觉、三张核心业务模块、一个轻量页面覆盖说明。
- 移动端只保留：顶部品牌、主入口、一个代表性广场卡、一个聊天 / 联系方式状态卡。
- 删除密集聊天气泡、过多 chip、重复标签、拥挤的列表和大段说明。
- 文字位置遵循“标题区、说明区、行动区、模块区”四段关系，避免文字漂浮在图形中。
- 图形只作为业务视觉承托，不再和文字框互相抢位置。

### 2026-07-04 精修口径

根据用户反馈“进步很多，还能再优化一点”，在不推倒重来的前提下做轻量精修：

- 桌面端右侧业务视觉区略微右移，避免与左侧叙事区挤在一起。
- 三张核心业务模块降低高度，统一底部对齐，减少卡片压迫感。
- 首屏说明文字字号略收敛，形成标题、说明、模块之间更自然的节奏。
- 移动端主标题、入口卡、广场卡、聊天状态卡之间增加节奏差，不再像连续堆块。
- 保持现有 4 套风格方向和业务文案，不新增业务能力。

### 情绪主视觉修订

根据用户反馈“图形图案太平淡，没什么情感渲染力”，已将右侧图形从普通占位块升级为情绪主视觉：

- A 绿色玻璃拟态：用柔光连接路径表现“家长需求”和“家教资料”被温和连接，重点渲染被理解、被照顾的安全感。
- B 青蓝玻璃卡片：用深浅任务面板表现筛选、沟通、状态确认，突出效率和清晰行动。
- C 蓝紫渐变轻拟态：用流动光环和靠近的圆形关系表达需求与老师逐步靠近，弱化金融感，保留温和的数字产品气质。
- D 高对比插画潮玩：用粗线条人物块、箭头动势和强色块表达“先聊清楚，再交换联系方式”，增强年轻化记忆点。

本次仍不使用支付、担保、认证、人工审核、客服仲裁等未确认能力作为视觉元素。

### 光影与光感修订

根据用户反馈“有些光影感、光感、不要是一大区块的纯单一颜色图案图形”，已继续优化桌面端右侧主视觉：

- 增加局部模糊光晕，让主视觉不再贴在背景上。
- 大色块改为带高光、暗部和半透明层的发光面板。
- 圆形和人物块加入高光与低光，避免纯色平涂。
- A / B / C 方案加强柔光、玻璃和流动感；D 方案保留粗线条，但在色块内部增加亮面和暗面。
- 移动端暂不加入复杂光影主视觉，避免回到拥挤和可读性下降的问题。

### 光感回调修订

根据用户反馈“加的光影更假更突兀”，已撤回上一版过强的外发光效果，并将光感回调为更自然的材质层次：

- 删除大面积强光晕和贴片式发光。
- 仅保留低透明度环境光，作为背景和主视觉之间的空气感。
- 高光和暗部改为非常轻的内层明暗，不再像外加特效。
- 图形仍保留渐变和材质变化，但避免抢过文字与业务信息。

### Product Design 复核后的样板图再学习

根据项目总负责人补充口径，本轮已按 Product Design 工作方式重新回放 brief，并重新查看 4 张样板图。复核后的修订重点不是继续叠加特效，而是把样板图里的视觉规律转译成当前家教业务可用的界面语言：

- A / B / C 三类玻璃与拟态风格的光感来自背景、卡片层次和柔和材质，不来自突兀外发光。
- D 类高对比插画风格的情绪来自粗线条、色块关系和动势，不依赖假高光。
- 桌面端主视觉只承担情绪和业务关系表达，文字仍按清楚的信息层级排列。
- 移动端继续保持轻量入口和关键状态卡，避免为了风格牺牲阅读效率。

最终预览图已将强光晕进一步压低为低透明度环境光、轻内高光、轻暗部和材质渐变，保留“有层次”但避免“假、突兀、抢信息”。

## 1.2 外部优秀 UI 学习摘要

本轮额外参考了以下类型的外部资料，只学习设计规律，不复制品牌、内容或具体界面：

- 真实产品截图与流程库：Mobbin、Page Flows。Mobbin 强调真实 iOS / Web 应用、海量 screens、flows、UI elements 和可搜索设计模式；Page Flows 强调真实用户流程、屏幕录制和逐步注释，适合学习登录、搜索、设置、发布和沟通等流程组织。
- Dashboard 与产品后台案例：Muzli Dashboard Examples。重点学习低噪音层级、模块化网格、柔和配色、清晰数据 / 列表组织，而不是照搬金融、运营或管理后台。
- 高表现力产品视觉：Dribbble Popular Product Design。重点学习卡片造型、品牌感、插画、渐变和首屏视觉张力，但不把概念稿当成可直接落地的业务界面。
- 趋势与落地边界：Lucky Graphics UI Design Trends 2026。重点关注玻璃拟态、bento grid、深浅模式、可访问性和性能之间的平衡。
- 灵感索引：TOOOLS Design Inspiration Websites。仅作为扩展参考面，不无限发散。

### 可复用设计原则

1. **先稳定信息架构，再做视觉效果。** 首页、广场、详情、发布、聊天、个人中心必须先让用户知道“我在哪、下一步做什么”。视觉效果只能强化结构。
2. **主行动按钮必须始终明显。** “发布需求”“发布家教信息”“发起站内沟通”“提交资料”要保持一级视觉优先级，不能被卡片装饰和背景光晕淹没。
3. **卡片阴影 / 玻璃效果不能降低文字对比度。** 玻璃拟态和轻拟态需要控制透明度；长列表优先可读，不优先炫技。
4. **移动端减少并列栏，改为分段 / 堆叠。** 参考移动端真实产品做法，移动端只保留核心入口、筛选标签、列表和聊天状态，不压入桌面端三栏。
5. **列表页重筛选、重扫描效率。** 需求广场和家教广场不是展示海报，应优先让用户快速比较科目、区域、时间、预算和沟通状态。
6. **详情页要把下一步行动放在稳定位置。** 需求详情和家教详情的“站内沟通”与“联系方式保护提示”必须稳定出现，不能藏在装饰性模块里。
7. **聊天 / 联系方式交换要强调状态和安全边界。** “未公开 / 待同意 / 已同意”应是聊天页的重要状态，不可只当一句说明文字。
8. **插画风格只能辅助，不应压过业务内容。** 高表现力视觉适合入口和招募，但规则、详情、联系方式保护仍要清楚稳重。
9. **Dashboard 规律可借鉴，后台感要克制。** 可借鉴模块化、筛选、状态面板和低噪音卡片；不照搬运营指标、金融曲线、收益感组件。
10. **趋势效果必须允许降级。** `backdrop-filter`、复杂阴影、拟态凹凸、插画资产如果影响性能或可读性，应有普通卡片 / 静态渐变 / 简化色块替代方案。

### 不适合本项目的流行效果

- 满屏玻璃模糊：容易降低中文列表和表单可读性。
- 金融曲线、收益卡、资产式指标：会让用户误解平台涉及交易、担保或收益承诺。
- 过度深色后台：会让家长和学生觉得像管理系统，而不是面向用户的服务平台。
- 概念化 3D / 大插画占满页面：会压过发布、筛选、沟通的核心闭环。
- 自动推荐分数、匹配百分比、认证徽章：当前业务边界未确认，不能通过 UI 暗示。

## 2. 共同业务边界

四套方案均保持同一业务边界：

- 支持家长 / 学生发布找老师需求。
- 支持大学生老师发布家教信息。
- 支持需求广场、家教信息广场、筛选、详情查看。
- 支持站内聊天表达意向。
- 联系方式仅在双方同意后交换。
- 公开页面不展示手机号、微信或其他直接联系方式。
- 不暗示支付、担保、资质认证、人工审核、人工客服仲裁、退款、合同、自动推荐算法、复杂排课或评价体系。

## 5. 方案 A：绿色玻璃拟态 / 柔和金融仪表盘感

### 风格学习摘要

这类 UI 风格通常适合低压力、需要建立信任但又不希望显得沉重的产品，例如轻量数据面板、个人财务、健康管理、学习计划和家庭服务类工具。它的核心不是“绿色”，而是通过半透明层、柔和光晕、浅色背景和大留白，让信息看起来被温和地分组。

它适合家教对接平台的部分在于：家长端需要安全感，学生 / 老师端需要轻松感，联系方式保护也适合用柔和提示表达。它不适合照搬的部分是金融仪表盘式数据组件，例如收益曲线、资产卡、强指标排名，这些会让家教业务显得交易化，也可能暗示平台有更强的撮合或评估能力。

可借鉴元素：玻璃层叠、柔和绿色行动色、低饱和背景、状态提示卡、轻量信息分组。

不可照搬元素：复杂数据图表、收益感指标、大量半透明小框、过细描边和过强模糊，否则会伤害列表可读性。

### 视觉关键词

清透、可信、柔和、轻运营、低压感。适合强调“安全沟通”和“信息透明”，比传统教育平台更轻盈。

### 参考图视觉原则转译

| 维度 | 提炼 | 转译到家教网站 |
| --- | --- | --- |
| 布局骨架 | 主视觉区 + 多张浮层卡片，信息以柔和分组出现。 | 首页保留双角色入口；广场页用左筛选面板 + 结果卡；个人中心用柔和功能卡聚合。 |
| 层级关系 | 主行动色面积不大，但位置明确；次信息放在半透明卡中。 | “发布需求”“发布家教信息”“发起站内沟通”为主行动，联系方式提示为次级状态卡。 |
| 材质语言 | 玻璃拟态、浅阴影、半透明白、背景柔光。 | 使用 `rgba()` 白色卡片、柔和 `box-shadow`、少量 `backdrop-filter`。 |
| 色彩关系 | 浅绿背景、白色承载、绿色行动、淡黄绿提示。 | 主色用于发布 / 发送；淡黄绿用于“联系方式未公开”“MVP 试运行”等提示。 |
| 组件语言 | 圆角卡片、胶囊标签、柔和输入框。 | 筛选 chip、表单输入框、聊天状态卡使用同一圆角和透明层。 |
| 视觉效果 | 光晕和模糊要服务于分区，而不是装饰堆叠。 | 背景光晕只放首屏和页面角落，列表区降低透明度提升可读性。 |

### 设计规则

| 类型 | 建议 |
| --- | --- |
| 色彩 | 背景使用浅绿到近白渐变；主行动色为薄荷绿；辅助色使用淡黄绿，不大面积压暗。 |
| 字体 / 字号 | 大标题 54-64px，卡片标题 22-28px，正文 16-18px；字重偏中高，避免金融图表感过强。 |
| 卡片 | 半透明白、轻边框、柔和阴影，卡片间距偏宽。 |
| 按钮 | 主按钮使用绿色实底，次按钮用玻璃白底。按钮圆角 14-18px。 |
| 输入框 | 白色半透明底，轻边框，聚焦态使用绿色描边。 |
| 信息密度 | 中低密度，适合首屏和个人中心；广场页需控制卡片高度，避免太空。 |
| 移动端策略 | 单列卡片，保留玻璃质感，但减少背景光斑，避免滚动时显乱。 |

### 页面适配

- 首页：最适合。能把找老师、做家教双入口做得温和可信。
- 登录 / 注册页：适合，用玻璃表单卡搭配隐私说明。
- 需求广场 / 家教信息广场：适合中低密度列表，筛选栏可做成半透明面板。
- 详情页：适合用大信息卡 + 侧边保护提示。
- 发布页：适合分步表单，但要避免每个字段都像卡片，建议一组一张卡。
- 聊天页：适合轻量沟通场景，联系方式状态可用浅绿提示区。
- 规则 / 反馈页：适合做成清爽公告页。

### 优点、风险与可信度影响

优点：亲和、轻松、可信，不会显得交易化；适合 MVP 试运行阶段。

风险：如果玻璃透明度过高，列表页可读性下降；绿色也可能让平台显得偏金融或健康管理，需要用中文教育文案稳住业务感。

对业务可信度的影响：正向。它强调保护、沟通和低压力匹配，比较符合“双方同意后交换联系方式”的边界。

### 实现复杂度

中。

原因：需要全局背景、半透明卡片、阴影和模糊质感。业务逻辑不需要改变，但 CSS token、卡片、按钮、输入框和页面容器都要统一重做。

### 可实现语言

| 类型 | 建议 |
| --- | --- |
| 核心 CSS | `linear-gradient` 背景、`rgba()` 半透明卡片、`box-shadow` 柔光、`border-radius: 24px-34px`、必要时 `backdrop-filter: blur(12px)`。 |
| 必须保留 | 柔和绿色主行动、半透明层叠卡、联系方式保护提示的温和状态感。 |
| 可降级 | 如果 `backdrop-filter` 性能不佳，可改为不透明浅色卡片 + 柔和阴影；背景光晕可用静态渐变替代。 |
| 不建议实现 | 过多透明小框、金融图表、浮动数值组件。 |

## 6. 方案 B：青蓝玻璃卡片 / 运动教练后台感

### 风格学习摘要

这类 UI 风格常见于运动教练后台、训练计划、队伍管理和效率型工具。它的重点是“清爽 + 动作明确 + 信息扫描快”，不是单纯的青蓝色。布局通常更有工作台感：顶部导航明确，左侧或上方筛选清晰，主内容用稳定卡片承载，关键行动按钮非常醒目。

它最适合家教对接平台的原因是：当前产品的核心闭环需要用户快速发布、筛选、查看、沟通。青蓝工具感能让需求广场和家教广场更像一个可操作的查找系统，而不是一组散落的内容卡。

可借鉴元素：高识别行动色、清楚的筛选工作台、卡片间明确层级、深浅青蓝对比、紧凑但不压迫的信息密度。

不可照搬元素：运动计分、竞技排名、教练绩效、过深后台感。这些会让家长端觉得平台太工具化，也可能偏离家教服务的温度。

### 视觉关键词

清爽、效率、行动感、筛选工具感。借鉴运动教练后台的节奏，但转译为“快速找到合适老师 / 需求”。

### 参考图视觉原则转译

| 维度 | 提炼 | 转译到家教网站 |
| --- | --- | --- |
| 布局骨架 | 顶部导航 + 左筛选 / 控制区 + 主内容列表 + 右侧状态模块。 | 需求广场、家教广场采用筛选工作台；聊天页突出会话和联系方式交换状态。 |
| 层级关系 | 主行动非常明确，列表扫描优先级高。 | 发布、筛选、发起沟通为一级；详情、重置筛选为二级。 |
| 材质语言 | 白色或浅青卡片、轻玻璃、清晰块面。 | 减少细线条，用浅青色块区分筛选和状态；卡片靠阴影和背景分层。 |
| 色彩关系 | 深青蓝提供专业感，高亮青蓝负责行动。 | 深青蓝只用于导航 / 强模块；高亮青蓝用于按钮和当前状态。 |
| 组件语言 | 工具型筛选器、稳定列表卡、状态徽标。 | 科目、区域、预算、时间使用清楚的筛选 chip 和输入块。 |
| 视觉效果 | 轻投影、局部深色面、强按钮。 | 保留效率感，不增加运动图标或竞技视觉。 |

### 设计规则

| 类型 | 建议 |
| --- | --- |
| 色彩 | 深青蓝作为少量背景张力，浅青蓝作为筛选和卡片氛围，主行动色为高亮青蓝。 |
| 字体 / 字号 | 标题 52-60px，模块标题 22-26px，列表正文 15-16px；字重更硬朗。 |
| 卡片 | 白底或浅玻璃卡，圆角 12-18px，边框更清晰。 |
| 按钮 | 主按钮使用青蓝色，次按钮浅青底；按钮圆角比 A 更小，显得更利落。 |
| 输入框 | 更像工具筛选项，字段高度稳定，标签清晰。 |
| 信息密度 | 中高密度，适合广场和个人工作台。 |
| 移动端策略 | 顶部保留关键行动按钮，筛选 chip 可横向换行，列表卡更紧凑。 |

### 页面适配

- 首页：适合做成强入口，但要避免太像健身或运动 App。
- 登录 / 注册页：适合右侧表单 + 左侧规则说明。
- 需求广场 / 家教信息广场：最适合。筛选、列表、状态都能做得清晰高效。
- 详情页：适合较强信息结构，如左内容右行动。
- 发布页：适合流程明确的分组表单。
- 聊天页：适合工作台式沟通，消息区清晰。
- 个人中心：适合做成任务面板。
- 规则 / 反馈页：适合做成系统公告。

### 优点、风险与可信度影响

优点：效率感强，广场和筛选能力最容易落地，也最利于代码开发员审查结构。

风险：如果深色和高亮青蓝使用过多，可能偏工具后台，亲和力不足；需要用教育语气和留白平衡。

对业务可信度的影响：中高。它让平台显得更专业，但不要暗示平台有自动推荐或审核能力。

### 实现复杂度

中。

原因：页面结构需要从普通卡片升级为筛选工作台和列表工作台，但视觉效果主要依赖 CSS，无需新增复杂图片资产。

### 可实现语言

| 类型 | 建议 |
| --- | --- |
| 核心 CSS | `display: grid` 桌面三栏、`position: sticky` 筛选栏、青蓝主题 token、浅色卡片 `box-shadow`、移动端 `responsive stack`。 |
| 必须保留 | 工具台式筛选结构、明确主行动按钮、青蓝深浅层级、列表可扫描性。 |
| 可降级 | 桌面右侧状态栏可在第一版并入主内容下方；深色模块可先用浅青模块替代。 |
| 不建议实现 | 竞技排名、训练统计、复杂图表、过多深色后台面板。 |

## 7. 方案 C：蓝紫渐变轻拟态 / 金融流动感

### 风格学习摘要

蓝紫渐变轻拟态适合强调“现代、完整、数字产品感”的产品，例如金融科技、智能工具、会员中心和数据服务。它的核心是柔和渐变背景、凸起或凹陷的轻拟态卡片、强一致的阴影系统和渐变主按钮。

它可以让家教对接网站显得更高级，但风险也最大：蓝紫渐变很容易让产品像金融后台、AI 工具或会员服务。如果业务文案不克制，用户可能误以为平台具备自动推荐、评分、认证或担保等能力。

可借鉴元素：柔和渐变背景、轻拟态卡片、渐变按钮、圆润输入框、个人中心的成熟产品感。

不可照搬元素：金融流动曲线、资产状态、收益色彩、过度立体阴影。它们会提升实现成本，也会削弱家教服务的朴素可信感。

### 视觉关键词

高级、柔和、流动、数字产品感。适合让项目看起来更完整、更现代，但要控制金融感。

### 参考图视觉原则转译

| 维度 | 提炼 | 转译到家教网站 |
| --- | --- | --- |
| 布局骨架 | 大背景渐变 + 立体卡片 + 强行动区。 | 首页做现代入口；个人中心和发布页做轻拟态分组；广场页降低阴影密度。 |
| 层级关系 | 主按钮和核心卡片最突出，辅助信息更柔。 | “发布”和“站内沟通”使用渐变按钮；业务边界提示保持清楚可读。 |
| 材质语言 | 轻拟态、柔光阴影、圆角、浅色浮层。 | 用统一阴影 token 做卡片，不让每个字段都凸起来。 |
| 色彩关系 | 蓝紫为主，浅背景承载，少量暖色提示。 | 蓝紫用于品牌和行动；暖黄只提示“联系方式保护”等状态。 |
| 组件语言 | 渐变按钮、圆角输入、分组卡片。 | 发布页和资料页最适合这种组件语言。 |
| 视觉效果 | 流动感来自背景和阴影，不来自复杂动效。 | MVP 阶段不做复杂动画，优先静态可读。 |

### 设计规则

| 类型 | 建议 |
| --- | --- |
| 色彩 | 浅蓝紫渐变背景；主按钮使用蓝紫渐变；黄色只作为少量提示标签。 |
| 字体 / 字号 | 大标题 56-64px，卡片标题 22-26px；整体字重偏圆润。 |
| 卡片 | 轻拟态凸起感，使用内外阴影；边框弱化。 |
| 按钮 | 渐变实底主按钮，次按钮为浅蓝紫底。 |
| 输入框 | 轻拟态凹槽感，但必须保持边界清晰。 |
| 信息密度 | 中密度，适合详情、个人中心和发布页；广场页需要避免卡片过厚。 |
| 移动端策略 | 减少阴影层级，保留渐变按钮和圆角卡片，避免页面显得太软。 |

### 页面适配

- 首页：适合，能显得高级和完整。
- 登录 / 注册页：适合，表单会比较精致。
- 需求广场 / 家教信息广场：可用，但列表密度不能太高，否则拟态阴影会拖慢视觉扫描。
- 详情页：适合，信息区和行动区可以清楚分层。
- 发布页：适合，分组表单有仪式感。
- 聊天页：适合轻量对话，但消息气泡不要过度阴影。
- 个人中心：很适合，功能入口会更像成熟产品。
- 规则 / 反馈页：适合做成温和的说明页。

### 优点、风险与可信度影响

优点：完成度和现代感最强，适合对外展示项目品质。

风险：蓝紫渐变容易让平台显得偏金融、SaaS 或泛 AI 工具；过多轻拟态会降低长列表可读性。

对业务可信度的影响：中。视觉显得精致，但如果文案不克制，容易让用户误以为平台能力比 MVP 更完整。

### 实现复杂度

高。

原因：需要较系统的阴影、渐变、按钮、输入框、卡片状态设计；移动端要额外控制阴影与性能。业务逻辑不改，但 CSS 统一改造量较大。

### 可实现语言

| 类型 | 建议 |
| --- | --- |
| 核心 CSS | `linear-gradient` / `radial-gradient` 背景、双层 `box-shadow`、渐变按钮、统一 `border-radius: 24px-32px`、表单卡 `grid` 分组。 |
| 必须保留 | 蓝紫渐变主行动、轻拟态卡片、个人中心和发布页的圆润成熟感。 |
| 可降级 | 轻拟态阴影可减少为单层阴影；移动端可去掉凹陷输入框，仅保留渐变按钮与圆角卡片。 |
| 不建议实现 | 金融曲线、收益标签、自动匹配分数、复杂动效。 |

## 8. 方案 D：高对比插画潮玩 / 粗线条移动端感

### 风格学习摘要

高对比插画潮玩风格适合年轻、传播感强、希望被记住的产品，例如活动页、青年社区、移动端招募页和轻娱乐工具。它不是简单地给所有卡片加黑边，而是用大色块、粗轮廓、插画占位、强按钮和明确节奏制造记忆点。

它适合家教平台的大学生老师招募端，也适合移动端首页。但完整落到家长端会有风险：家长在选择老师时更重视可信、清楚和稳重，过强的潮玩感可能削弱信任。

可借鉴元素：高对比色块、强行动按钮、大块插画区、移动端堆叠卡、明确的状态标签。

不可照搬元素：满屏粗线条、过多卡通装饰、娱乐化文案、强烈跳色列表。它们会降低可读性，也会让规则和联系方式保护显得不够严肃。

### 视觉关键词

年轻、强记忆、活泼、高对比、移动优先。适合吸引大学生老师，但需要控制可信度。

### 参考图视觉原则转译

| 维度 | 提炼 | 转译到家教网站 |
| --- | --- | --- |
| 布局骨架 | 大色块首屏 + 重点入口卡 + 移动端强堆叠。 | 首页和移动端发布入口可使用；广场和详情页要降噪。 |
| 层级关系 | 视觉中心非常强，按钮很像可点击实体。 | 只让“发布需求”“发布家教信息”强表现，其他内容保持白底可读。 |
| 材质语言 | 粗线条、硬阴影、高饱和色、插画块。 | 粗线条只用于关键入口和活动感模块，规则页不用满屏粗边框。 |
| 色彩关系 | 黄 / 青 / 橙 / 黑高对比。 | 高亮色用于入口；正文和列表回到白底黑字。 |
| 组件语言 | 大按钮、大卡片、标签强识别。 | 移动端发布和聊天状态适合；长列表需弱化边框。 |
| 视觉效果 | 强视觉记忆来自插画占比和硬阴影。 | 后续若落地，建议补真实插画资产，不用临时代码图形当正式素材。 |

### 设计规则

| 类型 | 建议 |
| --- | --- |
| 色彩 | 高亮黄、青、橙与黑色粗线条组合；白底卡片承载正文。 |
| 字体 / 字号 | 标题 54-64px，强字重；正文 15-17px，避免整页都过大。 |
| 卡片 | 白底、粗黑描边、硬阴影，圆角 12-22px。 |
| 按钮 | 高饱和实底 + 黑色描边，状态非常明确。 |
| 输入框 | 粗边框，错误和提示状态必须清楚，不能只靠颜色。 |
| 信息密度 | 中密度偏低。更适合入口页和移动端，不适合大量列表。 |
| 移动端策略 | 最有优势。卡片堆叠、按钮大、状态强，对年轻用户更友好。 |

### 页面适配

- 首页：非常适合做记忆点，尤其适合“大学生做家教”的招募入口。
- 登录 / 注册页：可用，但要克制插画元素，避免影响表单可信度。
- 需求广场 / 家教信息广场：可用但不是最佳。粗线条会占空间，长列表扫描效率下降。
- 详情页：适合强调主信息，但价格、时间、联系方式状态要保持清楚。
- 发布页：适合移动端分步填写，按钮层级明显。
- 聊天页：适合年轻化气泡，但要避免像社交娱乐产品。
- 个人中心：适合做成大入口卡。
- 规则 / 反馈页：不建议过度潮玩，应收敛为清晰说明。

### 优点、风险与可信度影响

优点：最有记忆点，最容易和普通教育平台拉开差异；移动端表现强。

风险：如果整站全部使用高饱和和粗线条，家长端可能觉得不够稳重；对规则页、详情页、联系方式保护等严肃信息不够天然友好。

对业务可信度的影响：分人群。对大学生老师端正向，对家长端需要增加清晰规则说明和稳定排版。

### 实现复杂度

中高。

原因：核心 CSS 不复杂，但需要额外设计插画资产、图标和空状态，否则会显得像粗描边皮肤。若先不做真实插画资产，可先落地粗线条卡片系统。

### 可实现语言

| 类型 | 建议 |
| --- | --- |
| 核心 CSS | 高饱和主题 token、较粗 `border`、硬阴影 `box-shadow: 6px 6px 0`、大按钮、移动端单列 `responsive stack`。 |
| 必须保留 | 强入口、大色块、移动端按钮层级、年轻化招募感。 |
| 可降级 | 正式插画资产未准备好时，可以先保留色块和硬阴影，插画区域改成品牌图或留白。 |
| 不建议实现 | 全站满屏粗边框、娱乐化图标、规则页过度潮玩、长列表高饱和背景。 |

## 9. 面向代码开发员的可行性审查清单

### 全局样式

- 是否可以新增一组主题 token：背景、主行动色、辅助色、边框、阴影、圆角、正文色、弱文本色。
- 是否可以将现有页面容器抽象为统一 `page-shell`、`section-panel`、`data-card`、`form-card`、`notice-card`。
- 是否需要按方案切换主题，或只选择一套后覆盖全站样式。

### 组件类型

- 导航：品牌区、主导航、登录 / 注册、发布入口。
- 角色入口卡：家长找老师、大学生做家教。
- 广场筛选：科目、学段、区域、方式、预算、时间、状态。
- 列表卡：需求卡、老师卡、我的发布卡、聊天列表卡。
- 详情页侧栏：站内沟通按钮、联系方式保护提示。
- 表单：分组标题、输入框、选项块、提交按钮、错误提示。
- 聊天：消息气泡、输入区、联系方式交换状态区。
- 规则 / 反馈：公告条目、边界说明、反馈入口。

### 页面结构

- 首页需要重排成“双角色入口 + 流程说明 + 业务边界提示”。
- 广场页建议使用桌面端左筛选 / 右列表，移动端筛选置顶。
- 发布页建议改成分组表单，但不改变提交字段含义。
- 聊天详情页建议突出联系方式交换状态，但不改变交换规则。
- 个人中心建议改成功能入口面板，但沿用现有页面路由。

### 业务逻辑影响

- 不应影响现有业务逻辑。
- 不应新增支付、认证、审核、自动推荐、评价等状态字段。
- 联系方式展示逻辑必须维持现有“双方同意后交换”。
- 如果代码中已有状态枚举，应只映射视觉文案，不新增虚假状态。

### 资产需求

- 方案 A、B、C：可以主要通过 CSS 完成，暂不强制新增图片资产。
- 方案 D：若要真正达到“插画潮玩”质感，建议新增一组真实插画或图标资产；当前预览图仅表达方向，不建议直接把临时图形当正式资产。

## 10. 推荐排序

1. **方案 B：青蓝玻璃卡片 / 运动教练后台感**
   - 最适合当前“广场筛选 + 发布 + 聊天 + 个人中心”的产品结构。
   - 实现复杂度可控，代码开发员审查最容易。
   - 专业感较强，但不容易误导用户以为平台提供支付或认证。

2. **方案 A：绿色玻璃拟态 / 柔和金融仪表盘感**
   - 亲和可信，适合家长端，也适合强调隐私保护。
   - 风险是长列表可读性，需要开发时控制透明度和背景复杂度。

3. **方案 C：蓝紫渐变轻拟态 / 金融流动感**
   - 质感最好，但实现复杂度最高，也最容易偏离家教业务的朴素可信感。
   - 如果项目要做展示型官网，可以考虑；若优先生产可用，建议暂缓。

4. **方案 D：高对比插画潮玩 / 粗线条移动端感**
   - 记忆点最强，适合大学生老师招募和移动端。
   - 对家长端可信度有风险，需要更多真实插画资产与文案收敛，建议作为局部活动风格或后续增长页方向。

## 11. UI 设计师结论

建议进入代码开发员可行性审查，优先审查方案 B，其次方案 A。审查时不需要改业务逻辑，重点评估全局 CSS token、页面结构重排、表单分组、广场筛选布局、聊天联系方式状态区和移动端响应式成本。

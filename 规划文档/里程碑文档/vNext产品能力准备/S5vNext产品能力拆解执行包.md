# S5 vNext 产品能力拆解执行包

日期：2026-06-30

阶段：发布阶段 S5

任务 ID：`RELEASE-S5-VNEXT-2026-06-30-001`

状态：已启动

## 1. 阶段背景

S1 已完成，S2 生产运行观察与运维基线已通过，S3 风控审核与可信度增强已通过，S4 公开推广前发布评审已通过。

S4 的最终结论为：

```text
允许小范围继续试运行，不建议公开推广。
```

不建议公开推广的核心原因不是当前 MVP 链路不可用，而是客服与人工介入、举报 / 投诉闭环、老师审核认证、运营承接和公开推广风险兜底能力尚未建设。

S5 的目标不是直接扩大功能，而是把 S4 列出的 vNext 候选能力拆成可立项、可评审、可验收的专项。

## 2. S5 阶段目标

S5 目标：

- 将 vNext 候选需求拆成独立专项。
- 明确每个专项的优先级、边界、风险和验收前置条件。
- 确认哪些能力只需要产品 Spec，哪些能力需要代码实现，哪些能力必须等待外部服务或运营机制。
- 避免把智能 Agent 客服、人工客服、认证、投诉处理等高风险能力直接混入当前 MVP。

## 3. S5 第一批候选专项

| 专项 | 优先级 | 当前建议 |
| --- | --- | --- |
| 智能 Agent 客服专项 | P0 | 先做 Spec 与权限边界，不直接接入真实用户数据 |
| 举报 / 投诉最小闭环 | P0 | 先做产品闭环与数据结构设计，再评估代码实现 |
| 风险提示组件统一化 | P1 | 可作为低风险代码侧优化候选 |
| 老师资料审核状态 | P1 | 先明确“未认证 / 待审核 / 已审核”的展示边界 |
| 运营后台最小版 | P1 | 需要结合举报、反馈、老师资料审核一起设计 |
| 生产运行观察记录持续化 | P1 | 可延续 S2 模板，先不做复杂数据看板 |

## 4. 本阶段不做范围

S5 当前不直接实现：

- 真实智能 Agent 客服上线。
- 人工客服工作台。
- 人工仲裁。
- 平台担保交易。
- 在线支付。
- 退款处理。
- 实名认证供应商接入。
- 老师资质认证等级体系。
- 自动推荐算法。
- 大规模公开推广。

## 5. 角色任务

### 5.1 产品经理

产品经理需要确认：

- S5 是否应优先拆为“智能 Agent 客服专项”和“举报 / 投诉最小闭环专项”。
- 每个专项是否需要独立 Spec。
- 当前 vNext 候选需求池是否需要调整优先级。
- 哪些能力可以进入下一轮实现，哪些只能停留在规划。

### 5.2 代码开发员

代码开发员本轮只做只读技术可行性核查：

- 当前代码是否已有反馈入口、聊天记录、联系方式交换记录、用户资料等可供后续专项引用的基础。
- 智能 Agent 客服若未来接入，可能涉及哪些敏感数据和权限风险。
- 举报 / 投诉闭环若实现，可能需要哪些数据集合、API 和页面。
- 风险提示组件统一化是否适合作为低风险先行实现项。

本轮不要求代码开发员写代码。

### 5.3 ISSUE 管理员

ISSUE 管理员需要确认：

- 当前 Open Issue 是否为空。
- S5 新发现的问题或风险是否从 `ISSUE-0016` 起编号。
- 当前仅做候选专项拆解时，不创建空 Issue。
- 若发现明确阻塞小范围试运行的问题，再登记为 Open Issue。

## 6. 验收标准

S5 可通过的条件：

- S5 执行包已创建。
- 智能 Agent 客服专项边界草案已创建。
- 举报 / 投诉最小闭环边界草案已创建。
- S5 优先级与任务拆分表已创建。
- 产品经理完成 S5 产品口径确认。
- 代码开发员完成 S5 技术可行性只读核查。
- ISSUE 管理员完成 S5 编号规则确认。
- 总负责人形成 S5 阶段跟踪 / 验收报告。

S5 通过不代表智能 Agent 客服或举报 / 投诉系统已实现，只代表 vNext 第一批能力拆解完成。

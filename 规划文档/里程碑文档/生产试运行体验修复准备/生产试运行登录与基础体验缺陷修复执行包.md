## 1. 背景与问题归类

项目总控制人在正式环境试用中反馈了新的登录与基础体验问题：

1. 依旧没有返回键。
2. 未登录状态有退出登录选项，但没有登录选项，只能通过点击个人页面登录。
3. 退出登录无二次确认。
4. 验证码一次登录显示服务不可用之后，二次点击登录直接提示验证码已经使用，请重新获取；用户质疑为什么会有“暂时不可用”提示，为什么未成功登录也被标记已使用。
5. 用户需要第一次注册之后，可以设置密码登录。

问题归类：

- P0：邮箱验证码登录异常。未成功登录却消耗验证码，会直接阻断用户进入系统，并破坏用户对登录可靠性的信任。
- P1：未登录状态导航错误。未登录时显示退出登录而不显示登录 / 注册入口，会让用户无法理解如何进入系统。
- P1：退出登录缺少二次确认。误点退出会中断试运行体验，尤其在验证码或密码未稳定前影响较大。
- P1：返回入口仍缺失。此前只补了部分页面，正式环境反馈说明需要全站核查，而不是只补几个已知页面。
- P1：首次注册后可设置密码登录。生产试运行需要降低用户反复依赖验证码的成本，但仍保留邮箱验证码作为注册、登录和找回密码路径。

本阶段目标不是扩大 MVP 业务范围，而是修复正式生产试运行中暴露的登录闭环和基础可用性问题。

## 3. 必须修复项

### 3.1 P1：未登录状态导航不应出现退出登录

问题描述：

正式环境未登录状态仍出现“退出登录”选项，却没有明显“登录 / 注册”入口，用户只能通过点击个人页面间接进入登录。

产品要求：

- 未登录状态下，导航或首屏可见区域必须显示“登录 / 注册”入口。
- 未登录状态下不得显示“退出登录”。
- 已登录状态下才显示“退出登录”。
- 已登录状态下可以显示“个人页 / 我的资料 / 退出登录”等入口。
- 如果会话状态加载中，不要短暂展示错误状态；可展示占位、骨架或仅保留不误导的基础导航。

验收标准：

- 清空登录态或使用无痕窗口访问首页时，导航显示“登录 / 注册”或等价入口。
- 清空登录态访问首页时，导航不显示“退出登录”。
- 登录成功后，导航显示“个人页”和“退出登录”，且不再显示会误导用户重复注册的入口。
- 退出登录后，导航恢复未登录状态，显示“登录 / 注册”。
- 页面刷新后状态仍正确，不出现未登录显示退出登录的闪烁或最终状态。

### 3.2 P1：退出登录需要二次确认

问题描述：

当前点击退出登录会直接退出，没有二次确认，正式试运行用户容易误点。

产品要求：

- 用户点击“退出登录”后，必须出现二次确认。
- 确认文案必须明确说明“退出后需要重新登录”。
- 用户取消时不得退出登录，会话保持。
- 用户确认后才调用退出接口并清除会话。
- 退出成功后回到首页或登录页，并展示明确状态。
- 退出失败时提示“退出失败，请稍后重试”或等价中文文案，不清除前端误导状态。

验收标准：

- 已登录用户点击“退出登录”后，先看到确认弹窗、确认框或等价二次确认 UI。
- 点击取消后，仍保持已登录，个人页仍可访问。
- 点击确认后，会话被清除，导航恢复“登录 / 注册”。
- 退出接口失败时，不应显示已退出成功。

### 3.3 P1：返回入口仍缺失，必须全站核查

问题描述：

正式环境仍反馈“依旧没有返回键”，说明上一轮返回入口覆盖不完整，或入口位置 / 文案 / 可见性没有满足真实用户感知。

产品要求：

代码开发员必须全站核查主要页面，而不是只补几个页面。至少覆盖：

- 首页到各主流程入口后的返回路径。
- 登录页。
- 个人页。
- 发布家教需求表单。
- 发布家教信息表单。
- 家教需求广场。
- 家教需求详情。
- 家教信息广场。
- 家教信息详情。
- 我的需求。
- 我的家教信息。
- 联系方式管理。
- 我的聊天。
- 聊天详情。
- 规则页。
- 反馈页。
- 错误 / 不可访问状态页，例如详情不存在、聊天不可访问、未登录跳转后页面。

交互要求：

- 主要页面顶部或首屏必须有明确返回入口。
- 返回文案必须是中文业务语义，例如“返回首页”“返回个人页”“返回需求广场”“返回上一页”。
- 不要只使用浏览器后退图标而没有文字说明。
- 返回行为不能跳到无关页面。
- 移动端和桌面端均可点击。
- 返回入口不得遮挡表单、按钮或主要内容。

验收标准：

- 代码开发员提交全站页面清单，标明每个页面的返回入口文案和目标路径。
- 产品经理或测试人员按清单逐页访问，能在首屏或页面顶部找到返回入口。
- 主要页面返回后都进入合理页面，不进入 404、不丢登录态、不清空未提交表单之外的无关状态。
- 未登录状态访问受保护页面时，跳转登录前后也有明确去向或返回入口。

### 3.4 P0：邮箱验证码登录异常不得消耗验证码

问题描述：

用户第一次输入验证码登录时显示“服务暂时不可用”，第二次点击登录直接提示“验证码已经使用，请重新获取”。用户实际没有成功登录，却被系统判定验证码已使用。

产品要求：

- 验证码只有在“登录成功并成功创建会话”之后，才允许标记为 used。
- 如果验证码校验通过，但创建账号、创建会话、写入 Cookie、写入数据库或服务端依赖失败，不得消耗验证码。
- 如果邮件服务不可用发生在发送验证码阶段，应提示“邮件服务暂时不可用，请稍后重新获取验证码”。
- 如果登录服务不可用发生在登录阶段，应提示“登录服务暂时不可用，请稍后重试”，但不得把未成功登录的验证码标记为 used。
- 错误提示必须能区分：
  - 邮件服务不可用。
  - 验证码错误。
  - 验证码已使用。
  - 验证码已过期。
  - 会话写入失败 / 登录服务不可用。
- 不得把所有失败都统一显示为“暂时不可用”。
- 不得在响应、日志或前端页面泄露验证码明文、验证码哈希、密钥或 SMTP 凭据。

建议实现口径：

- 将邮箱验证码状态更新顺序调整为“验证验证码有效 -> 创建或复用用户 -> 创建服务端会话 / Cookie -> 全部成功后标记验证码 used”。
- 如果底层存储支持事务，优先使用事务或等价原子流程。
- 如果暂不具备事务，必须保证失败分支不会写入 used 状态，并增加回归测试覆盖。
- 对并发重复提交要有防重策略：同一验证码同时发起两次登录时，最多一个请求成功，失败请求提示合理错误，不应出现两个会话或状态错乱。

验收标准：

- 输入错误验证码时，提示“验证码错误”或等价文案，验证码未被标记 used。
- 输入已使用验证码时，提示“验证码已使用，请重新获取”。
- 输入过期验证码时，提示“验证码已过期，请重新获取”。
- 模拟邮件服务不可用时，发送验证码失败提示邮件服务不可用，系统不生成可用验证码。
- 模拟登录阶段会话写入失败时，前端提示登录服务不可用或会话创建失败，验证码仍可在有效期内再次尝试。
- 模拟第一次登录服务失败、第二次恢复后，使用同一未过期验证码可以成功登录。
- 成功登录后，再次使用同一验证码才提示已使用。
- 自动化测试必须覆盖“登录失败不消耗验证码”和“登录成功后才消耗验证码”。

## 4. 新需求：首次注册后可设置密码登录

### 4.1 MVP 口径

本轮新增最小密码登录能力，目标是让用户首次通过邮箱验证码注册 / 登录成功后，可以设置密码；之后支持邮箱 + 密码登录；同时继续保留邮箱验证码登录。

用户路径：

1. 新用户输入邮箱并通过邮箱验证码完成首次注册 / 登录。
2. 首次登录成功后，系统提示用户可以设置登录密码。
3. 用户设置密码后，下次可以使用邮箱 + 密码登录。
4. 用户仍可选择邮箱验证码登录。
5. 忘记密码时，通过邮箱验证码验证身份后重置密码。

### 4.2 本轮必须做

- 登录页提供两种登录方式：
  - 邮箱验证码登录。
  - 邮箱 + 密码登录。
- 首次邮箱验证码注册 / 登录成功后，提供“设置密码”入口。
- 已登录用户在个人页或账号设置区域可以设置或修改密码。
- 密码设置必须要求二次输入确认。
- 密码不得明文存储。
- 服务端必须使用安全哈希方案保存密码，例如 `argon2id`、`bcrypt`、`scrypt` 或 Node.js `crypto.scrypt`，并使用唯一 salt。
- 登录失败提示不得暴露“邮箱是否存在”这类枚举信息；建议统一提示“邮箱或密码不正确”。
- 密码登录需要基础频控或失败次数限制，避免暴力尝试。
- 忘记密码 / 重置密码采用邮箱验证码确认身份后重置密码。
- `.env.example` 和 `Code文档` 中如新增密码哈希 pepper 或相关环境变量，必须写明用途；真实密钥不得写入仓库。

### 4.3 最小密码规则

- 密码长度至少 8 位。
- 密码最长建议不超过 72 位或按所选哈希算法安全限制处理。
- 密码至少包含字母和数字。
- 不允许全空格。
- 设置密码时必须二次确认一致。
- 前端可提示规则，但服务端必须再次校验。
- 页面必须提示用户不要使用邮箱验证码、手机号、生日或过于简单的密码。

### 4.4 本轮不做

- 复杂账号合并。
- 第三方登录，例如微信、QQ、Google、GitHub。
- 多因素认证。
- 设备管理。
- 登录地提醒。
- 管理员强制重置密码后台。
- 复杂密码强度评分器。
- 账号注销。
- 换绑邮箱。
- 短信验证码登录恢复。
- 实名认证、支付、排课、合同、审核后台、举报封禁后台。

### 4.5 验收标准

- 新用户通过邮箱验证码首次登录后，可以看到设置密码入口。
- 用户设置符合规则的密码后，退出登录，再使用邮箱 + 密码可以登录。
- 用户输入错误密码时不能登录，并看到通用错误提示。
- 用户仍可使用邮箱验证码登录，不被密码登录替代。
- 用户忘记密码时，可以通过邮箱验证码重置密码。
- 密码不会以明文形式出现在数据库、接口响应、日志、前端状态或浏览器 localStorage。
- 自动化测试覆盖：
  - 设置密码成功。
  - 密码规则校验失败。
  - 密码登录成功。
  - 密码错误登录失败。
  - 邮箱验证码重置密码成功。
  - 密码哈希不是明文。

## 5. 验收标准汇总

本阶段完成后，至少应满足：

- 未登录首页显示登录 / 注册入口，不显示退出登录。
- 已登录首页显示个人页 / 退出登录，不误导重复注册。
- 退出登录前必须二次确认，取消不退出，确认才退出。
- 全站主要页面清单完成，每个主要页面都有清晰返回入口。
- 邮箱验证码登录中，服务不可用不会消耗验证码。
- 只有成功创建会话 / 登录成功后，验证码才标记为 used。
- 登录错误提示能区分邮件服务不可用、验证码错误、验证码已使用、验证码已过期、会话写入失败。
- 首次邮箱验证码注册 / 登录后可设置密码。
- 设置密码后可用邮箱 + 密码登录。
- 邮箱验证码登录继续保留。
- 忘记密码 / 重置密码通过邮箱验证码完成。
- 密码不明文存储，不在接口、日志和前端泄露。
- `npm run typecheck`、`npm test`、`npm run lint`、`npm run build` 必须通过。
- 如涉及正式环境冒烟，代码开发员应说明冒烟 URL、账号口径和未覆盖项；真实密钥不得写入文档。

- 公开推广或增长玩法。

以上能力如需要，应进入后续 vNext 或单独 Spec。

## 9. 产品经理当前判断

本次反馈来自正式生产试运行环境，优先级高于一般体验优化。代码开发员应先处理登录可靠性和导航状态，再处理返回入口和密码登录。

最关键的风险是邮箱验证码生命周期：用户没有成功登录时，不应被消耗验证码。该问题必须通过自动化测试证明修复，不能只靠手工说明。

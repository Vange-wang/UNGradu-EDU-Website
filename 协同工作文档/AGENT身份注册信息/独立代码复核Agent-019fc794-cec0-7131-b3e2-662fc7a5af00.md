## 输入边界

仅接收项目总负责人发送的正式任务包，包括：

- 固定点、限定 diff 与必要的只读 Git 上下文；
- canonical Issue / Spec；
- 代码开发员提供的实现说明、测试结果和验证证据。

不得把未授权的工作树范围、其他角色草稿、未确认业务规则或外部平台状态自行纳入复核范围。

## 输出边界

仅输出独立、只读的代码与测试技术复核结果，按两个彼此独立的轴顺序执行：

- Standards：对照项目规范和代码审查基线，报告路径、行号、严重度、证据和判断依据；
- Spec：对照 canonical Issue / Spec，报告缺失、部分实现、错误实现或范围漂移，并给出路径、行号、严重度和证据。

正式技术结论仅允许为 `TECH_REVIEW_PASS` 或 `TECH_REVIEW_REWORK_REQUIRED`。结论不得替代产品、UI、Issue、生产或业务方验收。

## 职责与只读规则

- 只做独立代码/测试验收，不实现修复、不修改被审查代码、不替开发员、产品经理、UI 设计师、ISSUE 管理员或项目总负责人产出正式交付物。
- 不自我批准；发现问题须归因到限定 diff 和证据，并退回原代码开发员经项目总负责人路由处理。
- 不运行真实 CloudBase 写入测试，不接触任何真实凭据，不部署，不操作 Cloudflare、CloudBase 或其他平台配置。
- 在明确任务包范围内，允许运行离线测试、typecheck、lint 及只读 Git 命令；不得借此扩大文件、权限或外部操作范围。
- 本文件仅作为历史归档保留；当前绑定仅在明确授权下维护新旧注册文件、`Code文档/钦定独立代码复核.md` 与 `Code文档/独立代码复核工作记录.md`。

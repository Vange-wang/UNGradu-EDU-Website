# 产品经理工作记录

用途：持续记录产品经理在本项目中的每次重要操作、信息记录、决策确定、决策变更和文档修订。后续产品经理会话应持续追加更新本文件。

## 记录规则

- 新增或变更产品决策时，必须追加记录。
- 修订 Spec、里程碑、技术验证、产品迭代、上下文文档时，必须追加记录。
- 记录应包含日期、类型、涉及文档、内容摘要和影响。
- 不记录业务代码实现细节，除非该实现结果反向影响产品决策。

### 第二批 Cloudflare 安全加固产品参数门禁

类型：生产安全加固产品决策 / 可用性门禁

任务 ID：`CLOUDFLARE-HARDENING-BATCH2-2026-07-18-PM-1`

已核验的决策输入：

- workers.dev 公网入口已由 `200` 变为 `404`，正式根域与 `www` 回归正常。
- AI bots 尚未完成 Block，控制台交互仍由配置执行侧处理。
- 高风险写入口为 `POST /api/feedback`；匿名未登录请求返回 `401`，真实已登录用户仍可提交。
- Cloudflare Free 当前只能创建一条 rate-limit 规则。
- CloudBase 默认源站仍能直接访问 `/`、`/rules`、`/feedback`，可绕过 Cloudflare。

#### A. `/api/feedback` 唯一限流参数

产品决定：批准以下唯一可执行值，不再保留并行候选。

- 匹配主机：仅正式根域 `ungradeedu.eu.cc`。
- 请求方法：仅 `POST`。
- 请求路径：精确匹配 `/api/feedback`。
- 统计维度：每个来源 IP 独立统计；同一 IP 下所有匹配请求共同计数，不区分账号，也不区分最终返回成功、`401` 或其他状态。
- 阈值：同一来源 IP 在连续 `10 分钟` 内最多 `5 次`。
- 处置：超过阈值后阻断该来源 IP 对该精确入口的匹配请求 `10 分钟`。
- 误伤决策：允许同一 NAT 下正常用户被短时误伤，作为 Cloudflare Free 单规则、单 IP 维度的已知残余风险；理由是正常用户不应在 10 分钟内提交超过 5 次风险反馈，且误伤只影响该 POST 入口，不影响浏览、登录、聊天或其他业务路径。
- 用户口径：触发限流时只能提示“提交过于频繁，请 10 分钟后再试”，不得暗示账号被封禁或反馈已被平台受理。

#### B. 源站隔离产品可用性门禁

产品决定：允许采用“观察模式 → Worker 注入专用头并剥离客户端同名头 → 验证 → 源站强制无密钥 `403`”的分阶段方案；产品经理只定义可用性门禁，不参与密钥、Worker 或源站实现。

唯一上线节奏：

1. 观察模式持续 `24 小时`：只记录缺少专用头的源站访问，不改变返回结果；不得记录密钥值、Cookie、联系方式或反馈正文。
2. 在北京时间 `00:00–01:00` 低流量窗口部署 Worker 专用头注入及客户端同名头剥离；源站暂不强制 `403`，保持 `30 分钟` 灰度观察。
3. 灰度期间必须验证根域 `/`、`/rules`、`/feedback` 为 `200`，匿名 `GET /api/feedback` 为 `401`，并使用专用验收账号完成一次登录后反馈提交；不得使用真实未成年人、联系方式或投诉隐私作为测试数据。
4. 上述检查全部通过后，在同一低流量窗口启用源站“无正确专用头即 `403`”，随后持续监控 `30 分钟`。

允许的维护风险：

- 不安排主动停机；允许切换或回滚过程中出现累计不超过 `5 分钟` 的短暂不可用。
- 不允许反馈记录丢失、登录会话大面积失效、聊天主链路不可用或敏感专用头返回给浏览器。
- 如果预计不可用会超过 5 分钟，必须取消本次切换并恢复原状态，不得带故障继续上线。

失败与回滚条件：

- `/`、`/rules`、`/feedback` 任一路径连续两次探测不是 `200`，两次间隔 `60 秒`。
- 匿名 `GET /api/feedback` 不再返回 `401`。
- 专用验收账号的登录后反馈提交可稳定复现一次失败。
- Worker 正常请求被源站返回 `403`，或客户端自带同名头能够绕过 Worker 剥离规则。
- 专用头值出现在浏览器响应、公开日志或用户可见错误信息中。

任一条件触发后必须在 `5 分钟` 内开始回滚：先取消源站强制 `403`、恢复无密钥可访问，再回滚 Worker 专用头相关变更；回滚顺序不得反向。回滚完成后重新验证核心路由与反馈权限边界，未再次通过前不得重启强制隔离。

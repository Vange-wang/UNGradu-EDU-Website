# 举报 / 投诉最小闭环需求边界草案

日期：2026-06-30

关联阶段：S5 vNext 产品能力拆解

关联任务：`RELEASE-S5-VNEXT-2026-06-30-001`

## 1. 背景

S3 已建立风险提示与反馈入口边界，S4 已确认公开推广前仍缺少正式举报 / 投诉处理闭环。

当前反馈入口适合小范围试运行，不适合作为公开推广后的正式客服或工单系统。

## 2. 最小闭环目标

举报 / 投诉最小闭环应至少做到：

- 用户能提交风险反馈。
- 平台能记录反馈来源、对象、类型、内容和时间。
- 平台能区分功能问题、骚扰、虚假信息、联系方式滥用、未成年人风险、交易争议等类型。
- 平台能记录处理状态。
- 平台能保留处理记录。
- 用户界面不承诺即时客服、人工仲裁或退款担保。

## 3. 最小数据字段草案

未来可考虑新增集合，例如 `risk_reports` 或 `support_reports`。字段草案：

| 字段 | 说明 |
| --- | --- |
| `_id` | 记录 ID |
| `reporterUserId` | 提交人 |
| `targetType` | 对象类型：teacher、parent_need、chat、contact_exchange、other |
| `targetId` | 对象 ID |
| `category` | 分类 |
| `description` | 用户描述 |
| `evidenceText` | 可选证据描述 |
| `status` | open、reviewing、resolved、dismissed |
| `createdAt` | 创建时间 |
| `updatedAt` | 更新时间 |
| `resolutionNote` | 处理备注 |

真实字段需在正式 Spec 中确认。

## 4. 状态流草案

```text
open -> reviewing -> resolved
open -> reviewing -> dismissed
```

当前不承诺：

- 实时响应。
- 人工仲裁。
- 退款处理。
- 封禁自动执行。
- 认证撤销。

## 5. 页面入口草案

后续可考虑：

- 反馈页升级为风险反馈表单。
- 老师详情页增加“反馈风险”入口。
- 需求详情页增加“反馈风险”入口。
- 聊天页增加“反馈风险”入口。
- 联系方式交换记录页增加“反馈风险”入口。

## 6. 技术风险

- 需要权限校验，避免用户举报不存在或无权查看的对象。
- 需要防刷和频率限制。
- 需要避免举报内容泄露联系方式、未成年人信息和隐私。
- 需要明确记录保存周期。
- 需要明确管理员或后续 Agent 如何查看和处理。

## 7. 当前结论

举报 / 投诉最小闭环可以作为 S5 后续 P0 专项。当前阶段先完成边界设计与技术核查，不直接宣称平台具备正式客服或投诉处理能力。

## 1. 背景与目标

M1、M2、M3、M4、M5 均已完成阶段验收。M5 托管环境最终验收报告确认：CloudBase Run 测试托管服务 `ungradu-edu-m5-test` 已在真实公网地址完成 `npm run m5:hosted:verify` 复验，HTTP flow 与 50 虚拟用户 load 均 100.00% 成功。

同时，M1-M5 整体代码架构审查确认：当前代码框架整体合理，可以维持 MVP/M5 验收通过结论，但正式生产发布前仍需要完成产品、部署、安全、测试账号、回滚和代码底层架构收口。

本阶段目标不是扩大 MVP 功能范围，而是让已完成的 MVP 功能更可靠、更可说明、更可部署、更可回滚，并把当前代码核实报告和审核报告确认真实存在的 P1/P2 问题处理到可验收状态。

## 2. 阶段定位

本阶段是“发布前收口与架构治理”，承接已通过的 M5，不重新定义 M1-M5 业务范围。

核心目标：

- 完成 MVP 产品说明，明确已包含与不包含能力。
- 完成生产环境变量清单，区分测试托管环境与正式生产环境。
- 完成测试账号管理方案，避免测试数据和测试登录污染生产。
- 完成上线回滚预案，明确 CloudBase Run 服务、镜像、代码提交和环境变量的回退方式。
- 完成正式生产禁用测试登录确认。
- 处理架构审查、审核报告和代码核实报告共同确认的 P1 问题。
- 处理关键 P2 收口项，降低试运行风险。
- 将公开列表约 1000 条近期公开记录分页上限纳入后续技术债或 vNext 性能优化清单。
- 建立架构收口问题修复对照表，记录每项修复对应提交、测试和托管复验状态。

## 4. 范围边界

### 4.1 本阶段包含

产品与发布准备：

- MVP 产品说明。
- 生产环境变量清单。
- 测试账号管理说明。
- 上线回滚预案。
- 正式生产禁用测试登录确认清单。
- 发布前手工验收或浏览器冒烟验收清单。
- 架构收口问题修复对照表。

代码架构和规范性收口：

- 聊天会话查询索引化，避免全集合扫描。
- 登录 `next` 参数白名单校验。
- 反馈入口真实可执行。
- Cookie 服务端硬过期校验。
- API 非 JSON 响应容错。
- 可见登出入口。
- 证明图片当前能力边界说明。
- 最小浏览器冒烟 E2E 或等价手工验收记录。

技术债记录：

- 公开列表约 1000 条近期公开记录分页上限。
- 老师资料价格区间模型与 UI 不一致。
- 旧 localStorage 代码治理。
- 重复校验、ID、分页和错误处理工具抽取。

### 4.2 本阶段不包含

本阶段不新增以下业务能力：

- 在线支付、平台抽佣、退款。
- 复杂排课、课时记录、合同。
- 评价体系。
- 自动推荐算法。
- 人工撮合。
- 完整审核后台。
- 实名认证。
- 认证等级。
- 举报、拉黑、封禁后台。
- 图片聊天、语音聊天、已读未读、撤回。
- 多城市扩展或地图模式。
- 完整客服工单系统。

这些能力仍属于 vNext 或后续迭代讨论范围，不进入本阶段发布前收口。

## 5. 产品说明要求

应新增一份面向业务方、测试人员和后续运营的 MVP 产品说明文档。

必须说明：

- MVP 面向东莞大学城及周边区域的家教自助撮合。
- 当前支持手机号账号体系下的家长端和大学生端使用场景。
- 当前支持家长发布需求、大学生发布家教信息、双边广场筛选、详情查看、站内文字聊天、双方同意并二次确认后交换联系方式。
- 当前免费，不做支付、抽佣或交易担保。
- 当前不做人工撮合、不做人工审核、不做评价、不做举报封禁后台。
- 当前证明图片能力边界：若尚未实现真实 CloudBase 文件上传和查看，应明确说明“当前不提供正式证明图片审核能力”，避免用户误解。
- 当前反馈入口和处理方式。
- 当前正式生产不允许使用 M5 托管测试登录。

验收标准：

- 文档能让非开发人员理解 MVP 能做什么、不能做什么。
- 文档不得暗示已经具备未实现能力。
- 文档不得出现真实密钥、测试密钥或任何敏感凭据。

## 6. 生产环境变量清单

应新增一份生产环境变量清单，明确测试托管环境与正式生产环境的差异。

正式生产必须配置：

```text
APP_ENV=production
AUTH_SESSION_SECRET=<生产专用强随机密钥>
CLOUDBASE_ENV_ID=<生产或正式试运行 CloudBase 环境 ID>
TENCENTCLOUD_SECRETID=<生产环境腾讯云 SecretId>
TENCENTCLOUD_SECRETKEY=<生产环境腾讯云 SecretKey>
```

正式生产必须关闭或不设置：

```text
M5_ENABLE_HOSTED_TEST_LOGIN
NEXT_PUBLIC_ALLOW_TEST_LOGIN
```

要求：

- `APP_ENV=production` 是禁用测试登录的主闸。代码核实确认：只要 `APP_ENV=production`，即使误将 `M5_ENABLE_HOSTED_TEST_LOGIN=true` 或 `NEXT_PUBLIC_ALLOW_TEST_LOGIN=true` 配入环境，测试登录仍应被服务端拒绝。
- 生产 `AUTH_SESSION_SECRET` 必须独立强随机，不得复用测试环境密钥。
- 真实 `TENCENTCLOUD_SECRETID`、`TENCENTCLOUD_SECRETKEY`、`AUTH_SESSION_SECRET` 不得写入 Git、规划文档正文或聊天记录归档。
- 文档只记录变量名称、用途、是否必填、配置位置、生成或轮换要求，不记录真实值。
- 若生产仍未接入正式短信登录，应明确当前不能直接开放给真实公网用户作为正式生产登录入口，或必须先完成正式登录方案确认。

验收标准：

- 能按清单在 CloudBase Run 或等价生产环境完成配置。
- 清单明确哪些测试变量禁止出现在生产环境。
- 清单明确密钥轮换和泄露处理原则。

## 7. 测试账号管理

应新增测试账号管理说明，覆盖 M5 验收脚本、测试托管环境和后续试运行测试。

必须说明：

- 测试账号只能用于 `APP_ENV=test` 或本地开发环境。
- 测试账号不得作为生产真实用户账号运营。
- M5 脚本生成的需求、家教信息、会话、消息和联系方式交换记录应有可识别前缀、时间范围或清理策略。
- 测试数据清理不得误删真实用户数据。
- 若继续保留测试托管环境，应明确测试环境与生产环境的数据隔离方式。
- 生产环境不得开放 `/api/auth/test-login` 作为普通用户登录方式。
- 生产环境不得接受通过 `x-ungradu-test-user-phone` 请求头传入的备用测试身份。该路径由 `readAuthenticatedUserId` 经 `isTestLoginAllowed` 闸门控制，`APP_ENV=production` 时必须返回拒绝结果。

验收标准：

- 能区分测试账号、试运行账号和真实用户账号。
- 能说明测试数据如何识别、清理或隔离。
- 生产禁用测试登录的规则与环境变量清单一致。

## 8. 上线回滚预案

应新增上线回滚预案，至少覆盖 CloudBase Run 维度。

必须说明：

- 当前准备上线的代码提交或镜像版本。
- 上一稳定版本或可回退提交。
- CloudBase Run 服务名、镜像、环境变量和部署配置的回退方式。
- 环境变量变更如何回退。
- 回滚后必须执行的验证命令或手工检查。
- 回滚期间如何告知业务方和测试人员。

最低回滚验证：

- 首页可访问。
- 登录入口行为符合当前环境配置。
- 发布、筛选、详情、聊天、联系方式交换核心路径至少完成一轮冒烟检查。
- `APP_ENV=production` 下测试登录不可用。

验收标准：

- 回滚步骤清晰到可执行。
- 不需要依赖某个开发者的口头记忆。
- 不包含真实密钥。

## 9. 正式生产禁用测试登录确认

正式生产发布前必须完成一份禁用测试登录确认记录。

确认项：

- 生产环境 `APP_ENV=production` 已配置。
- 生产环境未配置 `M5_ENABLE_HOSTED_TEST_LOGIN=true`；若误配为 `true`，也必须被 `APP_ENV=production` 主闸拒绝。
- 生产环境未配置 `NEXT_PUBLIC_ALLOW_TEST_LOGIN=true`；若误配为 `true`，也必须被 `APP_ENV=production` 主闸拒绝。
- 生产 `AUTH_SESSION_SECRET` 已配置，且不是测试环境密钥。
- 调用 `/api/auth/test-login` 在生产环境返回拒绝结果。
- 通过 `x-ungradu-test-user-phone` 请求头传入备用测试身份时，生产环境同样返回拒绝结果。
- 前端页面不展示“测试账号”“测试验证码 000000”等误导真实用户的文案。
- 若后续轮换 `AUTH_SESSION_SECRET`，需提前确认是否会导致全部在线用户被强制登出，并评估轮换时机和通知方式。

验收标准：

- 有命令输出、截图记录或验收报告证明生产环境拒绝临时测试登录。
- 若因尚未部署生产环境无法验证，应明确标记为“生产发布前阻塞项”，不得以测试托管环境通过替代。

## 10. 代码底层架构和规范性收口

### 10.1 P1：聊天会话查询索引化

当前风险：

- `server/conversations.ts` 中会话查询仍存在全集合扫描风险。
- 数据量增长后可能出现会话漏读、重复创建会话、聊天列表缺失或性能下降。

代码核实：

- `readAllConversations()` 当前使用 `conversationsCollection.where({}).get()` 后再内存过滤。
- `createOrReadServerConversationFromSource()` 和 `listServerConversationsForUser()` 均依赖该全量读取结果做筛选和去重。
- 该问题与 M5 第四轮修复的 `parent_needs` / `tutor_profiles` 公开列表全集合扫描问题属于同一代码模式的复发。

要求：

- 直接参考 M5 第四轮已验证过的“按条件过滤 + `orderBy` + `skip` / `limit` 分页轮询”思路，或设计更稳妥的会话索引方案。
- 为会话新增稳定可查询字段，例如 `participantKeys`、`sourceKey`、`conversationUniqKey` 或等价设计。
- 创建会话时根据来源对象和双方用户生成稳定唯一键。
- 查询用户聊天列表时按当前用户参与键查询，不依赖全集合扫描。
- 创建或读取同一来源、同一双方用户会话时不得重复创建。

验收标准：

- 补充与 `parent-need-server.test.ts` 同等强度的回归测试：已有大量历史会话时，当前用户仍能稳定查询自己的会话。
- 补充测试覆盖：同一来源和同一双方用户重复进入详情发起聊天，不重复创建会话。
- 不在对外返回值中暴露未授权联系方式。
- 修复后需随下一次 `npm run m5:hosted:verify` 一并复验。

### 10.2 P1：登录 `next` 参数白名单校验

当前风险：

- 登录成功后直接使用 `next` 参数跳转，存在开放重定向或非预期跳转风险。

代码核实：

- 当前实现位置：`features/auth/login-form.tsx`。
- 登录成功回调中直接执行 `router.push(searchParams.get("next") ?? "/")`，未做任何字符串校验。

要求：

- 新增 `sanitizeNextPath()` 或等价逻辑。
- 只允许以 `/` 开头且不以 `//` 开头的站内相对路径。
- 空值、外部 URL、协议相对 URL、异常输入统一回退到 `/`。

验收标准：

- 单测覆盖合法站内路径。
- 单测覆盖 `https://example.com`、`//example.com`、空值和异常输入。
- 登录成功后的跳转使用清洗后的路径。
- 修复后需随下一次 `npm run m5:hosted:verify` 一并复验。

### 10.3 P1：反馈入口真实可执行

当前风险：

- 反馈页只有文案，没有真实邮箱、`mailto:` 链接、表单或外部收集链接。

要求：

- 至少提供一个真实可用反馈通道。
- 可以选择运营邮箱、`mailto:` 链接、最小反馈表单或外部表单链接。
- 页面说明反馈将在 3 个工作日内人工查看。
- 页面说明适用场景：虚假信息、骚扰、联系方式滥用、功能异常。

验收标准：

- 用户能从页面完成反馈提交或打开反馈渠道。
- 页面不再只有“请通过运营邮箱提交反馈”这类不可执行文案。
- 修复后需随下一次 `npm run m5:hosted:verify` 一并复验。

### 10.4 P2：Cookie 服务端硬过期校验

要求：

- 服务端读取签名 Cookie 时校验 `createdAt`。
- 超过有效期、时间格式非法或未来异常时间应拒绝。
- Cookie `Max-Age` 与服务端硬过期规则保持一致。

验收标准：

- 单测覆盖有效 Cookie。
- 单测覆盖过期 Cookie。
- 单测覆盖非法 `createdAt`。
- 修复后需随下一次 `npm run m5:hosted:verify` 一并复验。

### 10.5 P2：API 非 JSON 响应容错

当前背景：

- M5 托管复验首次曾遇到 CloudBase Run 返回 HTML 错误页。
- 代码核实确认多个前端 API client 直接 `await response.json()`，无统一非 JSON 容错。

要求：

- 前端 API client 不应默认所有响应都是 JSON。
- 对非 JSON、HTML 错误页、网络失败、非 2xx 响应给出统一可读错误。
- 可抽取统一响应解析工具。

验收标准：

- 单测覆盖非 JSON 响应。
- 单测覆盖 500/502 等错误状态。
- 页面不因 `response.json()` 解析异常而直接崩溃。
- 修复后需随下一次 `npm run m5:hosted:verify` 一并复验。

### 10.6 P2：可见登出入口

要求：

- 在个人页或全局导航提供“退出登录”入口。
- 调用 `/api/auth/logout`。
- 退出后跳转首页或登录页。

验收标准：

- 用户能主动退出当前账号。
- 退出后访问需登录页面会重新要求登录。
- 修复后需随下一次 `npm run m5:hosted:verify` 一并复验。

### 10.7 P2：证明图片能力边界说明

当前风险：

- 若当前仅保存证明图片元数据，页面却显示“证明图片 N 张”，可能让用户误以为已经支持真实上传、查看和审核。

要求：

- 若不做真实 CloudBase 文件上传，应在发布页、详情页或产品说明中明确当前能力边界。
- 不得暗示平台已经具备证明图片审核能力。
- 若决定保留入口，应明确“证明图片正式上传与审核属于后续真实性迭代”。

验收标准：

- 页面文案与真实能力一致。
- 产品说明同步说明该边界。
- 修复后需随下一次 `npm run m5:hosted:verify` 一并复验。

## 11. 浏览器冒烟验收

本阶段建议补充最小浏览器冒烟验收，可使用 Playwright，也可先使用手工验收清单。

最低路径：

1. 登录或进入受控测试登录。
2. 家长发布需求。
3. 大学生发布家教信息。
4. 家长在家教信息广场筛选并进入详情。
5. 大学生在需求广场筛选并进入详情。
6. 发起聊天。
7. 双方发送文字消息。
8. 发起联系方式交换请求。
9. 接收方同意并完成二次确认。
10. 双方看到授权后的存档联系方式。
11. 退出登录。

验收标准：

- 有脚本结果或手工验收记录。
- 若使用生产环境验证，必须确认测试登录已禁用，不能使用 M5 测试登录路径。

## 12. 技术债与 vNext 性能优化清单

### 12.1 公开列表分页上限

当前状态：

- M5 修复已将公开列表查询从单次 `.get()` 改为按 `status=published`、`createdAt desc`、`skip` / `limit` 分页读取近期公开记录。
- 当前策略最多读取约 1000 条近期公开记录。
- 该问题不阻塞当前 MVP/M5，但正式增长前需要治理。

产品语义说明：

- 当 `status=published` 的有效记录数超过约 1000 条时，最早发布且仍在分页窗口之外的记录可能不再出现在公开列表中。
- 这不是“近期发布的新记录丢失”问题，M5 第四轮已修复该场景。
- 它更接近“非常旧的历史记录在数据量很大时逐渐从公开列表退出”的产品表现。vNext 需要明确这是期望的“只展示近期活跃发布”模型，还是必须支持完整历史回溯。

后续方向：

- 设计数据库索引。
- 使用游标分页或服务端分页 API。
- 避免服务端读取大量记录后内存筛选。
- 为公开列表增加稳定分页参数和回归测试。

归类：

- 技术债：公开列表分页上限。
- vNext 性能优化：公开列表索引化与游标分页。

### 12.2 老师资料价格区间模型与 UI 对齐

当前状态：

- 模型支持 `feeRanges` 数组。
- UI 当前只编辑第一组价格区间。

后续方向：

- 若 MVP 只支持一组价格区间，将模型和文案收敛为单组。
- 若 vNext 支持多组价格区间，补充添加、删除、展示和筛选规则。

### 12.3 旧 localStorage 代码治理

当前状态：

- M5 主路径已迁移到服务端 API。
- 旧本地存储逻辑仍保留，用于历史阶段、测试或兼容。

后续方向：

- 标记 legacy。
- 删除不再使用路径。
- 保留必要测试工具时明确边界。

### 12.4 通用工具抽取

后续方向：

- 抽取重复校验规则。
- 抽取 ID 生成规则。
- 抽取分页和错误处理工具。
- 统一 API client 响应解析。

## 15. 风险说明

- 当前 M5 通过基于测试托管环境，不等同于生产环境已经可直接开放。
- 若生产仍未接入正式登录方案，则不能把 M5 测试登录作为真实用户登录方式。
- 若跳过聊天会话索引化，随着数据增长可能出现重复会话或聊天列表缺失。
- 若跳过反馈入口，用户遇到虚假信息或骚扰时缺少最小处理通道。
- 若跳过回滚预案，生产异常时恢复依赖人工记忆，风险不可接受。

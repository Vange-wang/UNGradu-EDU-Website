# MVP 产品说明

日期：2026-06-24
阶段：MVP 发布前准备

## 1. 产品定位

UNGradu EDU MVP 面向东莞大学城及周边区域，提供家教供需双方的自助撮合闭环。当前目标是验证家长/学生发布需求、大学生发布家教信息、双方筛选沟通并在双向同意后交换联系方式的最小可用流程。

## 2. 当前已支持

- 手机号账号体系下的家长端和大学生端使用场景。
- 家长发布结构化家教需求。
- 大学生发布家教信息。
- 需求广场和家教信息广场的科目、学段、价格、性别筛选。
- 公开详情页查看，但不展示发布者联系方式。
- 站内基础文字聊天。
- 任一方发起联系方式交换请求。
- 接收方同意前需要二次确认。
- 双方同意并完成二次确认后，在对应聊天会话中展示双方存档联系方式。
- 最小反馈入口：通过 GitHub issue 页面提交反馈，MVP 阶段由项目人员人工查看。

## 3. 当前不包含

- 在线支付、平台抽佣、退款或交易担保。
- 人工撮合。
- 人工审核后台。
- 实名认证、认证等级。
- 评价体系。
- 举报、拉黑、封禁后台。
- 自动推荐算法。
- 复杂排课、课时记录、合同。
- 图片聊天、语音聊天、已读未读、撤回。
- 第三方 IM SDK。
- 多城市扩展或地图模式。

## 4. 证明图片边界

当前大学生家教信息中的证明图片入口只记录文件名、文件类型和文件大小等元信息，不提供正式 CloudBase 文件上传、查看、审核或真实性认证能力。正式证明图片上传与审核属于后续真实性与风控迭代，不得在当前 MVP 中宣传为已具备能力。

## 5. 登录与生产边界

M5 测试托管环境使用隔离测试登录能力完成验收。正式生产环境不得使用 M5 托管测试登录作为真实用户登录方式。

正式生产必须配置 `APP_ENV=production`，且不得启用 `M5_ENABLE_HOSTED_TEST_LOGIN=true` 或 `NEXT_PUBLIC_ALLOW_TEST_LOGIN=true`。若生产仍未接入正式短信登录或业务确认的登录方案，则不得直接开放给真实公网用户作为正式生产登录入口。

## 6. 反馈处理方式

反馈页提供 GitHub issue 提交入口，用于收集虚假信息、骚扰、联系方式滥用和功能异常。MVP 阶段反馈由项目人员人工查看，页面承诺 3 个工作日内人工查看；该承诺用于 MVP 内部处理，不构成正式 SLA。

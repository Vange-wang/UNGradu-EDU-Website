## Serious Findings

### SF-1 — 状态码 "401/403/404" 与 "不泄露对象存在性" 互相矛盾，缺少防枚举映射规则

- **Location:** §2.3 第 59 行（"未认证或失权访问得到安全的 401/403/404 结果，不泄露对象存在性、联系方式或内部实现细节"）；关联 §2.1 目标 2（第 40 行，含"跨账号枚举"）、§5 V3-S1（第 113 行，"枚举测试"）。
- **Evidence:** 文档同时要求 (a) 对未认证/失权访问返回 401/403/404 三种不同状态码，且 (b) 不泄露对象存在性。但标准实现里 403=对象存在但无权、404=对象不存在，二者区分会直接泄露对象存在性，恰好助长文档自己要防御的"跨账号枚举/IDOR"。此外 §8 可测试验收标准（第 150–157 行）只把"枚举"列为用例，未把"不泄露对象存在性"落到可测试判据，也未规定状态码的规范映射。
- **Impact:** 实现方可能采用"存在但无权→403、不存在→404"，从而违背本 Spec 自身的枚举防护目标，泄露对象存在性。对安全基线关闭 Spec 而言属安全正确性缺陷。
- **Correction:** 将"401/403/404"替换为显式防枚举映射规则（如：未认证→401；对无权/不存在的对象统一返回 404 使二者不可区分，仅当认证接口明确可安全区分时才用 403，并说明为何不泄露存在性），并把该规则写入 §8 作为一条可测试验收标准 + 负向测试用例。Future closure trigger：出现 403/404 语义映射规范并通过对应负例。

### SF-2 — 目标 5 的 "CloudBase/Worker/域名入口边界验证" 无对应验收标准与证据阶段

- **Location:** §2.1 目标 5（第 43 行）列出 "CloudBase、Worker、源站、域名入口的边界验证"；§5 证据矩阵（第 112–116 行）仅 V3-S2 覆盖"源站隔离"；§8 验收标准（第 150–157 行）无任何一条提及 CloudBase/Worker/域名入口。
- **Evidence:** 目标 5 枚举了四个信任边界，但只有"源站"能溯源到证据（V3-S2）与验收标准（§8 第 1 条"源站隔离"）。CloudBase 边界、Worker 边界、域名入口（如 Worker 认证绕过、直连源站绕过 CDN/WAF、域名入口错路由）既无独立证据行，也无 pass/fail 判据。
- **Impact:** 这些边界可能被默认视作"已覆盖"却无可复现的通过与失败测试，削弱 §2.1 承诺的"可复现、可独立审计的关闭路径"，造成未测信任边界进入生产。
- **Correction:** 为 CloudBase/Worker/域名入口边界验证补一条明确验收标准并映射到证据阶段（含直连源站绕过、Worker/CloudBase 认证边界绕过、域名入口错路由等负例）；或显式声明其在范围外并给出理由。Future closure trigger：该边界出现对应负例证据与独立复核通过。

## Non-Serious Findings

- **NF-1** — "模板/命令边界"（§2.1 目标 3，第 41 行）未映射到 §5 证据或 §8 验收标准（仅列注入/SSRF）。建议显式映射，或注明"注入"已涵盖模板/命令注入。
- **NF-2** — "依赖"与"滥用控制"（§2.1 目标 4，第 42 行）无验收标准；"依赖结果"仅出现在 V3-S3 产物（第 115 行）。建议补 pass/fail 判据（如依赖漏洞阈值、滥用/限流生效阈值）。
- **NF-3** — "删除/恢复"（§2.1 目标 6，第 44 行）在 V3-S1 证据中出现（第 113 行），但 §8 验收标准未提及。建议补显式判据。
- **NF-4** — "上一已验收版本"用语与实际状态张力：§1.1（第 16 行）明确"生产验收仅部分通过"，§4.2（第 99 行）却要求 base receipt 证明该提交"确实对应上一已验收版本的技术、产品、UI/适用复核与业务状态"。§4.1（第 89 行）已要求记录"验收层级"部分缓解，但"已验收版本"易被读作"已全量验收"。建议明确 base 提交可接受的验收层级语义（例如"TECH_REVIEW_PASS、生产验收未完成"可作 base，并列出残余风险）。
- **NF-5** — "D7"未定义：第 75 行（"D7 owner/频率/保留/阈值"）与第 118 行（"D7 值"）使用该词但全文无定义。建议补一句定义（如"D7 = 7 天生产观察期"），便于独立阅读。
- **NF-6** — "V3"（路线图阶段）与"v2.3.2"（产品版本）标签并存未区分：标题"目标版本 v2.3.2"+任务 ID "V3-V7..."，正文大量用"V3 分支/V3 进入实现/V3-S0..S4"。建议加一句说明 V3 指路线图阶段而非版本号，避免下游路由歧义。
- **NF-7** — "只读降级"（§2.3 第 62 行）与"fail-closed 拒绝"（§6 第 126 行）语义张力：§9 已把"降级语义"列为待业务确认项，但 §2.3 把"只读降级"列为可接受安全响应，可能被误读为允许泄露敏感读路径。建议限定"只读降级仅适用于不泄露对象存在性/敏感字段的路径"。

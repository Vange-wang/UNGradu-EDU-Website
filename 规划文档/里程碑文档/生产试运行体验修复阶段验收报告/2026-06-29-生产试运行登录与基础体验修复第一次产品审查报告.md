## 二、逐项验收

### 1. ISSUE-0013：验证码失败不消耗、成功后才消耗、错误提示区分

判断：**通过，建议交由 ISSUE 管理员关闭**。

验收依据：

- 服务端 `verifyEmailLoginCode()` 只负责校验验证码与创建 / 更新邮箱用户，不再在校验成功时立即写入 `usedAt`。
- 登录 API 在成功生成会话 Cookie 后，才调用 `markEmailLoginCodeUsed()` 标记验证码已使用。
- 会话创建失败时返回“登录服务暂时不可用，请稍后重试”，状态为 503，验证码仍保持未使用，可再次登录。
- 自动化测试覆盖“会话创建不可用时不消耗有效验证码”和“成功登录响应后才标记验证码 used”。
- 错误提示已区分验证码发送失败、发送过于频繁、验证码过期、验证码已使用、登录服务暂时不可用、邮箱或密码错误等场景。

产品判断：原先“第一次服务不可用，第二次提示验证码已使用”的核心缺陷已修复。真实 SMTP 不可用仍可能导致发信失败，但不应再把未成功登录的验证码错误标记为 used。

### 2. ISSUE-0011：未登录导航显示登录 / 注册、不显示退出登录

判断：**通过，建议交由 ISSUE 管理员关闭**。

验收依据：

- `SessionNav` 在无会话状态显示“登录 / 注册”和“规则”。
- 无会话状态不显示“退出登录”。
- 登录后才显示“个人页”和“退出登录”。
- 加载中的兜底导航未显示退出登录，不会造成“未登录用户可退出”的误导。

产品判断：用户不再需要绕到个人页才能登录，未登录状态的导航语义已经清晰。

### 3. ISSUE-0012：退出登录二次确认

判断：**通过，建议交由 ISSUE 管理员关闭**。

验收依据：

- 顶部导航退出入口调用 `window.confirm("确认退出登录吗？退出后需要重新登录。")`。
- 个人页退出入口也调用同一二次确认文案。
- 用户取消确认时不调用退出接口；只有确认后才执行 `/api/auth/logout`。
- 退出接口失败时展示失败提示，避免用户误以为已经退出。

产品判断：满足“防止误点退出”的本轮最小要求。后续如需替换为自定义确认弹窗，可作为体验优化，不阻塞本轮验收。

### 5. ISSUE-0014：首次注册后可设置密码登录

判断：**通过，满足本轮 MVP 口径，建议交由 ISSUE 管理员关闭**。

验收依据：

- 首次邮箱验证码注册 / 登录成功后，个人页提供“设置登录密码”表单。
- 新增 `POST /api/auth/password/set`，要求当前会话存在，并校验提交邮箱与当前登录邮箱一致。
- 登录页保留邮箱验证码登录，并新增“密码登录”和“忘记密码”入口。
- 新增 `POST /api/auth/password/login`，支持邮箱 + 密码登录。
- 新增 `POST /api/auth/password/reset`，支持通过邮箱验证码重置密码。
- 密码最小规则为 8-72 位，且同时包含字母和数字，并要求二次确认一致。
- 密码使用随机 salt + `scrypt` 哈希保存为 `passwordHash`，自动化测试确认不保存明文。
- 错误密码使用“邮箱或密码不正确”通用提示，并包含失败次数 / 锁定保护。
- 自动化测试覆盖设置密码、弱密码拦截、二次确认不一致、邮箱 + 密码登录、错误密码、邮箱验证码重置密码等关键路径。

产品判断：本轮需要的密码登录 MVP 已完成。复杂账号合并、第三方登录、多因素认证、统一账号安全中心等仍属于明确不做范围，不应算作本轮代码阻塞。

## 2. 目标、非目标与用户可见结果

### 2.1 目标

为家长需求和老师资料中的有限字段建立可解释、可回放、可申诉的联系方式审核闭环，至少覆盖：

- childIntro 与 abilityDescription 的窄字段处理；
- 原始 Unicode 保留、规范化、偏移映射和异常转人工；
- `allow_candidate`、`contact_confirmed`、`contact_likely`、`ambiguous`、`normalization_failure`、`input_error`、`policy_error` 七类审核结果；
- draft、pending_review、needs_manual_review、published、rejected、appeal_pending、deleted 的状态边界；
- 确定性规则优先，AI 仅作辅助候选，不单独自动拒绝；
- 人工队列、二次复核、申诉、删除/恢复、编辑和审计；
- 公开内容、联系方式、未成年人信息和旧版本快照的最小化。

### 2.2 非目标

- 不扩大到非批准字段，不审核全部用户生成文本，不引入 OCR、抓取 URL、执行嵌入或任意外部工具。
- 不选择 AI/人工供应商、模型、region、DPA、预算、生产 key、数据出域或训练用途。
- 不允许 AI 单独自动拒绝、自动公开或替代人工 owner。
- 不改变已发布内容的所有权、聊天/联系方式授权、删除生命周期或数据库存储语义。
- 不关闭任何文档债务 Issue；本 Spec 的唯一 Issue 为 ISSUE-0036。
- 本轮不写代码、UI、生产数据、平台配置或 Issue canonical/state。

### 2.3 用户可见结果

在适用证据全部通过后：

1. 提交需求或资料后，用户明确看到待审核、需人工处理、已发布、被拒绝或申诉中的状态，不看到内部命中片段、模型分数、供应商名称或他人数据。
2. 未通过审核的内容不会悄悄公开；不确定、规范化失败、服务不可用、AI 超时和人工队列异常统一进入 needs_manual_review，不自动放行。
3. 已发布内容编辑、删除、恢复和申诉都会重新经过适用审核；旧发布快照不会因新草稿状态混淆而泄露。
4. 用户可以看到安全的下一步提示和申诉入口；联系方式只在既有双方授权规则允许时展示。
5. 家长、学生、老师的内容和联系方式按 owner/entity/version 隔离，用户不因审核结果看到其他账号原文。

这些是待验收结果，不是当前已生产通过的承诺。

## 5. 可冻结的功能契约

### 5.1 字段与规范化

只处理被业务确认的窄字段。保留原始 Unicode 视图以便审计，再生成 NFKC/偏移映射视图；映射失败、冲突、语言/国家范围不明、号码无法可靠归一化或规则结果不确定时，转 needs_manual_review，不自动 allow 或 reject。原文、归一化值和命中片段均按最小化和访问控制保存。

### 5.2 结果与状态

状态枚举唯一冻结为 `draft`、`pending_review`、`needs_manual_review`、`published`、`rejected`、`appeal_pending`、`deleted`。`pending_review` 表示服务端已接收、等待确定性/自动审核；`needs_manual_review` 表示出现联系方式信号、歧义、规范化/服务/策略失败或需要人工决定，二者均不得公开。

审核结果分类与状态映射唯一为：

| 结果分类 | 目标状态 | 约束 |
| --- | --- | --- |
| allow_candidate | pending_review | 只是允许候选；后续经授权审核决定才可 published |
| contact_confirmed | needs_manual_review | 不自动拒绝或公开 |
| contact_likely | needs_manual_review | 不自动拒绝或公开 |
| ambiguous | needs_manual_review | 不确定统一转人工 |
| normalization_failure | needs_manual_review | 不因解析失败放行 |
| input_error | draft | 返回可修正且不泄露内部规则的提示 |
| policy_error | needs_manual_review | 不由客户端或 AI 直接决定拒绝 |

分类本身不得直接产生 published 或 rejected。任何状态转移必须在 owner/entity/version/hash 隔离和审计成功后由获授权决定执行。申诉路径固定为未编辑内容 `rejected → appeal_pending → needs_manual_review → published/rejected`，编辑后内容 `rejected → draft → pending_review`；deleted 恢复只能 `deleted → pending_review` 并完整重审，不能直达 published，也不得恢复未授权聊天/联系方式。

### 5.3 申诉与编辑

申诉、放弃、编辑、重复提交、删除和恢复必须有明确状态、幂等键、版本/hash、操作者和审计。业务尚未选择申诉后编辑还是取消后回 draft 时，保持“用户确认前未决”；两种路径均不得跳过新内容完整重审。

### 5.4 AI 与人工

AI 只能返回结构化、可验证、无工具调用的辅助结果；超时、不可达、解析失败、低置信度或政策不确定时转人工。生产出域、供应商、模型、region、DPA、预算、key、训练和保留政策必须单独确认。人工 owner、备援、二审、工作时段和 SLA 未登记时，生产闭环不可声称通过。

## 7. 隐私、未成年人与数据生命周期

- childIntro、abilityDescription 和联系方式含有潜在未成年人或家庭信息时，默认最小字段、最小访问、最小日志和最小保留。
- 测试只使用合成或脱敏语料；不把完整电话号码、微信号、住址、学校、孩子姓名、聊天正文或真实申诉内容发送到未经批准的 AI/provider。
- 公开端只显示已批准内容；审核命中原因可供必要的内部角色审计，但用户提示不回显敏感命中值或其他用户信息。
- 删除后不得由旧审核任务重新发布；恢复必须重审并重新计算权限和版本。
- 日志需保存可追溯的版本、规则 hash、操作者、结果和时间，但不得保存不必要的原文、模型提示、token 或 Secret。
- 未成年人处理、家长授权、投诉/法务保留期限如未在 canonical/业务确认中确定，保持用户确认前未决，不自行填充法律规则。

## 8. 失败路径、停止、回滚与重开

### 8.1 失败路径

规则冲突、规范化失败、AI 不可达、解析异常、队列超时、重复提交、跨账号访问、审计失败、人工 owner 缺失、申诉路径不明或数据出域不确定时，进入 needs_manual_review 或停止当前阶段；不自动公开、不自动拒绝、不恢复联系方式。

### 8.2 停止条件

发现 AI 单独改变发布决定、未知内容自动 allow/reject、OCR/URL 抓取悄然启用、跨账号泄露、删除后复活、人工队列不可审计、生产 key/DPA/owner 缺失、独立复核为 REWORK_REQUIRED 或业务撤回关键选择时，停止该阶段和后续部署。

### 8.3 回滚

回滚到最近一个有精确 base/配置 receipt 的已验收版本；先停新发布/审核副作用，再保留审计、恢复已批准旧快照、验证 owner/entity 权限和聊天/联系方式边界。回滚不得删除历史审计，不得将“开关存在”写成已演练。

### 8.4 重开

生产误放、误拒超出已确认边界、人工/申诉 SLA 失效、AI 出域或模型变化、未成年人/联系方式泄露、状态机绕过、规则/字段扩大或业务撤销接受时，ISSUE-0036 保持 Open 或按新证据重开。重开由 Issue 管理员执行，本稿不改状态。

## 9. 可测试验收标准

1. 仅批准字段进入审核；非批准字段不被隐式抓取或发布。
2. allow_candidate、contact_confirmed、contact_likely、ambiguous、normalization_failure、input_error、policy_error 均有可复现分类，并严格映射到第 5.2 节状态；分类不直接产生 published/rejected，不确定统一 needs_manual_review。

4. 跨账号、不同 owner/entity/version/hash 的相同内容不合并；重复提交幂等，审计可追溯。
5. draft、pending_review、needs_manual_review、published、rejected、appeal_pending、deleted 的状态转移、权限、删除/恢复和申诉编辑路径均有负例；未编辑申诉、编辑后重审及 deleted 恢复不得绕过 pending_review/needs_manual_review。
6. 用户可见文案不泄露命中值、模型分数、内部 owner、其他账号资料或未成年人敏感信息。
7. 真实人工 owner、备援、二审、SLA、供应商/DPA/key/region/预算/保留和训练政策未确认时，生产闭环保持阻塞。

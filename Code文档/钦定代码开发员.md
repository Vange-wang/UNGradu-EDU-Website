# 钦定代码开发员

日期：2026-06-22

用途：用于新会话线程无缝接续本项目代码开发工作，避免遗漏 Spec 边界、重复梳理代码结构、误改产品文档或产生与既有验收结论冲突的实现。

## 1. 角色定位

后续接手本项目代码工作的 AI 必须以“代码开发员”身份工作。

职责边界：

- 负责读取 Spec、里程碑、代码验收报告和开发员工作记录后再进行代码开发。
- 负责维护 `Code文档` 下的业务代码、测试、开发说明、代码结构说明和开发员工作记录。
- 负责让代码实现严格契合已确认的 Spec 和当前里程碑，不自行扩展未经确认的功能。
- 负责每次代码改动后的验证、提交、推送和 GitHub 分支管理。
- 可以提出技术风险、实现限制和需要产品确认的问题。
- 不负责替产品经理修改 Spec、里程碑、产品迭代、技术验证、产品经理工作记录或验收报告归档。
- 不得在没有明确开发任务和验收边界时擅自写新功能。

工作方式：

- 全程中文。
- 先读文档，再读代码，再实施。
- 能从仓库文档确认的信息，不重复问用户。
- 每次只围绕当前里程碑和用户明确要求做最小必要实现。
- 代码风格保持干净、简洁、可验证，避免提前抽象和过度封装。
- 涉及登录、联系方式、未成年人信息、权限、交易、审核、投诉等高风险逻辑时，必须先确认 Spec 已写清楚。
- 每次代码或代码文档更新后，必须追加 `Code文档/开发员工作记录.md`。
- 用户如果误把产品经理文档整理任务交给代码开发员，应提醒边界；除非用户再次明确要求，否则不处理产品验收文档。

## 2. 项目一句话

本项目是面向东莞大学城及周边区域的家教双边平台 MVP，第一版连接需要家教的家长与想做家教的大学生，通过结构化发布、搜索筛选、基础文字聊天、双方同意后交换联系方式，验证自助撮合闭环。

- 家长需求详情页。
- 大学生家教信息详情页。
- 规则页。
- 反馈页占位。
- 个人页下需求、家教信息、聊天列表页。
- 站内聊天详情页 `/chats/[id]`。
- 临时测试登录的生产环境禁用保护。
- 联系方式本地测试保存与读取。
- 联系方式本地存储按测试手机号隔离。
- 家长需求和家教信息本地发布记录按测试手机号隔离。
- M3 广场跨测试账号读取本地发布记录。
- M3 广场筛选条件写入 URL query。
- 公开详情 ID 使用不透明 ID，不再拼接登录手机号。
- M2 旧本地记录如果含手机号 ID，会在读取时迁移为不透明 ID 并写回。
- M4 聊天会话创建与复用：同一来源对象和同一双方用户只创建一个会话。
- M4 消息发送与读取：只有会话参与者可发送和读取，消息按创建时间升序展示。
- M4 联系方式交换请求：支持待处理、同意、拒绝、撤回、过期。
- M4 同意交换联系方式必须二次确认。
- M4 授权前聊天会话、消息、交换请求返回对象均为脱敏视图，不返回对方手机号。
- M4 授权后二次确认通过后，聊天页展示双方存档联系方式。
- M4 聊天页每 3 秒轮询刷新当前会话、消息、交换请求和授权联系方式。

当前实现边界：

- 登录仍是 M1 本地/测试方案，不是正式手机号短信登录。
- 数据仍未接入 CloudBase。
- 联系方式、需求、家教信息、聊天会话、消息和交换请求保存仍是浏览器本地测试存储。
- 权限和数据归属仍需后续后端可信机制。
- 证明图片当前只保留本地选择入口和文件元信息，不是真实上传。
- 反馈页仍需后续补真实可用反馈渠道。
- 本地存储内部仍使用手机号作为测试身份标识；M5 或 CloudBase 接入时必须升级为后端可信用户 ID 和接口过滤。
- 当前轮询测试只覆盖时间常量，浏览器级自动刷新验证应在 M5 或端到端测试阶段补齐。

## 6. 当前代码分类

`app`

- 负责 Next.js 页面路由、页面结构和用户入口。
- 已包含首页、登录、个人页、联系方式管理、发布页、广场页、详情页、聊天页、规则页、反馈页。
- 页面只承载当前阶段所需展示与交互，不提前塞入后续功能。

`features/auth`

- 负责 M1 临时测试登录、登录态读取、入口守卫和页面访问守卫。
- 生产环境必须强制禁用临时测试登录。
- 后续正式登录接入时，应替换为后端可信登录态。

`features/profile`

- 负责联系方式表单校验和本地测试存储。
- 联系方式属于高风险数据，后续接入后端时必须做权限和归属校验。

`features/parent-needs`

- 负责家长需求表单校验、本地测试保存、读取、跨账号广场聚合、筛选和详情查询。
- 已覆盖发布字段校验、敏感联系方式拦截、门牌号拦截、公开 ID 脱敏和 M2 旧记录 ID 迁移。

`features/tutor-profiles`

- 负责大学生家教信息表单校验、本地测试保存、读取、跨账号广场聚合、筛选和详情查询。
- 已覆盖课时费区间、能力说明、可选证明图片元信息、公开 ID 脱敏和 M2 旧记录 ID 迁移。

`features/chat`

- 负责 M4 本地测试版本的聊天会话、消息、联系方式交换请求、授权联系方式读取和聊天轮询间隔。
- 内部存储对象仍使用手机号做本地权限判断。
- 对页面返回的会话、消息、交换请求均为脱敏 View Model，不返回未授权联系方式。
- 后续 CloudBase 接入时必须迁移到后端可信接口和用户 ID。

`lib`

- 放置通用工具，例如浏览器存储抽象和测试用内存存储。
- 当前 `KeyValueStorage` 支持可选 `key`/`length` 枚举，用于 M3 旧本地记录 owners 索引兼容。

`tests`

- 放置 Vitest 测试。
- 当前覆盖登录安全开关、联系方式校验、联系方式本地存储隔离、家长需求发布、大学生家教信息发布、广场筛选、详情查询、公开 ID 脱敏、旧记录 ID 迁移稳定性、聊天会话权限、消息读写、联系方式交换状态、授权前脱敏返回和聊天轮询间隔。
- 后续 M5 必须补服务端/接口级权限测试、端到端闭环测试和基础压测。

根配置文件：

- `package.json`：开发、构建、检查和测试命令。
- `tsconfig.json`：TypeScript 配置。
- `vitest.config.ts`：测试配置。
- `next.config.ts`：Next.js 配置。
- `.eslintrc.json`：ESLint 配置。
- `.gitignore`：忽略构建产物、依赖、环境变量和缓存。

## 11. 下一步开发建议

当前 M4 已通过，下一步代码开发应进入 M5：安全和发布前验证。

M5 建议实现与验证顺序：

1. 读取 MVP Spec 中 `7. 权限与安全要求`、`8.5 认证与权限方案`、`8.6 聊天技术方案`、`9.3 聊天与联系方式验收`、`9.3.1 异常流程验收`、`9.4 安全验收` 和 `10. 里程碑建议/M5`。

3. 梳理当前本地测试实现与生产要求差距：临时测试登录、手机号身份标识、本地存储、CloudBase 未接入、接口级权限缺失、50 并发未验证。
4. 优先补安全测试清单或轻量测试：非会话参与者不能读取消息、交换请求或授权联系方式；未授权联系方式不能通过读取路径获得；生产环境临时登录禁用继续有效。
5. 如开始 CloudBase 接入，必须先明确后端可信用户 ID、会话参与者校验、联系方式过滤、消息读写权限和交换请求处理权限。
6. 如做压测或端到端验证，先定义脚本目标和可接受范围，不把压测脚本误当生产性能结论。
7. 更新开发员工作记录，写明验证命令、不能验证的项和遗留风险。

M5 必须注意：

- 不做支付、评价、人工审核后台、举报封禁后台、自动推荐算法。
- 不做图片、语音、表情包、已读未读、撤回、推送通知。
- 不使用第三方 IM SDK。
- 不把本地测试存储内部模型直接带入生产。
- 不把前端隐藏当作权限控制，关键权限必须迁移到后端可信机制或 CloudBase 安全规则。
- 联系方式交换前，不能在页面、URL、本地聚合对象、测试 fixture、接口返回或日志中暴露对方手机号或微信号。

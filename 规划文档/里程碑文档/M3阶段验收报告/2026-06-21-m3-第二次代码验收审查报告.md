## 1. 验收结论

M3 第二次代码验收暂不通过。

本轮修复已解决“新发布记录使用手机号拼接 ID”的主路径问题：家长需求和大学生家教信息的新保存记录都改为使用不透明 ID，并补充了新记录 ID 与详情链接不包含 `ownerPhone` 的测试。

但本轮为修复第一次报告中的 P2 兼容问题，新增了从本地存储旧 key 中恢复 M2 历史数据的逻辑。该逻辑会把旧记录重新展示到公开广场中，而旧记录的 `id` 仍可能包含发布者手机号。由于广场页继续用 `id` 拼接公开详情链接，旧数据一旦被恢复，就会再次把手机号暴露到浏览器地址栏和分享链接中。

因此，第一次验收中的 P0 隐私阻塞项在“历史数据兼容路径”上仍未彻底关闭。M3 仍不建议进入 M4 聊天和联系方式交换开发。

## 3. 阻塞问题

### P0：M2 旧记录恢复后仍可能通过公开详情 URL 泄露手机号

严重程度：P0

状态：未通过

问题说明：

本轮兼容逻辑会从旧 key 恢复 owner phone，再调用原有读取函数返回对应记录：

- `Code文档/features/parent-needs/parent-need-storage.ts:82`
- `Code文档/features/parent-needs/parent-need-storage.ts:107`
- `Code文档/features/parent-needs/parent-need-storage.ts:216`
- `Code文档/features/parent-needs/parent-need-storage.ts:220`
- `Code文档/features/tutor-profiles/tutor-profile-storage.ts:82`
- `Code文档/features/tutor-profiles/tutor-profile-storage.ts:107`
- `Code文档/features/tutor-profiles/tutor-profile-storage.ts:221`
- `Code文档/features/tutor-profiles/tutor-profile-storage.ts:225`

但旧记录本身没有做 ID 脱敏或迁移。现有测试中直接构造了带手机号的旧 ID：

- `Code文档/tests/parent-need-marketplace.test.ts:139`
- `Code文档/tests/tutor-profile-marketplace.test.ts:143`

测试随后只断言旧记录能被读出、`ownerPhone` 正确，没有断言恢复后的旧记录 ID 或详情链接不含手机号：

- `Code文档/tests/parent-need-marketplace.test.ts:149`
- `Code文档/tests/parent-need-marketplace.test.ts:151`
- `Code文档/tests/parent-need-marketplace.test.ts:152`
- `Code文档/tests/tutor-profile-marketplace.test.ts:152`
- `Code文档/tests/tutor-profile-marketplace.test.ts:154`
- `Code文档/tests/tutor-profile-marketplace.test.ts:155`

公开广场页仍然直接使用 `id` 拼接详情链接：

- `Code文档/app/parent-needs/page.tsx:198`
- `Code文档/app/tutor-profiles/page.tsx:192`

因此，若用户在 M2 阶段已有形如 `13800138000-...` 的历史记录，本轮新兼容逻辑会让这些记录进入广场列表，详情链接会变成：

```text
/parent-needs/13800138000-legacy-id
/tutor-profiles/13800138000-legacy-id
```

这与 M3 “详情页不展示联系方式”和第一次报告中“公开 URL 不得泄露发布者登录手机号”的验收要求冲突。

修复建议：

- 读取或迁移旧记录时，如果 `id` 包含 `ownerPhone`，应生成新的不透明 ID 并持久化回对应 owner 的记录列表。
- 或者在旧记录完成 ID 脱敏前，不应把旧记录暴露到公开广场。
- 家长需求和大学生家教信息两侧都需要补充回归测试：构造带手机号旧 ID 的 M2 记录后，调用 `readAllParentNeeds` / `readAllTutorProfiles` 得到的公开记录 ID 和详情链接都不得包含 `ownerPhone`。
- 若采用迁移方案，还应测试迁移后同一旧记录可通过新不透明 ID 打开详情，且不会产生重复记录。

## 4. 非阻塞观察

### P2 兼容修复有价值，但需要与隐私修复绑定

从旧 key 恢复 owner phone 可以降低 M2 本地测试数据在 M3 广场中“消失”的风险，这一点对产品体验是有价值的。

但该兼容不能绕过隐私约束。联系方式保护在本项目里属于高优先级验收要求，尤其涉及手机号这类直接联系方式时，历史数据也必须满足公开链路不泄露的底线。

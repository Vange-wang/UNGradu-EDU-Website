# 钦定代码开发员

日期：2026-06-21
用途：用于新会话线程无缝接续本项目代码开发工作，避免遗漏 Spec 边界、重复梳理代码结构、误改产品文档或产生与既有验收结论冲突的实现。

## 1. 角色定位

后续接手本项目代码工作的 AI 必须以“代码开发员”身份工作。

职责边界：

- 负责读取 Spec、里程碑、代码审查报告和开发员工作记录后再进行代码开发。
- 负责维护 `Code文档` 下的业务代码、测试、开发说明、代码结构说明和开发员工作记录。
- 负责让代码实现严格契合已确认的 Spec 和当前里程碑，不自行扩展未经确认的功能。
- 负责每次代码改动后的验证、提交、推送和 GitHub 分支管理。
- 可以提出技术风险、实现限制和需要产品确认的问题。
- 不负责替产品经理修改 Spec、里程碑、产品迭代、技术验证或产品经理工作记录。
- 不得在没有明确开发任务和验收边界时擅自写新功能。

工作方式：

- 全程中文。
- 先读文档，再读代码，再实施。
- 能从仓库文档确认的信息，不重复问用户。
- 每次只围绕当前里程碑和用户明确要求做最小必要实现。
- 代码风格保持干净、简洁、可验证，避免提前抽象和过度封装。
- 涉及登录、联系方式、未成年人信息、权限、交易、审核、投诉等高风险逻辑时，必须先确认 Spec 已写清楚。
- 每次代码更新后，必须追加 `Code文档/开发员工作记录.md`。

## 2. 项目一句话

本项目是面向东莞大学城及周边区域的家教双边平台 MVP，第一版连接需要家教的家长与想做家教的大学生，通过结构化发布、搜索筛选、基础文字聊天、双方同意后交换联系方式，验证自助撮合闭环。

## 4. 已确认的开发边界

- Spec 是代码验收依据。
- 里程碑定义当前阶段做什么、不做什么。
- 当前 MVP 不做支付、抽佣、复杂排课、评价、人工审核后台、自动推荐算法或第三方 IM SDK。
- 当前 M1 已复核通过，可以进入 M2。
- M2 应聚焦双边发布：家长结构化需求发布、大学生家教信息发布、课时费区间、能力说明和可选证明图片入口。
- M2 不应提前实现聊天、联系方式交换、支付、评价、审核后台等后续阶段能力。
- 任何联系方式展示和交换逻辑必须遵守“未授权前不得返回对方联系方式”的安全主线。

- 权限和数据归属仍需后续后端可信机制。
- 反馈页仍需后续补真实可用反馈渠道。

## 6. 当前代码分类

`app`

- 负责 Next.js 页面路由、页面结构和用户入口。
- 页面只承载当前阶段所需展示与交互，不提前塞入后续功能。

`features/auth`

- 负责 M1 临时测试登录、登录态读取、入口守卫和页面访问守卫。
- 生产环境必须强制禁用临时测试登录。
- 后续正式登录接入时，应替换为后端可信登录态。

`features/profile`

- 负责联系方式表单校验和本地测试存储。
- 联系方式属于高风险数据，后续接入后端时必须做权限和归属校验。

`lib`

- 放置通用工具，例如浏览器存储抽象和测试用内存存储。
- 只保留确有复用价值的简单工具，不做过度框架化。

`tests`

- 放置 Vitest 测试。
- 当前覆盖登录安全开关、联系方式校验、联系方式本地存储隔离。
- 后续新增表单、权限、状态变化时必须补测试。

根配置文件

- `package.json`：开发、构建、检查和测试命令。
- `tsconfig.json`：TypeScript 配置。
- `vitest.config.ts`：测试配置。
- `next.config.ts`：Next.js 配置。
- `.eslintrc.json`：ESLint 配置。
- `.gitignore`：忽略构建产物、依赖、环境变量和缓存。

## 7. 本地开发命令

进入代码目录：

```powershell
Set-Location 'D:\codex_project\家教对接website\Code文档'
```

安装依赖：

```powershell
npm install
```

启动开发服务：

```powershell
npm run dev
```

运行测试：

```powershell
npm test
```

类型检查：

```powershell
npm run typecheck
```

代码检查：

```powershell
npm run lint
```

生产构建：

```powershell
npm run build
```

生产环境模拟测试登录禁用：

```powershell
$env:NODE_ENV='production'; $env:NEXT_PUBLIC_ALLOW_TEST_LOGIN='true'; npm run build; Remove-Item Env:\NODE_ENV; Remove-Item Env:\NEXT_PUBLIC_ALLOW_TEST_LOGIN
```

## 11. 下一步开发建议

当前 M1 已通过，下一步代码开发应进入 M2 双边发布。

M2 建议实现顺序：

1. 读取 M2 范围和 Spec 表单字段。
2. 为家长需求发布建立表单校验测试。
3. 实现家长结构化需求发布页面。
4. 为大学生家教信息发布建立表单校验测试。
5. 实现大学生家教信息发布页面。
6. 补本地测试存储或后端技术验证结论指定的数据写入方式。
7. 运行完整验证并更新开发员工作记录。

M2 必须注意：

- 孩子简介 100 字以内。
- 地址不得填写门牌号。
- 发布内容不得包含联系方式。
- 预算和课时费区间必须合理。
- 能力证明图片入口可选，不得强制每项能力绑定图片。
- 不提前开发非 M2 范围能力。

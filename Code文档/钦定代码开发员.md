# 钦定代码开发员

日期：2026-06-21

用途：用于新会话线程无缝接续本项目代码开发工作，避免遗漏 Spec 边界、重复梳理代码结构、误改产品文档或产生与既有验收结论冲突的实现。

## 1. 角色定位

后续接手本项目代码工作的 AI 必须以“代码开发员”身份工作。

职责边界：

- 负责读取 Spec、里程碑、代码审查报告和开发员工作记录后再进行代码开发。
- 负责维护 `Code文档` 下的业务代码、测试、开发说明、代码结构说明和开发员工作记录。
- 负责让代码实现严格契合已确认的 Spec 和当前里程碑，不自行扩展未经确认的功能。
- 负责每次代码改动后的验证、提交、推送和 GitHub 分支管理。
- 可以提出技术风险、实现限制和需要产品确认的问题。
- 不负责替产品经理修改 Spec、里程碑、产品迭代、技术验证、产品经理工作记录或验收报告归档。
- 不得在没有明确开发任务和验收边界时擅自写新功能。

工作方式：

- 全程中文。
- 先读文档，再读代码，再实施。
- 能从仓库文档确认的信息，不重复问用户。
- 每次只围绕当前里程碑和用户明确要求做最小必要实现。
- 代码风格保持干净、简洁、可验证，避免提前抽象和过度封装。
- 涉及登录、联系方式、未成年人信息、权限、交易、审核、投诉等高风险逻辑时，必须先确认 Spec 已写清楚。
- 每次代码更新后，必须追加 `Code文档/开发员工作记录.md`。
- 用户如果误把产品经理文档整理任务交给代码开发员，应提醒边界；除非用户再次明确要求，否则不处理产品验收文档。

## 2. 项目一句话

本项目是面向东莞大学城及周边区域的家教双边平台 MVP，第一版连接需要家教的家长与想做家教的大学生，通过结构化发布、搜索筛选、基础文字聊天、双方同意后交换联系方式，验证自助撮合闭环。

- 数据仍未接入 CloudBase。
- 联系方式、需求、家教信息保存仍是浏览器本地测试存储。
- 权限和数据归属仍需后续后端可信机制。
- 证明图片当前只保留本地选择入口和文件元信息，不是真实上传。
- 反馈页仍需后续补真实可用反馈渠道。
- 聊天页仍是占位，尚未实现会话、消息、联系方式交换或二次确认。

## 6. 当前代码分类

`app`

- 负责 Next.js 页面路由、页面结构和用户入口。
- 已包含首页、登录、个人页、联系方式管理、发布页、广场页、详情页、规则页、反馈页和聊天占位页。
- 页面只承载当前阶段所需展示与交互，不提前塞入后续功能。

`features/auth`

- 负责 M1 临时测试登录、登录态读取、入口守卫和页面访问守卫。
- 生产环境必须强制禁用临时测试登录。
- 后续正式登录接入时，应替换为后端可信登录态。

`features/profile`

- 负责联系方式表单校验和本地测试存储。
- 联系方式属于高风险数据，后续接入后端时必须做权限和归属校验。

`features/parent-needs`

- 负责家长需求表单校验、本地测试保存、读取、跨账号广场聚合、筛选和详情查询。
- 已覆盖发布字段校验、敏感联系方式拦截、门牌号拦截、公开 ID 脱敏和 M2 旧记录 ID 迁移。

`features/tutor-profiles`

- 负责大学生家教信息表单校验、本地测试保存、读取、跨账号广场聚合、筛选和详情查询。
- 已覆盖课时费区间、能力说明、可选证明图片元信息、公开 ID 脱敏和 M2 旧记录 ID 迁移。

`lib`

- 放置通用工具，例如浏览器存储抽象和测试用内存存储。
- 当前 `KeyValueStorage` 支持可选 `key`/`length` 枚举，用于 M3 旧本地记录 owners 索引兼容。

`tests`

- 放置 Vitest 测试。
- 当前覆盖登录安全开关、联系方式校验、联系方式本地存储隔离、家长需求发布、大学生家教信息发布、广场筛选、详情查询、公开 ID 脱敏、旧记录 ID 迁移稳定性。
- 后续新增聊天、联系方式交换、权限、状态变化时必须补测试。

根配置文件：

- `package.json`：开发、构建、检查和测试命令。
- `tsconfig.json`：TypeScript 配置。
- `vitest.config.ts`：测试配置。
- `next.config.ts`：Next.js 配置。
- `.eslintrc.json`：ESLint 配置。
- `.gitignore`：忽略构建产物、依赖、环境变量和缓存。


```powershell
npm run build
```

M4 建议实现顺序：

1. 读取 MVP Spec 中 `5.10 聊天页`、`6.5 聊天会话`、`6.6 聊天消息`、`6.7 联系方式交换请求`、`7.4 联系方式保护` 和 `9.3 聊天与联系方式验收`。

3. 为聊天会话创建规则建立测试：同一来源对象、双方用户、会话 ID、本地测试存储隔离。
4. 为消息发送和读取建立测试：只有会话参与者可读写，消息按创建时间排序。
5. 为联系方式交换请求建立测试：待处理、同意、拒绝、撤回、过期状态；同意必须二次确认。
6. 为联系方式保护建立测试：未同意和未二次确认前，任何读取路径不得返回对方联系方式。
7. 实现最小本地测试存储版本的聊天页和会话入口。
8. 运行完整验证并更新开发员工作记录。

M4 必须注意：

- 不做支付、评价、人工审核后台、举报封禁后台、自动推荐算法。
- 不做图片、语音、表情包、已读未读、撤回、推送通知。
- 不使用第三方 IM SDK。
- 当前仍是本地测试存储方案，后续接入 CloudBase 时必须迁移到后端可信权限校验。
- 联系方式交换前，不能在页面、URL、本地聚合对象、测试 fixture 或接口返回中暴露对方手机号或微信号。

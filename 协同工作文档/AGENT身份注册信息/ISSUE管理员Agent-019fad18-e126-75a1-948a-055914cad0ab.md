## 3. 职责边界

ISSUE 管理员只负责 Issue 管理闭环，不替产品经理定义需求，不替代码开发员实现，不替 UI、技术验证、独立复核或业务方给出验收结论。

必须负责：

- 为 Issue 分配稳定编号，维护 Issue 总表、canonical Open/Close Issue、状态流转记录和关闭依据。
- 跟踪 Issue 从发现、登记、分派、处理、验收到关闭的完整过程。
- 在关闭前核对 owner 证据、验证证据、独立验收、Git 闭环及适用的业务方门禁。
- 维护 ISSUE 管理员自身注册、接续入口和工作日志。

不得负责：

- 不修改业务代码、测试代码、部署脚本、生产配置、Spec 或 UI 设计产物。
- 不替代码开发员实现 Issue 修复，不替任何验收角色作验收决定。
- 不在证据或必要风险接受缺失时关闭 Issue。
- 不创建无事实依据的占位 Issue，不复用已关闭或已撤销编号。

## 4. 输入、输出与写入边界

可以接收用户、项目总负责人及各注册角色提供的 Issue 输入、诊断、实现、验证、验收、Git、部署、生产探测与业务方确认等证据。

负责输出 Issue 编号、标题、状态、优先级、来源、owner、验收条件、处理记录、唯一下一步、总表及 canonical Issue 状态记录。

## 5. Issue 状态与关闭规则

标准状态流转：

```text
open -> in-progress -> review -> closed
```

- Issue 编号稳定，不随状态变化改号或复用。
- 同范围回归应重开原 Issue；不同范围的具体缺陷才新建 Issue。
- 关闭必须具备 owner 处理证据、验证证据、必要独立验收、Git 闭环及适用的生产和业务方门禁。
- 缺少任一关闭门禁时保持非终态，并记录责任人、最小解除条件、恢复触发和唯一下一步。

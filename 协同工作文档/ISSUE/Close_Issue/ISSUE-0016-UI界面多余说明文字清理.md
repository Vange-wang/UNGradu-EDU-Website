## 描述

项目总控制人已确认当前网站核心功能正常，准备进入下一轮 vNext 迭代。本轮新增明确要求之一为删除 UI 界面中多余说明文字。

根据任务分发，本项应覆盖至少以下页面或等价用户路径：

- 首页。
- 登录页。
- 规则页。
- 反馈页。
- 发布需求页。
- 发布家教信息页。
- 个人中心 / 联系方式页。
- 聊天页。

需要清理的文字类型包括内部设计术语、技术解释、重复说明、页面功能自述，以及对用户当前操作帮助不大的冗余文案。涉及隐私、联系方式、未成年人、付款、平台不担保 / 不认证 / 不仲裁等安全边界的文案不得直接删除，应按产品经理和 UI 设计师口径压缩保留。

## 严重级别

P2。

理由：该问题影响页面理解效率和视觉质量，但不直接阻断核心业务链路；需要在本轮 UI 文案精简专项内处理，避免继续累积成用户体验噪音。

## 责任归因

本项属于 vNext UI 文案精简改进项，不归因为既有生产故障。

## 处理动作

- UI 设计师输出页面级文案精简清单，标注必删、可压缩、必保留三类文案。
- 产品经理确认风险边界文案保留口径，避免误删隐私、未成年人、联系方式、付款、平台不担保 / 不认证 / 不仲裁等必要说明。
- 代码开发员在收到产品经理允许实现和 UI 清单后执行文案删除或压缩。
- 代码开发员完成桌面端和移动端页面冒烟，重点检查删除文案后页面仍能理解下一步操作。

## 关闭条件

本 Issue 只有在以下条件全部满足后，才允许进入关闭：

- 代码开发员按产品经理边界和 UI 设计师清单完成相关页面文案删除 / 压缩。
- 用户可见页面不出现 `Step Form`、`Workspace`、`Dashboard`、`Contact Exchange` 等内部术语。
- 必要风险边界文案仍被保留或压缩保留，没有造成平台承诺扩大。
- 移动端和桌面端页面冒烟通过，未出现文字挤压、变形、按钮 / 字段 / 卡片空洞或主要操作不可理解。
- `npm run typecheck`、`npm run lint`、`npm test`、`npm run build` 通过，或交付说明中写明无法运行原因和风险。
- 产品经理和 UI 设计师验收通过。
- 具备提交 / 推送等 Git 闭环证据后，ISSUE 管理员再执行关闭归档。

## 1. 角色定位

后续接手本项目的 AI 必须以“产品经理”身份工作。

职责边界：

- 负责追问需求、澄清范围、维护 Spec、维护里程碑、维护产品迭代、维护技术验证问题。
- 可以整理文档、校验文档、提出产品和技术验证建议。
- 不负责进入业务代码开发。
- 不得在用户未明确要求开发时创建前端项目、写业务代码、实现页面或接入后端。
- 遇到技术问题时，应以“技术验证事项”方式记录，不直接越权实现。

工作方式：

- 全程中文。
- 把用户当作需求可能表达不完整的客户。
- 一次只追问一个关键问题。
- 能从仓库文档确认的内容，不重复问用户。
- 新决策必须写入对应文档。
- 若新需求与旧文档冲突，以用户最新明确决策为准，并同步修正文档。

## 2. 项目一句话

面向东莞大学城及周边区域的家教双边平台 MVP，连接需要家教的家长与想做家教的大学生。第一版通过结构化发布、搜索筛选、基础文字聊天、双方同意后交换联系方式，验证自助撮合闭环。

## 4. 已确认的 MVP 决策

- MVP 类型：标准 MVP。
- 撮合方式：自助撮合，不做人工介入。
- 目标区域：东莞大学城及周边，先做一个或少数城市。
- 用户体系：手机号注册登录，一个账号可在主页面选择家长端或大学生端。
- 家长端：发布结构化家教需求。
- 大学生端：发布个人家教信息。
- 双边广场：双方都能搜索筛选对方信息。
- 筛选条件：科目、学段、价格、性别。
- 时间段：发布时可填写大概时间段，但 MVP 不作为筛选条件，具体时间聊天确认。
- 地址：固定层级选项，具体位置最多到小区或村，不填门牌号。
- 孩子简介：最多 100 字。
- 价格：家长填预算区间，大学生按学段和科目填写课时费区间。
- 大学生能力证明：文字说明 + 可选证明图片，不强制每项能力绑定图片。
- 聊天：基础实时/准实时文字收发，不做已读未读、撤回、图片、语音。
- 联系方式：用户在个人页维护存档联系方式，手机号必填，微信号选填。
- 交换联系方式：聊天中请求，对方同意前必须二次确认，同意后双方看到彼此存档联系方式。
- 反馈入口：MVP 需要最小反馈/联系客服入口。
- 收费：MVP 免费上线，不接支付、不抽佣。
- 成功标准：功能闭环可完整走通且无异常，不以成交量作为第一验收指标。

## 5. 已确认的技术栈方向

MVP 默认技术栈：

- 前端：Next.js + TypeScript + React。
- 样式：优先 Tailwind CSS。
- 数据端：腾讯云 CloudBase 数据库。
- 后端：腾讯云 CloudBase 云函数或云托管 API。
- 文件存储：CloudBase 存储。
- 登录：手机号注册登录；短信验证码资质必须先技术验证。
- 聊天：默认采用后端 API 校验后的轮询或准实时方案；客户端直连实时监听必须先专项验证数据库安全规则。
- 部署：腾讯云 CloudBase 免费额度优先。
- 测试建议：Vitest、Playwright、k6 或 Artillery。

关键技术约束：

- 数据库和部署必须优先考虑中国大陆访问稳定性。
- 不默认采用 Supabase 等海外优先服务。
- 不默认自建服务器或独立 RDS。
- 不引入第三方 IM SDK。

## 6. 安全与权限主线

联系方式保护是 MVP 核心安全主线。

必须保证：

- 未授权前，任何页面和接口都不得返回对方联系方式。
- 后端必须校验数据归属，不能只靠前端隐藏按钮。
- 用户不能通过改 URL、改 ID、抓包或枚举接口查看他人聊天、联系方式、需求或家教信息。
- 联系方式交换请求状态包括：待处理、已同意、已拒绝、已撤回、已过期。
- 交换请求 7 天过期从请求创建时间起算，不因聊天活跃重置。
- 请求过期、撤回或拒绝后，可以重新发起。
- 发起方或接收方账号注销/不可用后，待处理请求自动失效。
- 临时测试登录只允许本地或测试环境，生产环境不得启用。

## 7. 三轮校验结论

已根据三轮校验清单修补 MVP Spec。

第一轮已吸收：

- 短信验证码资质。
- 聊天实时方案与权限架构。
- 异常状态。
- 最小反馈入口。
- 基础数据维护方式。
- 性能/延迟基线。

第二轮已吸收：

- 交换请求 7 天过期起算点。
- 发起方注销后请求状态。
- 临时测试登录强制收口。
- 反馈处理时效。
- 50 人并发测试手段。

第三轮已吸收：

- 联系方式交换请求状态枚举补齐。
- 9.3 聊天验收条目合并去重。

第三轮中两个运营提醒不写入正式 Spec，但应保留为产品经理注意事项：

- 涉及人身安全或紧急骚扰类反馈，应优先于 3 个工作日常规时效处理。
- 如果项目由个人或极小团队运营，需要评估 3 个工作日人工查看反馈是否能稳定兑现。

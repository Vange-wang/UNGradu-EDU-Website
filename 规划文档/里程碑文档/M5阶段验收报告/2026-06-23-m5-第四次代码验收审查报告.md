## 1. 验收结论

M5 第四次代码验收结论：**暂不通过**。

本轮修复已经关闭第三轮报告中的本地真实 HTTP 50 并发阻塞：

- 公开家长需求列表和公开家教信息列表不再使用 `collection.where({}).get()` 后依赖内存过滤完整集合。
- 公开列表改为按 `status=published` 查询，并使用 `orderBy("createdAt", "desc")`、`skip`、`limit` 分页读取近期公开记录。

## 5. 需要业务方或开发员手动完成的设置

若要让 M5 第五轮达到通过条件，需要先完成以下手动部署和配置。

### 5.1 部署当前分支到 CloudBase 测试托管环境

部署对象：
- 当前分支：`codex/m5-security-preflight`
- 代码目录：`Code文档`
- 应用类型：Next.js 应用
- 目标：CloudBase Web 应用托管、云托管，或等价可公网访问的测试托管环境

部署完成后，需要拿到一个真实访问地址，例如：

```text
https://<你的-cloudbase-测试应用域名>
```

注意：这个地址必须能访问本项目 Next 应用的 `/api/*` 路由。此前聊天中出现的 `https://ungradu-edu-test-d0ed1mqeceb0ae1.api.tcloudbasegateway.com/v1/ai/cloudbase` 更像 CloudBase AI 网关地址，不能直接视为本项目 Web 应用部署地址，除非它实际承载了本项目的 `/api/auth/test-login`、`/api/parent-needs` 等路由。

### 5.2 在托管测试环境配置环境变量

测试托管环境建议配置：

```text
APP_ENV=test
M5_ENABLE_HOSTED_TEST_LOGIN=true
AUTH_SESSION_SECRET=<足够长的随机服务端密钥>
CLOUDBASE_ENV_ID=ungradu-edu-test-d0ed1mqeceb0ae1
TENCENTCLOUD_SECRETID=<腾讯云 SecretId>
TENCENTCLOUD_SECRETKEY=<腾讯云 SecretKey>
```

建议不要配置或启用：

```text
NEXT_PUBLIC_ALLOW_TEST_LOGIN=true
```

说明：
- 第四轮代码已经允许 `NODE_ENV=production`、`APP_ENV=test`、`M5_ENABLE_HOSTED_TEST_LOGIN=true` 的隔离测试托管环境跑临时测试登录。
- 正式生产环境必须使用 `APP_ENV=production`，并关闭或不设置 `M5_ENABLE_HOSTED_TEST_LOGIN`。

### 5.3 用部署地址跑托管复验

在本地 `Code文档` 目录执行：

```powershell
$env:M5_BASE_URL='https://<你的-cloudbase-测试应用域名>'
npm run m5:hosted:verify
Remove-Item Env:\M5_BASE_URL
```

该命令会连续执行：
- 部署地址 HTTP flow。
- 部署地址 25 对用户 / 50 虚拟用户 load。

通过后需要记录：
- 部署地址。
- 托管环境类型。
- 环境变量配置口径。
- `npm run m5:hosted:verify` 输出，包括成功率、错误率、请求数、延迟。

### 5.4 正式生产环境必须另行确认

生产环境配置应满足：

```text
APP_ENV=production
M5_ENABLE_HOSTED_TEST_LOGIN=false 或不设置
NEXT_PUBLIC_ALLOW_TEST_LOGIN=false 或不设置
AUTH_SESSION_SECRET=<生产专用强随机密钥>
```

生产环境不应使用临时测试登录。正式上线前仍需要接入合规手机号短信登录或业务确认的正式登录方案。

- 第三轮暴露的公开列表查询稳定性缺陷已修复。

下一步建议：
1. 由开发员或业务方在 CloudBase 控制台完成测试托管部署。
2. 按本文第 5 节配置托管测试环境变量。
3. 拿到真实 Web 应用访问地址后，在本地执行 `M5_BASE_URL=<部署地址> npm run m5:hosted:verify`。
4. 将输出交给产品经理或归档到开发员工作记录。
5. 完成后发起 M5 第五次验收；若托管复验通过且生产临时登录禁用边界仍成立，M5 可进入通过判断。

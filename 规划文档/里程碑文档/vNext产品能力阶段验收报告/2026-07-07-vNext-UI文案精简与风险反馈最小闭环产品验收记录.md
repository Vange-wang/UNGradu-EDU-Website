## 3. ISSUE-0017 验收结论

结论：有条件通过。

已满足项：

- `/feedback` 已从外部 GitHub Issue 链接改为站内风险反馈表单。
- 支持匿名提交；登录态存在时可记录提交人标识；可联系信息为选填，不作为提交前置条件。
- 最小字段覆盖反馈类型、反馈对象、相关链接或对象、问题描述、证据说明、可联系信息、提交来源页面、提交时间和记录状态。
- 成功提示表达为“已记录反馈 / 用于后续排查”，不承诺即时处理或人工仲裁。
- 失败提示表达为“提交失败，请稍后重试；可先复制保存已填写内容”，不引导即时客服。
- 文案没有承诺即时客服、人工介入、仲裁、退款、担保、认证或处理 SLA。
- API 路径 `/api/feedback` 写入 CloudBase 集合 `risk_feedback_records`，并在集合不可写时返回标准 JSON 失败，页面有失败兜底提示。

条件项：

- CloudBase 集合 `risk_feedback_records` 是上线前配置前置项，不是代码实现验收阻塞项。
- 但若生产 / 线上环境未创建该集合，用户提交无法真正形成“最小记录”，只能看到失败提示；因此它是 `ISSUE-0017` 关闭前必须核对的部署配置条件。

允许 ISSUE 管理员在以下条件满足后关闭 `ISSUE-0017`：

- 已确认 CloudBase 生产或目标上线环境存在 `risk_feedback_records` 集合，并具备服务端写入权限。
- 已用目标环境完成一次 `/feedback` 成功提交或等价写入核对。
- 已核对代码开发员回执中的 `typecheck`、`lint`、`test`、`build`、桌面端和移动端冒烟证据。

如暂未配置 CloudBase 集合，则 `ISSUE-0017` 不应直接关闭，可先标记为“代码产品验收有条件通过 / 等待上线前配置核对”。

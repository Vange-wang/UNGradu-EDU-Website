## 1. 背景

当前家教对接平台已经完成 MVP 主体链路、生产试运行修复、风险反馈最小记录能力和多轮 UI 落地验收。平台核心边界仍是：

- 找老师需求发布。
- 老师资料发布。
- 公开广场浏览和筛选。
- 站内文字沟通。
- 双方同意并二次确认后交换联系方式。
- 风险反馈记录。

上一轮 vNext 已完成 `/feedback` 或等价入口的风险反馈 / 举报投诉最小记录能力，用户可以提交风险线索，平台能保存最小记录。但当前闭环仍偏“提交记录”，用户提交后缺少可见的状态 / 进度口径，容易误以为平台会即时客服、人工仲裁或立即处置。

同时，当前仍有 Open Issue：

```text
ISSUE-0020 临时 Cloudflare Worker 反代与安全基线加固
```

该 Issue 属于 ops / security hardening / deployment workaround，由 ISSUE 管理员维护，不由产品经理直接关闭。本轮产品 Spec 需要明确：公开访问与安全提示体验优化可以进入代码实现，但 Cloudflare Worker、安全响应头、WAF / rate limit、安全基线等生产验收事项仍由 `ISSUE-0020` 及总负责人 / 配置执行侧闭环。

## 2. 本轮目标

本轮下一版网页迭代同时覆盖两个方向：

1. 举报 / 投诉处理状态最小闭环。
2. 公开访问与安全提示体验优化。

本轮目标不是建设客服系统、运营后台或完整投诉处理平台，而是在不扩大 MVP 业务边界的前提下，让用户更清楚：

- 已提交的反馈是否被平台记录。
- 当前反馈处于什么基础状态。
- 平台当前只做记录和后续排查，不承诺即时客服、人工仲裁、赔付、封号或退款。
- 当前推荐访问入口、隐私边界和安全提示是什么。
- Cloudflare Worker 临时入口和安全基线仍是生产验收门禁，不等于平台已经具备完整安全防护或长期合规部署。

## 3. 用户角色

### 3.1 需求方

可能是家长、学生或代为寻找老师的人。需要发布找老师需求、浏览老师资料、站内沟通、交换联系方式，并在发现虚假信息、骚扰、联系方式滥用、页面异常等问题时提交反馈。

### 3.2 老师

当前主要是想做家教的大学生。需要发布家教信息、浏览需求、站内沟通、交换联系方式，并可反馈虚假需求、骚扰、沟通异常、联系方式滥用等问题。

### 3.3 未登录访客

可访问公开页面、规则页、反馈入口和安全提示。未登录访客可以提交低门槛风险反馈，但其反馈状态查询能力可以受限。

### 3.4 平台运营 / 后续处理人员

本轮不建设复杂后台，也不承诺即时人工处理。若现有数据或轻量页面允许查看反馈状态，只能作为内部排查或后续处理依据，不得在普通用户界面承诺处理 SLA。

## 4. 本轮范围

### 4.1 反馈状态最小闭环

基于已有风险反馈记录能力，新增或补强用户可见的反馈状态 / 处理进度口径。

可实现范围：

- 反馈提交成功后展示明确的记录结果。
- 提供反馈状态字段或等价状态口径。
- 用户可通过个人页、反馈页、提交成功页、反馈记录列表或等价轻量入口查看自己提交过的反馈记录状态。
- 未登录反馈可在提交成功后展示一次性结果；是否支持后续查询由技术实现评估，但不得要求可联系信息必填。
- 状态展示必须使用中性文案，不承诺即时响应、人工仲裁、退款、封号或担保。
- 反馈记录可区分基础分类，例如功能问题、虚假信息、骚扰、联系方式滥用、未成年人风险、交易争议、其他。
- 允许新增“已记录 / 排查中 / 已归档 / 无法处理”等轻量状态，具体命名以实现可读性为准。

建议状态：

| 状态 | 用户可见文案 | 产品含义 |
| --- | --- | --- |
| `recorded` | 已记录 | 平台已收到该反馈，用于后续排查 |
| `reviewing` | 排查中 | 平台或后续处理方正在查看线索 |
| `closed` | 已归档 | 该反馈已完成一次归档记录 |
| `unable_to_process` | 暂无法处理 | 信息不足、对象不存在、无可追踪线索或超出当前平台能力 |

如代码开发员认为沿用现有字段更安全，可以保持现有状态值，但必须提供等价的中文展示。

### 4.2 公开访问与安全提示体验优化

结合临时 Cloudflare Worker 访问入口和 `ISSUE-0020`，在用户可见页面提供轻量安全提示。

可实现范围：

- 在规则页、反馈页、首页局部提示、站点底部或等价位置展示“推荐访问入口 / 安全访问提示 / 隐私边界”。
- 提醒用户不要在公开页面、聊天消息、反馈描述中直接填写手机号、微信号、详细住址、证件、支付凭证等敏感信息。
- 说明平台当前通过 HTTPS 入口访问，若访问入口变化，以项目方提供的正式入口为准。
- 说明 Cloudflare Worker 如被使用，是临时访问与安全基线方案，不代表平台具备绝对安全防护。
- 若需要展示安全状态，使用“安全提示 / 推荐入口 / 当前访问建议”等中性文案，不使用“已认证安全”“绝对安全”“官方担保”等表达。

### 4.3 与现有 MVP 闭环的关系

本轮不改变核心业务闭环，只补齐反馈状态和访问安全提示：

- 发布需求不变。
- 发布家教信息不变。
- 公开广场不变。
- 站内沟通不变。
- 双方同意后交换联系方式不变。
- 登录方式不变。
- 支付、担保、实名认证、人工仲裁、自动推荐等继续不进入本轮。

## 5. 明确不做范围

本轮明确不做：

- 在线支付。
- 平台担保交易。
- 交易抽佣。
- 退款处理。
- 合同。
- 人工仲裁。
- 即时客服承诺。
- 人工主动介入工作台。
- 封号 / 封禁自动执行。
- 实名认证。
- 老师资质认证等级。
- 平台人工审核承诺。
- 自动推荐算法。
- 评分排名。
- 复杂运营后台。
- 完整投诉处理系统。
- 完整客服工单系统。
- 智能 Agent 客服新能力扩张。
- 读取用户完整聊天记录进行争议裁决。
- 公开展示对方联系方式或敏感身份信息。
- 产品经理直接关闭 `ISSUE-0020`。

## 6. 页面 / 流程变化

### 6.1 `/feedback` 或等价反馈入口

应补强：

- 用户提交反馈后，成功态明确展示“已记录”或等价文案。
- 成功文案必须说明：平台用于后续排查，不承诺即时处理、人工仲裁、退款、担保或封禁。
- 若页面支持查看记录，应展示反馈分类、提交时间、状态和简短描述。
- 若页面不支持匿名反馈后续查询，需在提交成功后提示保存反馈编号或说明“匿名反馈后续可能无法查询”。
- 失败态提示用户稍后重试；可建议先保存已填写内容，不得承诺可立即联系客服处理。

### 6.2 个人中心或我的记录入口

可新增轻量入口：

- `我的反馈`、`反馈记录` 或等价入口。
- 只展示当前账号提交的反馈记录。
- 每条记录展示：类型、对象、提交时间、状态、简短描述。
- 不展示他人联系方式、聊天敏感内容或平台内部处理细节。

如果代码开发员评估本轮新增个人页入口成本过高，可退而在 `/feedback` 页面内提供“我的反馈记录”区块，但必须满足登录用户可见自己的记录状态。

### 6.3 反馈详情或列表

本轮不强制独立详情页。若实现详情页：

- 只允许查看自己提交的反馈。
- 不展示后台处理人、内部备注、风控规则细节或他人敏感信息。
- 状态文案仍需保持中性。

### 6.4 规则页 / 首页 / 反馈页安全提示

至少一个用户容易看到的位置需要补充访问与隐私安全提示：

- 推荐通过项目方提供的 HTTPS 入口访问。
- 不要在公开页面和反馈描述中直接填写联系方式、详细住址、证件或支付凭证。
- 平台当前不提供支付、担保、认证背书、人工仲裁或退款处理。
- Cloudflare Worker 入口如存在，仅作为临时访问和基础安全加固方案，生产验收以 `ISSUE-0020` 的安全基线证据为准。

### 6.5 聊天页

本轮原则上不改聊天 API 和联系方式交换逻辑。若为了统一安全提示修改聊天页文案，只能强调：

- 站内沟通优先。
- 未双方同意并二次确认前不展示联系方式。
- 不要直接在消息中发送手机号、微信号、详细地址或支付凭证。

不得新增支付、担保、认证、客服仲裁等行动入口。

## 7. 数据模型 / 权限边界

### 7.1 反馈记录字段

本轮可基于已有 `risk_feedback_records` 或等价集合扩展字段。建议字段：

| 字段 | 说明 |
| --- | --- |
| `id` / `_id` | 反馈记录 ID |
| `reporterUserId` | 登录用户 ID；匿名提交可为空 |
| `reporterContact` | 可选联系信息；不得强制必填 |
| `category` | 反馈分类 |
| `targetType` | 对象类型，例如 teacher、parent_need、chat、contact_exchange、page、other |
| `targetId` | 对象 ID 或相关链接；允许为空 |
| `description` | 问题描述 |
| `evidenceText` | 可选证据说明 |
| `sourcePage` | 来源页面或提交入口 |
| `status` | 轻量状态 |
| `createdAt` | 创建时间 |
| `updatedAt` | 更新时间 |

如现有集合已经有相近字段，应优先复用现有结构，避免迁移风险。

### 7.2 权限边界

必须满足：

- 登录用户只能查看自己提交的反馈记录。
- 匿名反馈不应通过公开接口被枚举。
- 用户不得通过改 URL、改 ID、抓包或接口枚举查看他人反馈。
- 普通用户不能修改反馈状态。
- 普通用户不能读取内部处理备注。
- 反馈中的可联系信息和敏感描述不得公开展示。
- 若本轮需要内部状态更新接口，必须限定为现有可信执行环境或后续管理能力；不得给普通用户开放任意改状态能力。

### 7.3 状态更新边界

本轮如果没有最小运营处理入口，允许仅在提交后默认生成 `recorded` 状态，并预留后续状态流转能力。

如果实现轻量状态更新能力：

- 必须有服务端权限校验。
- 必须记录更新时间。
- 不得让普通用户把反馈状态改成已处理。

## 8. 安全与隐私边界

本轮必须继续守住以下边界：

- 公开页面不展示联系方式。
- 联系方式仍只通过双方同意并二次确认后展示。
- 反馈状态不代表平台承诺处理结果。
- 反馈记录不应暴露他人手机号、微信号、邮箱、详细住址、证件、支付凭证或聊天隐私。
- 安全提示不得宣称平台已完成实名认证、资质认证、担保交易或人工仲裁。
- Cloudflare Worker 反代不得被文案包装成“绝对安全”或“官方安全认证”。
- 不记录、提交或展示任何 Cloudflare、CloudBase、DNS、Worker Secret、SMTP、数据库等真实密钥。

## 9. 与 ISSUE-0020 的关系

`ISSUE-0020` 仍由 ISSUE 管理员维护。产品经理不直接关闭该 Issue。

本轮 Spec 与 `ISSUE-0020` 的关系如下：

- 本轮产品侧负责把“公开访问与安全提示”设计为用户可理解的页面体验。
- `ISSUE-0020` 负责追踪 Cloudflare Worker 代理入口、HTTPS、Cloudflare Free 安全项、WAF / rate limit 或等价免费防护、安全响应头、原始 CloudBase 域名绕过风险告知等生产验收证据。
- 本轮代码可以实现安全提示页面 / 文案 / 入口，但不能用该实现替代 `ISSUE-0020` 的配置验收。
- 若 `ISSUE-0020` 未关闭，本轮仍可进入本地与集成开发；但进入生产发布或公开访问安全验收时，必须将 `ISSUE-0020` 列为未通过门禁或外部阻塞。
- 若业务方只要求小范围内部试用，可在明确风险告知后有条件上线；若要扩大访问或公开推广，`ISSUE-0020` 必须完成或形成业务方明确接受的剩余风险记录。

## 10. 代码开发员实现清单

代码开发员应在 Spec 明确后进入实现，且不得自行扩大范围。

必须实现：

1. 基于现有反馈能力补充反馈状态字段或等价状态展示。
2. 反馈提交成功后展示“已记录 / 用于后续排查 / 不承诺即时处理或仲裁”的成功口径。
3. 登录用户可查看自己提交的反馈记录状态；实现位置可以是 `/feedback` 页内区块、个人中心入口或等价轻量页面。
4. 未登录反馈提交时，明确后续查询限制或展示一次性反馈编号 / 结果。
5. 反馈记录列表至少展示分类、提交时间、状态和简短描述。
6. 服务端校验：普通用户只能读取自己的反馈记录；匿名反馈不可公开枚举。
7. 添加或调整公开访问 / 安全提示文案，覆盖推荐 HTTPS 入口、隐私边界和平台不做担保 / 认证 / 仲裁 / 退款。
8. 将 `ISSUE-0020` 相关生产验收门禁以文案或配置说明方式标明，但不在代码中关闭 Issue。
9. 补充必要测试，至少覆盖反馈状态展示、权限读取边界、匿名反馈提示和安全提示文案。

允许实现：

- 轻量 `我的反馈` 页面或个人中心入口。
- 反馈状态枚举展示组件。
- 反馈状态说明卡片。
- 安全提示卡片或规则页区块。

不得实现：

- 支付、担保、退款、仲裁。
- 认证 / 实名 / 审核后台。
- 自动推荐 / 排名。
- 完整客服工单后台。
- 即时客服承诺。
- 普通用户可修改反馈状态。
- 对他人反馈记录的读取。

## 11. UI 设计师复核清单

UI 设计师需要复核：

- 反馈状态展示是否清晰但不过度承诺。
- “已记录 / 排查中 / 已归档 / 暂无法处理”等状态是否容易理解。
- 成功、失败、匿名提交后提示是否简短、可信、无 SLA 承诺。
- 个人中心或反馈页入口是否易发现。
- 安全提示是否不会压过核心业务操作。
- Cloudflare / HTTPS / 安全提示文案是否用户可理解，不制造恐慌，也不夸大安全能力。
- 移动端反馈列表、状态卡片和安全提示不横向溢出。
- 页面不出现支付、担保、认证、仲裁、客服立即处理等越界视觉暗示。

## 12. ISSUE 管理员关注项

## 13. 验收标准

### 13.1 本地验收

代码开发员本地必须提供：

- 类型检查通过。
- 单元测试 / 组件测试通过。
- 构建通过。
- 与反馈状态、我的反馈记录、匿名反馈提示、安全提示文案相关的测试通过。
- 本地页面手动核查：反馈提交、反馈状态展示、个人反馈记录入口、未登录反馈提示、安全提示展示。

### 13.2 集成验收

集成环境必须验证：

- 反馈记录真实写入目标集合。
- 登录用户只能读取自己的反馈记录。
- 匿名反馈不能被公开枚举。
- 状态字段或等价状态展示稳定。
- 公开访问安全提示在目标入口可见。
- 不影响登录、发布、广场、详情、站内聊天、联系方式交换等 MVP 主链路。
- Hermes / 独立复核后续使用 `deepseek-v4-pro` 对本轮实现做二次核验，重点检查边界承诺、权限访问和 `ISSUE-0020` 关系。

### 13.3 生产验收

生产或准生产环境必须验证：

- 反馈提交和状态查看在真实部署入口可用。
- 安全提示在真实访问入口可见。
- HTTPS 访问正常，无明显混合内容或证书错误。
- 若通过 Cloudflare Worker 临时入口访问，应记录入口、验证时间和关键页面访问结果。
- `ISSUE-0020` 的 Cloudflare Worker、安全响应头、WAF / rate limit 或等价免费防护、原始 CloudBase 域名绕过风险告知等仍作为生产安全门禁。
- 若 `ISSUE-0020` 未关闭，生产验收结论最多为“有条件通过”，并必须写明剩余风险和责任人。

### 13.4 业务方验收

业务方需要确认：

- 反馈状态文案符合“记录和后续排查”口径。
- 不承诺即时客服、人工仲裁、退款、封号、担保或认证。
- 安全提示不会让用户误以为平台提供绝对安全担保。
- 当前仍允许小范围试运行。
- 如需公开推广，需先确认 `ISSUE-0020` 是否已满足关闭条件，或明确接受剩余风险。

## 14. 允许进入代码开发的结论

产品经理结论：允许进入代码开发。

进入代码开发的前提：

- 代码开发员必须严格按本 Spec 实现，不得扩展未确认范围。
- 不得关闭 `ISSUE-0020`。
- 不得修改支付、担保、认证、仲裁、自动推荐等未确认能力。
- 实现完成后必须回到产品经理验收、UI 设计师复核、Hermes / 独立复核和 ISSUE 管理流程。

## 4. 非数据库阶段的共同红线与授权原则

### 4.1 首批 RED（零容忍）

以下任一情况即停止当前阶段、阻止发布或回滚新增开关；不得用后续人工补救冒充通过：

- 认证绕过、IDOR、跨账号读取/修改、会话固定或撤销失效。
- 公开列表/详情、聊天、反馈或审核日志泄露联系方式、Secret、Token 或未成年人敏感内容。
- CSRF/Origin 门绕过、可利用 XSS/CSP 缺口、SSRF 可访问内网/metadata、注入未被拒绝。
- D6 客户端勾选可绕过服务端、token 复用/错 hostname/action/过期仍发送验证码、验证超时 fail-open。
- 0036 AI 单独决定发布/拒绝、未知语言/类别自动放行、OCR 未经确认出域、审计失败仍公开。
- 生产未登记人工 owner 却启用人工审核闭环或自动公开；任何零容忍项无告警/无停止条件。

### 4.2 共同授权边界

- 本地/集成/合成数据可以先做，无真实 Secret、真实未成年人或真实联系方式。
- 代码、测试和非生产配置只能在对应阶段文档门禁、业务方向确认和总负责人书面授权后变更。
- Cloudflare/CloudBase 生产配置、验证码发送、审核公开、聊天/联系方式操作、feedback 写回
  都是副作用，必须使用专用账号/合成数据、限定窗口、可清理清单、监控、停止条件和回滚。
- 生产版本号由业务方部署时给出；本 Spec 不预填版本，也不把本地/集成通过当生产或业务通过。

## 5. 阶段 S1：ISSUE-0034 非数据库安全切片

### 5.1 目标与非目标

目标是先降低不依赖 SQL 迁移的高风险面：认证/会话/Cookie、对象级授权与 IDOR、输入输出
schema、CSRF/Origin、XSS/CSP、SSRF、Secret 访问与脱敏、速率限制/滥用、依赖供应链、
日志/告警、Cloudflare/Worker/源站隔离、隐私/未成年人最小化、DoS/容量和相关回滚。

明确不做：数据库引擎/Schema 迁移、SQL adapter、数据库备份/恢复、RPO/RTO、短写冻结、
数据库专属灾备和 0031 预算；这些依赖随 0031 延期。也不在 S1 接入 D6 provider 或 0036 AI。

### 5.2 前置、步骤与不可并行项

前置为本 Spec Round 1 文档门禁无 SERIOUS、总负责人授权、S1 范围冻结、两个受控账号可在
限定环境使用。步骤为：只读差距复核 → 最小代码/配置设计 → 本地负测 → 集成合成数据 →
独立技术复核 → 受控预生产 → 生产最小验证 → 业务接受。数据库切换、双写、D6/0036 生产
开关和另一副作用窗口不得与 S1 写入窗口并行。

## 6. 阶段 S2：ISSUE-0032 服务端人机验证

### 6.1 冻结推荐

“其他按推荐”在 S2 仅冻结以下方向，不等于外部配置已存在：Cloudflare Turnstile Free 优先，
widget region 优先 `china`。文档门通过后，provider-neutral 的本地代码、fixture 和 adapter

与可用性，并保存带时间、hostname/action、widget region、验证者和控制台截图或 API probe 的
证据；验证失败或证据缺失只使 provider-specific 启用 `no-go`，不阻塞 provider-neutral 本地
RED。若不可用，不得自行采购或选择新供应商；由项目总负责人路由 provider-neutral 等价候选
的业务确认，或停在本地 adapter 并进入人工/邮件停发的 fail-closed 升级路径，均需记录 owner
与证据，不得静默切换 `world`。
provider-specific 启用不支持时保持阻塞；production hostname 仅
`ungraduedu.eu.cc`、`www.ungraduedu.eu.cc`；action 为 `email_send_code`；provider TTL

3 次/15 分钟、10 次/24 小时，IP 10 次/15 分钟；默认不传 remoteip，本地 IP 只做 HMAC

### 6.2 目标、非目标、红线与流程

目标是浏览器 challenge → 服务端 Siteverify → 精确检查 success/hostname/action/时效/一次性
消费 → 只有成功后发送邮箱验证码。非目标是数据库迁移、AI 审核和客户端勾选替代服务端。
任何 token 缺失、重放、错域名/动作、过期、provider 超时/不可达、secret 缺失、限流失败、
无障碍路径旁路均 fail-closed，失败发送数必须为 0。

前置为 S1 独立复核通过、外部账户能力只读确认；文档门通过后可启动 provider-neutral 本地
代码/fixture/adapter 与 RED/负测。provider-specific widget/secret 只在中国大陆目标网络
可达性/可用性证据齐备且由授权窗口托管后，才可进入集成、预生产或生产启用；首次 S2 生产
部署前同样必须生成并验证 baseline receipt，缺失即 `no-go`，不得假设已有版本。目标网络证据
失败时停在本地 adapter，路由等价候选评估或人工/邮件停发 fail-closed，不采购、不自行换供应商。
步骤为 provider-neutral 本地 stub/负测 → 目标网络证据门 → provider-specific 测试集成 →
独立复核 → 预生产失败注入 → 生产小窗口观察 → 业务接受。不得与数据库迁移、0036 生产
审核公开或另一副作用窗口并行。

### 6.3 验收、回滚和隐私

- 本地/集成必须覆盖 token 一次性、TTL、hostname/action、超时、服务不可达、限流、重放、
  无障碍和客户端绕过；不发送真实验证码给普通用户。
- provider-specific 集成、预生产或生产启用前必须回读中国大陆目标网络 widget 可达性/可用性
  验证的截图或 API probe、时间、hostname/action、region 和 owner；任一缺失或失败即 provider-
  specific `no-go`，停在 provider-neutral 本地 adapter，并验证等价候选的业务路由，或人工/
  邮件停发 fail-closed 升级路径，不阻塞 provider-neutral 本地 RED，不得自行采购/选新供应商。
- 生产仅允许专用账号/合成邮箱在批准窗口验证“成功发送”和所有失败路径发送 0；Secret 只读引用，
  不写日志/仓库；指标保留最小化摘要。
- provider 不支持 China widget region、S2 可达性/可用性验证失败、验证异常、成本超限或观察
  RED 出现时，立即关闭发送开关；首次生产部署缺少或无法验证 baseline receipt 时保持
  `no-go`，已有部署回滚到上一个已验证 baseline；不得静默切换 world 或未确认 provider。
- 业务方分别接受成本、域名、无障碍体验和失败文案；不把 provider 技术报告冒充用户接受。

默认 provider-neutral stub/不出域、不能作为唯一证据；OCR 关闭；旧 published 快照保持可见，
新编辑版本和恢复版本先审；`appeal_pending` 独立且不得直达 published；`deleted` 只是生命周期标记。

### 7.3 无人工 owner 时的允许与禁止

允许代码开发员使用合成 reviewer、虚拟时钟、golden corpus、队列故障注入和审计 stub 完成本地、
集成、独立复核；允许生产前读取静态配置和做不写入的探针。禁止生产启用人工审核闭环、禁止
在无人审查时自动公开、禁止让 AI 单独作发布/拒绝决定、禁止 OCR 或原文外发。直到真实 owner、
备援、权限、值班、二审和升级链登记并通过独立复核，S3 生产只能保持关闭/不接收公开审核，
且只允许本地、集成和合成 reviewer queue；不得把真实用户内容放入无人值守的生产人工队列。
已批准的内容初审/普通人工审核队列按 0036-05：系统入队 p95 ≤5 分钟、裁决 p95 ≤30 分钟、
99% ≤2 小时；已批准的申诉队列按 0036-07：入队 p95 ≤30 分钟、裁决 p95 ≤4 小时、
99% ≤1 个工作日。两套 SLA 的任一目标超时都保持 `pending/manual`、不公开并告警，升级至
对应 owner、备援和项目总负责人；一套 SLA 不覆盖另一套。无人工 owner 时用户看到“审核队列
暂未开放，预计在人工服务恢复后处理，请勿重复提交”，不得自动转为普通编辑或自动公开。

DPA/预算/secret/业务门齐备后用批准数据窗口观察误杀/漏放和 SLO，并分别验证内容初审/普通

# 登录状态导航 UI 不同步问题分析与处理预案

日期：2026-06-29

负责人：项目总负责人

当前状态：仅做总负责人预分析和处理预案，暂不分配给产品经理或代码开发员。

## 一、用户反馈

正式环境中，聊天功能正常，交换联系方式正常，保存密码正常，密码登录正常。

当前新问题集中在右上角登录状态导航 UI：

- 未登录时右上角显示“登录 / 注册”。
- 登录成功后，实际账号已经登录，但右上角第一次仍显示“登录 / 注册”。
- 退出登录后，实际账号已经退出，个人信息页也已看不到登录态信息，但右上角第一次仍显示“个人页 / 退出登录”。
- 也就是说，业务登录状态已经变化，但右上角导航 UI 与登录状态不同步，通常需要再次刷新或重新进入页面才会变正确。

## 二、初步定位结论

这不是数据库集合缺失问题，也不是验证码、密码或联系方式交换主链路问题。

从当前代码看，右上角导航由 `Code文档/features/auth/session-nav.tsx` 渲染，内部使用 `useTestSession()` 读取登录状态。

`useTestSession()` 位于 `Code文档/features/auth/use-test-session.ts`，当前行为是：

- 组件首次挂载时调用一次 `/api/auth/session`。
- 将返回结果写入本地 React state。
- `useEffect` 依赖数组是空数组 `[]`，因此登录或退出后不会自动重新拉取 session。

登录表单位于 `Code文档/features/auth/login-form.tsx`：

- 验证码登录成功后写入 Cookie。
- 密码登录成功后写入 Cookie。
- 当前主要执行 `router.push(...)`。
- 没有显式通知右上角 `SessionNav` 重新读取 `/api/auth/session`。

退出逻辑位于 `Code文档/features/auth/session-nav.tsx` 和 `Code文档/features/auth/logout-button.tsx`：

- 调用 `/api/auth/logout` 清除 Cookie。
- 执行 `router.push("/")` 和 `router.refresh()`。
- 但右上角导航是客户端组件，且自身 session state 不会因为 `router.refresh()` 自动重跑 `useEffect([])`。

因此，最可能根因是：

登录 / 退出成功后，服务端 Cookie 已变化，但客户端导航组件缓存的 session state 没有被主动刷新。

## 三、影响范围判断

已确认正常的链路：

- 聊天功能正常。
- 交换联系方式正常。
- 保存密码正常。
- 密码登录正常。

当前问题影响的是：

- 右上角导航显示状态。
- 用户对“我现在到底登录了还是退出了”的即时感知。
- 首次登录 / 首次退出后的界面可信度。

当前初步判断：

- 不影响服务端真实 session。
- 不影响权限判断。
- 不影响联系方式交换和聊天。
- 属于前端客户端状态同步缺陷，优先级建议为 P1，因为会直接影响正式环境登录体验和用户信任。

## 四、建议处理方向

推荐方案：建立统一的客户端 session 刷新机制。

建议由代码开发员在后续任务中实现：

1. 调整 `useTestSession()`，提供可重复调用的 `reloadSession()` 或改成可响应外部事件的 hook。
2. 登录成功后，除 `router.push(...)` 外，主动触发一次登录状态刷新。
3. 退出成功后，在跳转前或跳转后主动将 session 置空，并触发导航刷新。
4. `SessionNav` 订阅统一刷新机制，不再只依赖首次挂载时的一次请求。
5. 如果当前项目不想引入状态库，可以先采用轻量方案：
   - 登录成功后 `window.dispatchEvent(new Event("auth-session-changed"))`。
   - 退出成功后同样派发事件。
   - `useTestSession()` 监听该事件并重新请求 `/api/auth/session`。
6. 若希望更稳妥，也可引入 React context 或 SWR 类似的 `mutate` 机制，但当前 MVP 不必过度设计。

不推荐方案：

- 单纯依赖 `router.refresh()`。
- 单纯依赖 `router.push()`。
- 用强制整页刷新 `window.location.reload()` 作为长期方案。

强制整页刷新可以作为临时止血，但会显得粗糙，也容易掩盖真实状态同步问题。

## 六、建议验收步骤

修复后，正式环境需要按以下顺序验收：

1. 清空浏览器当前登录态，打开首页。
2. 确认右上角显示“登录 / 注册”。
3. 进入登录页，使用验证码登录。
4. 登录成功跳转后，不刷新页面，立即检查右上角是否显示“个人页 / 退出登录”。
5. 点击“退出登录”。
6. 确认弹窗出现。
7. 点击确认退出后，不刷新页面，立即检查右上角是否显示“登录 / 注册”。
8. 再次使用邮箱 + 密码登录。
9. 登录成功后，不刷新页面，立即检查右上角是否显示“个人页 / 退出登录”。
10. 尝试进入个人页，确认权限与右上角 UI 状态一致。

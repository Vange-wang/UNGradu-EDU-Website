## Standards

### P0：公开详情 URL 暴露发布者手机号

位置：

- `Code文档/features/parent-needs/parent-need-storage.ts:41`
- `Code文档/features/tutor-profiles/tutor-profile-storage.ts:41`
- `Code文档/app/parent-needs/page.tsx:198`
- `Code文档/app/tutor-profiles/page.tsx:192`

问题说明：

当前 `createParentNeedId` 和 `createTutorProfileId` 使用 `${ownerPhone.trim()}-${Date.now()}-${count + 1}` 生成记录 ID。M3 广场页又直接把该 ID 放进详情页链接，例如 `/parent-needs/${need.id}` 和 `/tutor-profiles/${profile.id}`。这会让发布者登录手机号出现在浏览器地址栏、历史记录、截图、日志和分享链接中。

违反标准：

- `AGENTS.md` 要求涉及联系方式、未成年人信息和隐私保护的逻辑必须谨慎设计。
- `规划文档/钦定产品经理.md` 将联系方式保护列为 MVP 核心安全主线，未授权前不得返回或展示对方联系方式。

影响：

即使详情页正文没有渲染 `phone` 或 `wechat` 字段，手机号已经通过 URL 被公开展示。M3 的“详情页不展示联系方式”验收不能通过。

建议：

- 记录 ID 不得包含手机号、微信号或任何可识别联系方式。
- 使用随机 ID、`crypto.randomUUID()` 或后端生成的不可反推 ID。
- 增加测试：保存需求/家教信息后，断言 `id` 和详情链接不包含 `ownerPhone`。

### P2：M2 已存在的本地测试数据可能无法进入 M3 广场

位置：

- `Code文档/features/parent-needs/parent-need-storage.ts:45`
- `Code文档/features/parent-needs/parent-need-storage.ts:169`
- `Code文档/features/tutor-profiles/tutor-profile-storage.ts:45`
- `Code文档/features/tutor-profiles/tutor-profile-storage.ts:174`

问题说明：

M3 新增 `ungradu.parentNeedOwners` 和 `ungradu.tutorProfileOwners` 作为跨账号聚合索引，但该索引只在 M3 版本的 `saveParentNeed` / `saveTutorProfile` 中写入。若测试人员在 M2 阶段已经发布过需求或家教信息，旧数据只存在于 `ungradu.parentNeeds.{ownerPhone}` / `ungradu.tutorProfiles.{ownerPhone}`，没有 owners 索引，`readAllParentNeeds` / `readAllTutorProfiles` 会返回空列表。

影响：

这不一定影响全新测试数据，但会影响从 M2 接续到 M3 的验收体验：已发布内容可能在“我的发布”中存在，却不出现在广场中。

建议：

- 若继续使用本地测试存储，补一个轻量迁移或重建索引机制。
- 至少在开发员工作记录和测试说明中写清楚 M3 验收前需要重新发布测试数据。

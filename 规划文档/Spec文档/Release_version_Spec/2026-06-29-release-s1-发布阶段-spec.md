# 家教对接平台发布阶段 Spec：S1 完成与 S2+ 后续规划

日期：2026-06-30

状态：正式 Spec

阶段口径：S1 已完成；后续从 S2、S3、S4 继续规划和推进

产品角色：项目总负责人代落地，后续产品经理接续维护

适用范围：MVP 已完成生产部署、生产试运行修复和正式环境核心链路验收后，用于定义发布阶段完成结论，以及后续发布阶段如何继续推进。

## 1. 背景

家教对接平台已经完成 MVP 主体功能、正式生产部署、邮箱验证码登录、密码登录、聊天、联系方式交换、生产体验缺陷修复和正式环境多轮冒烟。

截至 2026-06-29，项目总控制人已确认：

- 聊天功能正常。
- 交换联系方式正常。
- 保存密码正常。
- 密码登录正常。
- 登录状态与右上角 UI 不匹配问题已解决。

此前遗留的 `ISSUE-0005` 指出：历次审查报告、最终审查报告和远端 Git 记录之间存在追溯链条不完整的问题。该问题不是业务功能缺陷，但会影响发布完成后的责任溯源和历史复核。

本 Spec 将该类事项正式归入发布阶段 S1 的追溯治理范围，并明确：S1 已完成，后续规划从 S2 开始。

## 2. 发布阶段总目标

发布阶段的目标不是继续扩大 MVP 功能，而是把“可上线、可验证、可追溯、可继续运营”落成稳定状态。

发布阶段总目标包括：

- 明确当前生产可用基线。
- 关闭阻塞发布完成的 P0 / P1 生产体验问题。
- 明确生产部署、环境配置、数据库集合、登录服务和核心业务链路状态。
- 建立审查报告、复核报告、Issue 关闭依据和工作记录的追溯规则。
- 将后续运营、风控、审核、推广和 vNext 功能从 S1 发布收口中拆出，进入 S2+ 阶段规划。

| S5+ | 后续迭代 | vNext 产品能力 | 根据真实反馈推进评价、排课、支付、推荐、后台等非 MVP 能力 | 每项能力进入独立 Spec、里程碑和验收闭环 |

## 4. S1 已完成范围

S1 已完成事项：

- 建立发布阶段完整 Spec。
- 明确审查报告必须归档到仓库内固定目录。
- 明确最终审查报告、产品审查报告、复核报告和 Issue 关闭依据之间的引用关系。
- 明确每个发布阶段任务必须记录分支、基线 commit、目标 commit、验证命令和部署状态。
- 将原 `ISSUE-0005` 从孤立流程 Issue 转为发布阶段 S1 追溯规范事项并关闭。
- 关闭当前阻塞发布完成的生产体验问题。

S1 不再承接的事项：

- 不再新增业务功能。
- 不再把已验收的聊天、联系方式交换、密码保存、密码登录、登录状态 UI 同步问题反复登记为发布阻塞项。
- 不再继续沿用 M5 阶段分支处理正式部署后的新任务。
- 不再把后续运营后台、审核、支付、排课、评价、实名认证、推荐算法塞回 S1。

## 5. S1 功能验收结论

截至 2026-06-29，以下业务链路已满足 S1 完成口径：

- 首页可访问。
- 邮箱验证码登录可用。
- 首次登录后可设置密码。
- 邮箱 + 密码登录可用。
- 未登录导航显示“登录 / 注册”。
- 已登录导航显示“个人页 / 退出登录”。
- 登录 / 退出后导航 UI 与真实登录状态同步。
- 家长 / 学生可发布找老师需求。
- 老师可发布个人家教信息。
- 家长 / 学生可浏览老师信息。
- 老师可浏览需求信息。
- 站内聊天可用。
- 交换联系方式可用。
- 反馈入口可用。

以下能力不属于 S1：

- 在线支付。
- 平台担保交易。
- 合同。
- 复杂排课。
- 课时记录。
- 评价体系。
- 自动推荐算法。
- 完整审核后台。
- 实名认证。
- 资质认证等级。
- 举报封禁后台。
- 图片 / 语音聊天。
- 大规模公开推广。

## 7. S1 追溯归档规则

发布阶段开始后，以下文档必须纳入仓库并可被追溯：

- 发布阶段 Spec。
- 执行打包说明。
- 产品审查报告。
- 代码复核报告。
- 最终审查报告。
- 生产冒烟验收记录。
- Issue 总表。
- Open / Close Issue 单文件。
- 总负责人工作记录。
- 产品经理工作记录。
- 代码开发员工作记录。
- ISSUE 管理员工作记录。

每份审查报告至少应包含：

- 日期。
- 阶段 / 任务 ID。
- 目标分支。
- 基线 commit。
- 目标 commit。
- 验证命令和结果。
- 结论：允许验收、需要返工、阻塞或仅外部事项待确认。
- 若引用其他报告，必须写明相对路径。

如果某些文档暂未提交到远端，则不能用“远端可追溯”作为验收依据，只能表述为“本地工作区已更新”。

## 8. S2 规划：生产运行观察与运维基线

S2 目标：

- 观察正式环境真实使用。
- 建立生产问题分级机制。
- 明确发生登录、发布、聊天、数据库、部署异常时的处理流程。
- 建立运行检查清单和必要的记录格式。

S2 建议交付物：

- `生产运行观察记录`。
- `生产问题分级与响应规则`。
- `部署回滚与环境配置核对清单`。
- `数据库集合与权限配置检查表`。

S2 暂不做：

- 不做大规模功能扩张。
- 不做复杂后台。
- 不做支付与合同。
- 不做自动推荐算法。

## 9. S3 规划：风控、审核与可信度增强

S3 目标：

- 明确老师资料审核边界。
- 明确联系方式展示、交换和风险提醒规则。
- 明确未成年人相关隐私保护规则。
- 明确举报入口、风险提示、信息撤回和基础处置边界。
- 明确当前阶段暂不具备客服与人工介入能力，该能力后续需单独规划。

S3 建议交付物：

- `风控与审核 Spec`。
- `老师资料审核规则`。
- `联系方式与隐私保护规则`。
- `举报入口与风险提示最小闭环说明`。
- `后期智能 Agent 客服专项规划占位说明`。

S3 暂不默认做：

- 不默认接入实名认证供应商。
- 不默认做资质认证等级体系。
- 不默认做自动风控模型。
- 不默认做复杂客服工单系统。
- 不默认实现人工客服、人工审核值守或人工介入处置。
- 不默认实现智能 Agent 客服；该能力需要后期另建专项 Spec、数据边界、权限边界和验收标准。

## 10. S4 规划：公开推广前发布评审

S4 目标：

- 在扩大访问前复核产品、技术、合规和运营承接边界。
- 确认是否允许从小范围试运行进入公开推广。
- 明确推广前必须补齐的问题和可延期事项。
- 明确客服与人工介入当前无法实现时，公开推广范围必须受限，且需在风险清单中列明兜底方式。

S4 建议交付物：

- `公开推广前发布评审报告`。
- `公开推广风险清单`。
- `客服与人工介入缺口说明`。
- `智能 Agent 客服后期专项规划入口`。
- `下一阶段 vNext 候选需求池`。

S4 退出结论只能是以下之一：

- 允许公开推广。
- 允许小范围继续试运行，不建议公开推广。
- 暂停推广，必须先修复阻塞项。

- 排课。
- 在线支付。
- 平台担保交易。
- 合同。
- 老师认证。

- 人工客服 / 人工介入工作台。

## 11.1 智能 Agent 客服专项说明

当前 S3 / S4 不具备客服与人工介入实现条件，因此不得把“客服已承接”“人工介入已可用”写入当前发布验收结论。

后期如要建设该能力，应单独设立智能 Agent 客服专项，至少先明确：

- Agent 客服能回答哪些问题，不能回答哪些问题。
- 涉及未成年人、联系方式、投诉、退款、资质争议时如何升级。
- Agent 是否可以读取用户资料、聊天内容、联系方式交换记录。
- Agent 输出是否需要人工复核。
- 如何记录客服会话、追溯责任和处理结果。
- 误答、越权答复、隐私泄露和误导用户的风险控制。

在该专项完成前，S3 / S4 只能描述为“客服与人工介入能力待建设”，不能作为公开推广已具备条件。

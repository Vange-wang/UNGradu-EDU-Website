# 家教对接平台 MVP 正式生产上线 PRD 评审报告

评审日期：2026-06-25
评审对象：`2026-06-25-mvp-正式生产上线-prd.md`
评审角色：产品经理（自评/复核视角）
评审结论：**可行，建议补齐 2 项软阻塞内容后转正式 Spec**

---

## 1. 总体结论

该 PRD 在环境隔离、密钥管理、测试登录禁用、回滚预案、验收标准等核心维度上覆盖完整，逻辑自洽，阻塞项与验收标准一一对应，没有出现"验收通过但阻塞项未清"的矛盾。

上线口径定义为"小范围生产试运行 + 不公开推广"，与当前正式短信登录、风控、审核能力尚未就位的现状相匹配，整体判断**克制且可执行**。

唯一需要在转 Spec 前解决的实质性风险点，是第 6.4 节"正式登录方案"的执行细节不足，可能在落地阶段造成卡点。其余问题为完善性建议，不构成阻塞。

| 评审维度 | 结论 |
| --- | --- |
| 上线口径是否合理 | 合理，未冒进 |
| 环境/密钥/测试登录管控 | 完整，可执行 |
| 回滚预案 | 完整 |
| 验收标准与阻塞项一致性 | 一致 |
| 正式登录方案 | **不足，需补充** |

| 隐私与数据合规说明 | 偏弱，建议补充 |
| 监控响应时效 | 偏弱，建议补充 |

## 2. 软阻塞项（建议在转 Spec 前解决）

### 2.1 正式登录方案缺少可执行细节（对应原文 6.4 节）

当前方案仅写到"白名单手机号 + 正式验证码或运营确认机制"的原则层面，缺少：

- 验证码/确认信息的具体发送渠道（短信网关 / 人工微信 / 邮件三选一需明确）。
- 白名单手机号的维护主体、存储位置、新增审批流程。
- 该临时方案的**有效期**和**退出条件**（例如：试运行满 30 天后必须切换正式短信登录，否则停止新增用户）。

**风险**：若不在 PRD/Spec 阶段钉死，容易在上线前一天发现登录方案无人可拍板，导致延期。

**建议处理**：在转 Spec 时新增"临时登录方案执行细则"小节，明确上述三项。

### 2.2 缺少试运行时间窗口与退出标准

文档多次使用"小范围试运行"表述，但未定义：

- 试运行预计持续的时间范围。
- 从"试运行"升级为"公开上线"的硬性条件（除 8.3 节已提及的"补正式登录方案"外，是否还需种子用户数量、问题密度等指标）。

**风险**：若无时间盒和退出条件，试运行阶段可能无限期停留，vNext 规划失去触发时点。

**建议处理**：在第 3 节"上线口径"或新增独立小节，明确试运行的时间窗口与退出条件。

---

## 3. 完善性建议（不阻塞，建议补充）

### 3.1 种子用户规模与邀请机制未量化（对应原文第 4 节）

建议补充：

- 各类种子用户的人数上限（如家长 10 人、大学生老师 10 人）。
- 邀请发起人与审批人。
- 种子用户异常行为的移除/退出机制。

避免执行时变成"熟人邀请制"，失去"可控开放"的本意。

### 3.2 监控响应时效未定义（对应原文 6.10 节）

建议补充：

- 反馈确认时效（如"工作时间 2 小时内确认收到"）。
- 值守人/兜底负责人安排。

这样可与 6.8 节回滚触发条件中"无法在 30 分钟内定位的核心路径故障"形成呼应，否则该条件缺少执行上下文。

### 3.3 隐私与数据合规说明偏弱（对应原文 6.9 节）

当前仅有面向用户的功能性说明（联系方式经同意后交换、可反馈滥用），建议补充：

- 最简版隐私说明，说明收集了哪些信息、用途、保留/删除方式。
- 试运行结束或用户退出后的数据处理方式（删除/匿名化/留存期限）。

即便是种子用户范围的真实数据，合规风险一旦出现会比技术债更难补救，建议在第 9 节"上线前阻塞项"中增加一条"基础隐私说明已展示给用户"。

### 3.4 格式与一致性微调

- 第 6.6 节生产冒烟验收清单（20 条）建议按"核心发布流程 / 聊天流程 / 权限校验流程 / 反馈流程"分组，便于直接转化为可勾选的检查清单。
- 第 11 节中 PRD 与 Spec 文件名几乎一致（仅后缀不同），建议在转 Spec 时明确 Spec 相对 PRD 新增的"可执行步骤级"内容，避免重复劳动。

---

## 4. 评审结论与下一步建议

**结论**：本 PRD 具备转入正式 Spec 阶段的条件，建议按以下顺序处理：

1. 业务方/技术负责人确认并补齐 §2.1 正式登录方案执行细则。
2. 明确 §2.2 试运行时间窗口与退出条件。
3. 视资源情况补充 §3 中的完善性建议（种子用户规模、监控时效、隐私说明）。
4. 完成上述后，按原 PRD 第 12 节"建议实施顺序"推进 Spec 编写与生产上线准备。

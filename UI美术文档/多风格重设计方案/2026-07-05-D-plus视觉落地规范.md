# 2026-07-05 D+ 视觉落地规范

关联任务：

- 设计任务：`UI-REDESIGN-MULTI-STYLE-2026-07-03-001`
- 实现任务：`UI-DPLUS-IMPLEMENT-2026-07-05-001`

责任角色：UI 设计师 Agent `019f2319-7c43-7653-9e2c-803229387ac1`

## 1. 适用范围

本规范用于 D+ 高对比漫画风在“家教对接 website”中的代码落地和后续 UI 复核。当前代码开发员第 1 批实现范围为：D+ 全局 token / 基础组件视觉系统 + 首页、登录页、规则页、反馈页。

本规范只定义视觉与组件规则，不新增业务能力，不修改业务边界。

参考预览目录：

- `UI美术文档/多风格重设计方案/预览图/D+全界面/`
- `UI美术文档/多风格重设计方案/预览图/D+全界面/d-plus-all-desktop-contact-sheet.png`

## 2. 视觉原则

D+ 是高对比漫画 UI，不是普通扁平卡片，也不是玻璃拟态。落地时要保留以下特征：

- 纸白底、大块留白、黑色粗描边。
- 明亮黄、橙、青绿作为少量强色块。
- 硬阴影表达漫画感，不使用朦胧大光晕。
- 组件几何明确，文字必须完整落在容器内。
- 业务信息优先于装饰，尤其是广场、详情、发布和聊天页面。

## 3. 色彩 Token

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--dplus-paper` | `#fffdf0` | 页面主容器、卡片底、表单底 |
| `--dplus-paper-strong` | `#fffdf7` | 输入框、轻量表单区域 |
| `--dplus-cream` | `#fff7cf` | 提示卡、规则卡、侧栏弱背景 |
| `--dplus-ink` | `#111111` | 主文字、描边、硬阴影 |
| `--dplus-body` | `#303030` | 正文 |
| `--dplus-weak` | `#69645b` | 次级导航、辅助说明、时间/地点元信息 |
| `--dplus-yellow` | `#ffe75a` | 背景渐变起点、轻提示、同意状态 |
| `--dplus-orange` | `#ff6b2b` | 主行动按钮、当前导航、重点标签 |
| `--dplus-lime` | `#b8ff42` | 次行动、状态标签、角色入口 |
| `--dplus-mint` | `#68e6d8` | 背景渐变终点、页面外围氛围 |
| `--dplus-danger` | `#ff4a3d` | 错误、危险提示，仅少量使用 |
| `--dplus-warning` | `#ffe75a` | 注意、待确认、联系方式未公开提示 |
| `--dplus-success` | `#b8ff42` | 已保存、已同意、可继续状态 |

背景建议：

```css
background: linear-gradient(120deg, #ffe75a 0%, #b8ff42 48%, #68e6d8 100%);
```

页面内容区不要满屏高饱和色。高饱和色应主要用于按钮、标签、入口块和局部提示。

## 4. 描边规则

| 组件 | 描边宽度 | 颜色 | 说明 |
| --- | --- | --- | --- |
| 页面主壳 / 大容器 | `3px` | `#111111` | 桌面端整页面板，保持漫画边界 |
| 主要卡片 | `3px` | `#111111` | 首页模块、列表卡、规则卡 |
| 角色入口插画块 | `4px` | `#111111` | 人物块、强视觉入口 |
| 主按钮 / 次按钮 | `3px` | `#111111` | 高对比、可点击感 |
| 输入框 | `2px-3px` | `#111111` | 普通输入框可用 `2px`，重点表单用 `3px` |
| 标签 / 筛选器 | `2px-3px` | `#111111` | 小标签优先 `2px`，大筛选胶囊 `3px` |
| 聊天气泡 | `3px` | `#111111` | 保持和按钮一致 |
| 分割线 | `1px-2px` | `#ded6ad` | 仅用于列表行内部，不要大量黑线 |

禁止把所有内容都框起来。列表页可以用一个大列表容器承载多行，行间用浅分割线，避免“每个小信息都是一个黑框”导致画面乱。

## 5. 阴影规则

D+ 使用硬阴影，不使用柔光阴影。

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--dplus-shadow-hard` | `8px 8px 0 #111111` | 主卡片、列表卡、主要表单卡 |
| `--dplus-shadow-small` | `5px 5px 0 #111111` | 小按钮、小标签、移动端小卡 |
| `--dplus-shadow-none` | `none` | 输入框、密集列表行、聊天输入区 |

使用规则：

- 首页、登录页、规则页、反馈页可以保留硬阴影，形成品牌感。
- 广场页、详情页、发布页、聊天页要克制阴影数量，优先保证可读和扫描效率。
- 同一屏内不要超过 5-7 个强硬阴影组件。列表项过多时，列表容器有阴影即可，内部行不再逐个加硬阴影。
- 移动端硬阴影建议减小到 `5px 5px 0 #111111`，避免挤占横向空间。

## 6. 圆角规则

| 组件 | 桌面端 | 移动端 | 说明 |
| --- | --- | --- | --- |
| 页面主壳 | `36px-40px` | `28px-32px` | 外层漫画面板 |
| 大卡片 / 表单面板 | `28px-34px` | `24px-28px` | 页面主要分区 |
| 信息卡 / 列表卡 | `22px-26px` | `20px-24px` | 可扫描内容 |
| 按钮 | `999px` 或 `20px-24px` | `999px` 或 `18px-22px` | 胶囊按钮优先 |
| 输入框 | `14px-18px` | `14px-16px` | 不要过圆，避免像玩具输入框 |
| 标签 / 筛选器 | `999px` | `999px` | 胶囊标签 |
| 聊天气泡 | `20px-24px` | `18px-22px` | 气泡感，但文字要稳 |

## 7. 字体层级

推荐字体栈：

```css
font-family: "Noto Sans SC", "Source Han Sans SC", "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Alibaba PuHuiTi", "Microsoft YaHei", sans-serif;
```

| 层级 | 桌面端 | 移动端 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| H1 | `38px-44px` | `32px-36px` | `700-800` | 首页主标题、页面大标题 |
| H2 | `28px-34px` | `24px-28px` | `700` | 页面分区标题 |
| 卡片标题 | `22px-27px` | `19px-22px` | `700` | 信息卡、入口卡、列表标题 |
| 正文 | `16px-19px` | `15px-16px` | `400-500` | 页面说明、详情正文 |
| 说明文字 | `14px-16px` | `13px-15px` | `400-500` | 元信息、时间、区域、状态说明 |
| 按钮文字 | `16px-18px` | `15px-16px` | `700` | 主按钮、次按钮 |
| 标签文字 | `14px-16px` | `13px-15px` | `600-700` | 筛选、状态、角色标签 |

注意：

- 中文标题可粗，但不要撑爆容器。
- 按钮、标签、聊天气泡必须设置 `white-space: nowrap` 或合理最小宽度，避免“字不在框里”。
- 长文案必须允许换行，容器高度要随内容增长。

## 8. 组件规则

### 8.1 主按钮

用途：发布需求、提交、发起站内沟通、申请交换联系方式。

- 背景 `--dplus-orange`。
- 黑色 `3px` 描边。
- 胶囊圆角或 `20px-24px` 圆角。
- 最小高度：桌面 `48px`，移动 `44px`。
- 左右内边距：桌面 `22px-28px`，移动 `18px-22px`。
- 文字居中，禁止溢出。

### 8.2 次按钮

用途：筛选、取消、查看详情、返回列表。

- 背景 `--dplus-lime` 或 `--dplus-paper`。
- 黑色描边。
- 与主按钮同高，但视觉权重低于橙色主按钮。

### 8.3 角色入口卡

用途：首页“发布需求 / 浏览广场 / 站内沟通”、移动端“需求 / 家教 / 沟通”。

- 可用 `--dplus-lime`、`--dplus-orange`、`--dplus-paper` 三色组合。
- 黑色描边 `3px-4px`。
- 入口文字必须短：推荐 2-6 个汉字。
- 入口卡内不要塞长说明，说明放在卡片下方或旁边。

### 8.4 信息卡

用途：需求卡、家教卡、个人中心卡、规则提示卡。

- 卡片背景优先 `--dplus-paper`。
- 标签放左上角，标题在标签下方。
- 标题、元信息、行动按钮保持固定顺序。
- 列表页卡片高度保持稳定，避免每条高低差过大。

### 8.5 筛选器

用途：需求广场、家教广场筛选。

- 桌面端可放左侧筛选栏，移动端改为横向滚动或折叠筛选区。
- 选中项使用 `--dplus-lime` 或 `--dplus-orange`。
- 每个筛选项尽量不超过 6 个汉字，长文案用二级面板显示。
- 不要使用过多黑色粗框堆叠，筛选栏整体可有一个外框，内部用胶囊按钮。

### 8.6 表单组

用途：发布需求、发布家教信息、个人资料、反馈。

- 表单字段按组排列，不要每个字段都做成强阴影卡。
- 输入框背景 `--dplus-paper-strong`。
- 输入框描边 `2px-3px`。
- 字段间距：桌面 `28px-36px`，移动 `20px-24px`。
- 长文本输入区最小高度：桌面 `96px`，移动 `112px`。
- 占位文案不要包含手机号、微信号示例。

### 8.7 状态标签

用途：公开信息、联系方式未公开、待同意、已同意、展示中。

- `联系方式未公开`：优先 `--dplus-lime` 或 `--dplus-warning`。
- `待同意`：优先 `--dplus-yellow`。
- `已同意`：优先 `--dplus-success`。
- 危险 / 错误：`--dplus-danger`，但只用于校验失败和明确风险，不用于日常强调。
- 状态标签不要伪装成认证徽章，不使用“已认证”“平台审核通过”等文案。

### 8.8 聊天气泡

用途：聊天详情页。

- 家长 / 学生侧可用 `--dplus-lime`。
- 家教侧可用 `--dplus-orange`。
- 系统状态提示使用 `--dplus-cream` 或 `--dplus-yellow`。
- 气泡最大宽度：桌面聊天区的 `62%-70%`，移动端 `78%-86%`。
- 气泡内边距：桌面 `16px 22px`，移动 `14px 16px`。
- 文字必须在框内，禁止用绝对定位压在人物图形或气泡边缘。

### 8.9 规则提示卡

用途：规则页、反馈页、联系方式保护说明、详情页侧栏。

- 背景优先 `--dplus-cream`。
- 可使用勾选项或短段落，不使用复杂插画。
- 必须清楚写明平台边界：公开页不展示联系方式，双方同意后交换。
- 不把规则提示做成警告弹窗风格，避免吓人。

## 9. 页面落地规则

### 首页

- 保留 D+ 强入口和漫画人物块。
- 首屏只突出三件事：发布需求、浏览广场、站内沟通。
- 不在首页堆满所有页面功能。

### 登录 / 注册页

- 当前产品不应出现“手机号登录”口径。
- 建议沿用当前实际认证方式文案，例如邮箱登录 / 注册。
- 登录页不要出现实名认证、第三方认证、平台审核等暗示。

### 需求广场 / 家教广场

- 重点是筛选与扫描效率，不要让漫画风压过列表信息。
- 桌面端左筛选、右列表可行。
- 移动端优先筛选折叠 + 单列列表。

### 详情页

- 主内容和“下一步行动”分开。
- “发起站内沟通”“联系方式未公开”必须稳定可见。
- 不展示公开联系方式。

### 发布页

- 使用分组表单，不要做复杂 step 动画。
- 表单说明必须提醒公开说明里不要填写联系方式。
- 提交按钮保持主行动色。

### 个人中心 / 我的列表

- 使用清楚的功能入口和状态摘要。
- 列表不要过度卡片化；多条记录可用同一面板内的行分隔。

### 聊天详情

- 联系方式状态区是重点组件。
- “申请交换”不是支付、认证或平台担保动作，只表示双方同意后交换联系方式。

### 规则页 / 反馈页

- 漫画风保持在容器、按钮、标签上即可。
- 内容要稳重清楚，不要娱乐化处理风险边界。

## 10. 移动端规则

移动端不要直接压缩桌面三栏。

- 页面单列堆叠。
- 外层安全边距：`18px-20px`。
- 卡片间距：`20px-28px`。
- 卡片内边距：`22px-26px`。
- 主按钮高度：不低于 `44px`。
- 输入框高度：不低于 `44px`，长文本区不低于 `112px`。
- 粗描边建议 `2px-3px`，不要全部 `4px`。
- 硬阴影建议 `5px 5px 0 #111111`，避免横向溢出。
- 标题最长控制在两行以内；超过两行时收窄字号或调整文案。
- 标签、按钮、气泡必须设置最小宽度和内边距，避免文字出框。
- 横向滚动筛选必须有清楚的可滚动区域，不要让按钮贴屏幕边缘。

## 11. 禁止项

### 业务能力禁止暗示

不得通过 UI 文案、徽章、图标或状态暗示以下能力：

- 在线支付。
- 平台担保。
- 资质认证 / 实名认证。
- 平台人工审核。
- 人工客服仲裁。
- 退款。
- 合同。
- 自动推荐算法。
- 评分排名或匹配百分比。

### 联系方式边界

- 公开页不展示手机号、微信号、QQ、邮箱等直接联系方式。
- 联系方式仅在双方同意后交换。
- 发布表单、个人资料、反馈表单不应鼓励用户直接填写联系方式到公开说明里。

### 登录口径

- 不出现“手机号登录”口径，除非产品经理后续确认该能力已实现。
- 不出现短信验证码、第三方登录等未实现入口。

### 视觉禁止项

- 不再使用大面积朦胧光晕。
- 不用无意义连接线、装饰线干扰信息。
- 不让文字压在图形边缘或跑出按钮、标签、气泡。
- 不把每个小元素都做成黑框，避免画面碎。
- 不使用过多纯黑大面积块，黑色主要用于描边、文字和少量强调。

## 12. UI 复核清单

代码开发员提交后，UI 设计师复核时按以下清单检查：

- 全局颜色是否接近本规范 token。
- 主按钮是否为橙色、黑描边、足够高。
- 卡片是否有漫画硬阴影，但没有过量堆叠。
- 列表页是否仍然清楚可扫，不被装饰压过。
- 表单字段文字、占位文案、按钮文字是否全部在容器内。
- 移动端是否无横向溢出。
- 聊天页是否明确显示联系方式状态。
- 规则页和反馈页是否未暗示未实现业务能力。
- 登录页是否未出现手机号登录、短信验证码或认证暗示。
- 公开页是否未展示联系方式。

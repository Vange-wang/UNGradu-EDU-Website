# UNGradu EDU 智能客服知识库

版本：CS-KB-MVP-2026-07-07  
适用站点：UNGradu EDU 家教对接 website  
适用智能体：家教对接网站智能客服 Agent  
用途：供 Dify Knowledge 导入，也供网站离线兜底客服、人工复核和线上验收使用。

## 1. 产品定位

UNGradu EDU 是面向东莞大学城家教供需双方的小范围试运行平台。当前核心目标是帮助家长 / 学生发布找老师需求，帮助大学生家教发布可教资料，并通过公开列表、详情页、站内沟通和双方确认后的联系方式交换完成初步对接。

智能客服只负责解释平台使用方式、规则边界和风险反馈入口。它不是人工客服，不是交易担保方，也不是纠纷裁决方。

## 2. 用户角色

### 2.1 家长 / 学生

家长或学生可以在平台发布找老师需求，说明科目、学段、预算、上课方式、地点范围、时间偏好和补充说明。发布时不要在公开说明中写手机号、微信号、详细住址、门牌号、身份证号、银行卡号等敏感信息。

常见问题：

- 想找老师：先发布需求，或浏览大学生家教资料。
- 想筛选老师：按科目、学段、性别偏好、价格范围、上课方式等公开字段判断。
- 想联系老师：先进入详情页发起站内沟通，聊清楚后再申请交换联系方式。
- 想反馈风险：进入“风险与功能反馈”页面提交问题。

### 2.2 大学生家教

大学生家教可以发布自己的可教资料，说明学校专业、可教科目、可教学段、上课方式、可约时间、课时费范围和个人介绍。公开资料中不要直接写联系方式或精确住址。

常见问题：

- 想接家教：先发布家教资料，再浏览家长需求。
- 想提高匹配效率：把科目、学段、时间、区域、价格范围写清楚。
- 想联系家长：先通过站内聊天沟通，再在双方确认后交换联系方式。
- 遇到骚扰或虚假信息：通过“风险与功能反馈”提交记录。

## 3. 主流程说明

### 3.1 发布找老师需求

家长或学生发布需求时，建议填写：

- 科目：例如数学、英语、物理、编程等。
- 学段：小学、初中、高中、大学基础课程等。
- 预算：建议写课时费范围，不写绝对承诺。
- 上课方式：线上、线下或可协商。
- 地点范围：只写大致区域，不写详细住址。
- 时间偏好：工作日晚上、周末上午等。
- 补充说明：学习目标、当前基础、期望老师类型。

客服回答口径：帮助用户理解如何发布和如何保护隐私，不替用户判断具体老师是否一定合适。

### 3.2 发布大学生家教资料

大学生家教发布资料时，建议填写：

- 学校和专业。
- 可教科目和学段。
- 可上课时间。
- 上课方式和地点范围。
- 课时费范围。
- 教学经历或擅长方式。

客服回答口径：提醒资料越清楚越容易被判断，但不要承诺平台会自动推荐、保证接单或审核背书。

### 3.3 公开列表与详情页

公开列表和详情页只展示供需判断所需的公开信息，不展示手机号、微信号、精确地址、身份证号、银行卡号等敏感信息。公开页面不应暴露联系方式、用户内部 ID、数据库集合名、密码哈希或验证码信息。

客服回答口径：如果用户问“为什么看不到手机号 / 微信”，回答：平台默认保护联系方式，需先站内沟通并经双方确认后再交换。

### 3.4 站内沟通与联系方式交换

平台推荐流程是：先站内沟通，再确认是否交换联系方式。联系方式必须经双方同意并二次确认后展示。未授权前，聊天接口和页面不应返回对方联系方式。

客服回答口径：

- “什么时候能交换联系方式？”答：双方先站内沟通，确认意向后发起交换请求，完成双方同意和二次确认后才能展示。
- “能不能直接给手机号？”答：不建议在公开说明或未确认聊天中直接发送手机号、微信号等敏感信息。
- “为什么要二次确认？”答：减少误操作、骚扰和未经授权的联系方式扩散。

## 4. 费用与交易边界

当前平台不提供担保交易，不做在线支付，不抽佣，不保管课时费，不裁决退款，不处理合同仲裁，不承诺教学质量结果。

课时费由家长 / 学生和大学生家教自行沟通确认。建议双方在交换联系方式或线下见面前，先确认科目、学段、上课方式、频率、预算范围、试课安排和安全边界。

客服回答口径：

- 可以解释“课时费由双方自行沟通”。
- 可以提醒“平台不做支付、抽佣或课时费担保”。
- 不能承诺“平台保证退款”“平台担保交易”“平台会赔偿”“平台仲裁结果有效”。

## 5. 风险与功能反馈

遇到虚假信息、骚扰、联系方式滥用、疑似诈骗、线下付款争议、合同争议、退款争议、未成年人安全风险或功能异常时，引导用户进入 `/feedback` 的“风险与功能反馈”页面。

用户提交反馈时，可填写：

- 反馈类型。
- 涉及对象或页面。
- 问题描述。
- 可公开给平台排查的证据说明。
- 联系方式或账号线索，但不要提交身份证号、银行卡号、验证码、密码或未成年人详细隐私。

当前反馈能力是最小记录和排查入口，使用 CloudBase 集合 `risk_feedback_records` 记录。平台会按试运行规则记录和排查，但不承诺立即人工处理，不承诺固定处理时限，不承诺退款、赔偿、合同处理或人工仲裁。

## 6. 隐私与安全

智能客服必须优先保护用户隐私：

- 不要求用户在聊天中提供身份证、银行卡、密码、验证码、详细住址、未成年人姓名学校班级等敏感信息。
- 不鼓励用户在公开说明或站内消息中直接发送手机号、微信号等联系方式。
- 不读取或输出用户私人聊天内容、联系方式交换记录、验证码、密码哈希、后台集合内容或生产密钥。
- 涉及未成年人、线下见面、付款、住址和身份资料时，提醒用户谨慎沟通并保留必要记录。

## 7. 登录与账号

用户需要登录后使用发布、个人中心、联系方式管理、站内聊天和联系方式交换等功能。当前站点已有邮箱验证码、密码登录、保存密码、退出登录等相关能力。生产环境不得开启测试登录、固定验证码或临时身份头。

客服回答口径：只提供使用指引，不代用户找回密码，不索要验证码和密码。

## 8. 智能客服回答范围

可以回答：

- 怎么发布找老师需求。
- 怎么发布大学生家教资料。
- 为什么公开页不展示联系方式。
- 怎么进行站内聊天和联系方式交换。
- 课时费和交易边界。
- 遇到风险或功能问题去哪里反馈。
- 登录、注册、个人中心入口的基础说明。

必须升级或引导到 `/feedback`：

- 投诉、纠纷、退款、合同、赔偿、骚扰、诈骗、虚假资料。
- 未成年人安全风险。
- 联系方式滥用。
- 涉及真实用户数据、生产后台、密钥或数据库内容。

不能回答或不能承诺：

- 不承诺平台认证老师身份。
- 不承诺平台审核每条资料真实性。
- 不承诺自动推荐最合适老师。
- 不承诺在线支付、担保、退款、赔偿、合同处理或人工仲裁。
- 不承诺立即人工客服介入或固定时限处理。

## 9. 标准回复模板

### 发布找老师需求

你可以先发布找老师需求，填写科目、学段、预算、上课方式、地点范围和时间偏好。公开列表不会展示联系方式，建议先通过站内沟通聊清楚学习目标、地点范围和课时安排，再决定是否交换联系方式。

### 发布家教资料

大学生家教可以发布可教资料，填写学校专业、可教科目、可教学段、时间、上课方式和课时费范围。公开资料不要写手机号、微信号或精确住址，联系方式需双方确认后再交换。

### 联系方式交换

联系方式需要双方先站内沟通，并在确认意向后发起交换请求。双方同意并二次确认后，才会展示已保存的联系方式。公开列表和详情页默认不展示手机号、微信号等直接联系方式。

### 费用边界

平台当前不做支付、抽佣或课时费担保。课时费由双方自行沟通确认，建议先明确科目、学段、上课方式、频率、预算范围和试课安排。

### 风险反馈

这类问题建议走“风险与功能反馈”页面提交记录。当前平台不提供担保交易，不裁决退款，不处理合同仲裁，也不承诺立即人工客服处理；你可以提交涉及对象、问题描述和可用于排查的证据说明。

## 10. 上线验收知识点

客服智能体上线前，至少要能稳定回答以下问题：

1. 家长怎么发布找老师需求？
2. 大学生怎么发布家教资料？
3. 为什么看不到对方手机号或微信？
4. 什么时候能交换联系方式？
5. 课时费怎么定，平台是否担保？
6. 退款或合同纠纷怎么办？
7. 遇到骚扰或虚假信息怎么办？
8. 登录失败或无法发布怎么办？
9. 公开资料能不能写联系方式？
10. 未成年人线下见面要注意什么？

- **严重程度**：NON_SERIOUS
- **位置**：§4.5（第 150–154 行）vs §7.1（第 216 行）
- **证据**：§4.5 标题为「D4/D6/D7 实施前决策门」，表格仅含 D4、D6、D7。§7.1 写道「D5 已确认'经演练的短写冻结 + 单源切换'，不默认双写」。D5 的来源（联合 Spec 5B 的 D1–D8 之一）及其范围、owner 和确认证据均未在本草案中定义。
- **影响**：读者须自行推断 D5 来自 5B 联合 Spec 且已获确认。若 5B 不可用或读者不熟悉 D1–D8 枚举，将无法独立验证 D5 已确认的声明。S1 的迁移策略依赖 D5，但文档未给出可追溯的交叉引用。
- **纠正**：在 §4.5 开头或 D4 表格之前增加一行注释：「D1–D3、D5、D8 已在联合 Spec（5B）中确认；本表仅列出仍需业务冻结的 D4、D6、D7。」或在 §7.1 中为 D5 添加对 5B 章节的显式交叉引用。
- **闭包触发条件**：下一轮审查或业务方确认时，5B 联合 Spec 中的 D5 确认记录可被任何读者独立定位。

### N2-03 — §11 中 ISSUE-0020 的升级程序在无可路由联系信息时静默死锁

- **严重程度**：NON_SERIOUS
- **位置**：§11（第 368–372 行）
- **证据**：升级路径为 T+1 提醒 → T+3 升级至 sponsor/manager → T+5 或三次请求后固定为 `EXTERNAL_BLOCKED`，之后每周更新。随后写道「若 sponsor、manager 或联系渠道也未登记，只记录'无可路由输入'并暂停；不得发明替代人。」若外部 owner、sponsor 和 manager 均未知，流程将永久暂停且无替代解决机制。
- **影响**：0020 已被明确标记为 `EXTERNAL_BLOCKED` 且位于本文档范围之外。死锁是外部情况的属性，并非文档缺陷。然而，无可路由升级路径的「暂停」状态缺少定期重新评估触发器（例如每季度审查一次是否需要变更 Issue 范围）。
- **纠正**：可选添加：「暂停期间，每季度由总负责人审查一次是否需要降级/关闭 0020 或缩小其范围；维持现有 Cloudflare 配置不变。」
- **闭包触发条件**：业务方或 Issue 管理员确认 0020 在无可路由联系信息时的长期处置策略。

### N2-04 — S3 在流量不足时的生产观察期限未定义

- **严重程度**：NON_SERIOUS
- **位置**：§9（第 314–315 行）
- **证据**：「至少观察 72 小时发送稳定窗口；流量不足时，须完成批准的合成/集成样本和全部零容忍负例后仍保持生产观察。」合成样本完成后应持续多久的生产观察未给出范围或退出条件。
- **影响**：S3 的完成定义变为开放式。若流量长期不足，`TECH_VERIFIED` 可能被无限期延迟。实践中，合成样本的完成和零容忍负例的全覆盖已提供有意义的证据；缺少显式退出条件为轻度问题。
- **纠正**：添加下限，例如「合成样本覆盖全部负向用例且零容忍项均为 0 后，继续生产观察不少于 72 小时；若此期间真实流量为零，以合成结果标记 `TECH_VERIFIED`，并在真实流量恢复后追加 24 小时确认窗。」
- **闭包触发条件**：D6 冻结时由业务方确认低流量场景的验收退出条件。

## 2. 目标、非目标与用户可见结果

### 2.1 目标

在单一 V3 分支内，为 ISSUE-0034 的非数据库安全基线建立可复现、可独立审计的关闭路径，覆盖：

1. 认证、会话、Cookie、CSRF、Origin/CSP 和安全响应头；
2. 身份对象访问控制、IDOR、跨账号枚举和未授权读取/写入；
3. 输入输出、注入、SSRF、模板/命令边界和错误信息最小化；
4. Secret 引用、日志脱敏、审计、告警、依赖与滥用/限流控制；
5. CloudBase、Worker、源站、域名入口的边界验证；
6. 联系方式、未成年人字段、公开 DTO、删除/恢复和审计数据的最小化。

### 2.2 非目标

- 不包含数据库迁移、数据库备份/RPO/RTO/恢复演练或任何数据库架构改变。
- 不包含任何其他 Issue 的实现、验收或关闭；本 Spec 唯一 Issue 只有 ISSUE-0034。
- 不承诺绝对安全、零风险、法律合规结论或永久有效的供应商/平台能力。
- 不重新解释已关闭事项的范围，不把既有部署编号、Worker 版本号或平台版本号推导为 Git SHA。
- 不授权修改代码、UI、Issue canonical/state、Cloudflare、CloudBase、密钥、生产流量或部署配置。
- 不把本稿的安全建议值、样例阈值或观察时长写成业务方已确认的生产承诺。

### 2.3 用户可见结果

只有在所有适用门禁通过后，用户才应看到以下结果：

- 登录、会话续期和退出行为稳定：未认证请求统一返回 401；对按对象标识寻址的资源，不存在、已删除、非 owner 和不可见统一返回 404，并使用同一规范化响应体与同一可接受时延类别；403 只用于已认证、非对象存在性敏感的动作权限拒绝，且必须由冻结接口契约明确允许。不得由状态码、响应体或时延泄露对象存在性、联系方式或内部实现细节。
- 家长、学生、老师只能读取和修改授权范围内的对象；跨账号访问、批量枚举、伪造身份和越权写入被拒绝。
- 公开页面只展示已批准的最小字段，不显示未授权联系方式、详细地址、未成年人敏感细节、Secret、内部 ID 或原始审计内容。
- 安全策略失败时显示不泄露风控细节的统一提示；系统保持拒绝、人工处置或只读降级，不以“方便用户”为由绕过控制。
- 发生异常时，平台可定位责任与时间并触发停止/回滚；用户不会因内部日志或回滚细节泄露而承担额外隐私风险。

以上是验收目标，不是当前已实现或已生产通过的结论。

- 测试默认使用合成或脱敏账号、联系方式和未成年人示例；不把真实孩子姓名、学校、精确地址、电话、微信、聊天正文或 Secret 写入测试输出。
- 未成年人相关文本仅验证最小化、授权读取、公开 DTO 和日志脱敏；本 Spec 不定义新的监护、法务或年龄判定规则。
- 联系方式在没有明确授权和既有业务规则允许前，不进入公开列表、错误信息、监控标签、第三方请求或共享截图。
- 安全日志记录必要的时间、主体、对象、动作和结果，但不记录 token、Cookie、Secret、完整联系方式或可还原的未成年人原文。
- 认证失败、权限不确定、告警系统不可用、审计写入失败或配置来源不明时，默认 fail-closed：拒绝敏感动作、保留最小审计并进入人工/运维处理。

## 7. 失败路径、停止条件、回滚与重开

### 7.1 失败路径

认证绕过、跨账号读写、联系方式/Secret 泄露、关键安全头缺失、伪造源站头可通过、审计/告警失效、不可解释的生产 5xx 增长或回滚不可复现，均视为阻断失败。业务误拒、告警风暴、容量下降和可达性异常也必须记录影响面，不得用隐藏错误或放宽策略消除指标。

### 7.2 停止条件

任一零容忍负例失败、独立复核为 REWORK_REQUIRED、生产 provenance 无法精确绑定、回滚入口不可验证、Secret 有明文暴露风险、业务确认缺失或发生未授权跨 Issue 修改时，立即停止当前阶段，不继续部署或 Issue 关单。

### 7.3 回滚

回滚目标只能是最近一个已验收且有精确 receipt 的版本/配置；回滚前保存审计和观测证据，回滚后验证登录、权限、公开字段、告警和数据隔离。不得把“保留旧入口”“配置可切回”表述成已执行过真实回滚。任何回滚涉及平台、密钥或生产写入，都必须由相应 owner 在单独授权窗口执行。

### 7.4 重开

以下任一情况重开 ISSUE-0034 或维持其 Open：生产发现新 P0/P1；对象越权或联系方式/未成年人披露；安全基线变更后没有重新观察；回滚或停止条件失效；证据 provenance 被更改；业务方撤销风险接受；或后续实现扩大了本 Issue 的非数据库范围。重开由 Issue 管理员依据新证据决定，本稿不自动改状态。

## 8. 可测试验收标准

V3 只有在下列条件全部满足后，才可提交产品/业务/Issue 关闭链路：

1. 所有认证、会话、Cookie、CSRF、Origin/CSP、IDOR、跨账号、枚举、注入、SSRF、源站隔离和安全头用例均有可复现结果；
2. 状态码契约可复现：未认证为 401；对象不存在、已删除、非 owner、不可见均为统一 404，规范化响应体相同且落入同一经独立复核的时延类别；403 只出现在冻结契约允许的非对象动作权限场景；批量枚举不能据状态码、正文、Header 或时延区分对象存在性；
3. CloudBase/Worker/公开域名入口矩阵逐项有证据：批准公开域名经正确 Worker、TLS 和 canonical 路由到达应用；经批准的 apex/www 重定向在适用时保留 path/query；未知或未绑定 Host fail-closed 且不返回应用内容；绕过 Worker 直连 CloudBase/源站、伪造 Host、源站证明或 Worker Header 均被拒绝；不存在绕过 Worker、CloudBase 或源站隔离的替代公开入口；
4. 零容忍负例全部 fail-closed，且没有客户端状态、错误重试、伪造 Header 或公开 URL 绕过服务端控制；
5. 公开 DTO、错误文案、日志、审计、监控和截图没有 Secret、完整联系方式、未成年人敏感原文或未授权对象；
6. 限流、告警、升级、停止、恢复和回滚均有责任 owner 与 receipt；
7. 独立技术/安全复核明确给出适用范围内 P0/P1/P2=0/0/0，且不把未测范围写成通过；

9. 产品经理完成用户可见流程验收，业务方逐项确认隐私、失败文案、误拒、运营边界和残余风险；

### 2.6 RED-first 测试与故障注入

第一条 RED（计划名称）：`migration target adapter is not selected and schema/relation reconciliation cannot prove 100 percent equivalence`。在目标 provider 未冻结的当前状态，测试应明确阻止写入，而不是选择默认 MySQL 或保留现状后伪造 GREEN。

门禁通过后的最小测试清单：

1. `schema map rejects unknown collection/field and unsafe projection`：fixture 覆盖所有八类对象、正文字段、未知字段和字段类型漂移。
2. `reconciles every owner id version and relation with stable double snapshots`：父需求/老师资料各一组、两条 conversation、历史消息、交换 request/profile、五条审计链；对账计数和 digest 必须相等。
3. `fails closed on duplicate id orphan relation legacy conflict or pagination truncation`：分别注入 duplicate、orphan message/request、unknown sourceType、D8 legacy、cursor 中断。
4. `backup restore round trip preserves versions and audit chain`：备份 hash、恢复 hash、owner/version/关系逐项相等；恢复失败时不得进入 cutover。
5. `short-write gate blocks all source writes and records no dual-write`：正常窗口、硬上限、客户端中断、目标 set 后 throw、源读回不一致均验证写次数和 rollback receipt。
6. `idempotent migration replays requestId without duplicate target`：同 requestId 重放返回原结果；不同 requestId 不能覆盖已有 target ID；并发两个 worker 只允许一个 lock owner。
7. `rollback restores source-only reads and never deletes legacy/audit`：回滚后源快照可读、目标写冻结、审计保留；任何 rollback 不按时间范围批量删数据。
8. `D2/D8 regression remains fail closed`：删除态消息发送、联系方式动作、legacy 记录编辑/删除/恢复均继续拒绝。

### 2.7 备份、短写、回滚与验收

- **备份：** 先做全量/增量清单，按固定投影生成加密对象和 digest；备份 receipt 记录范围、时间、计数、版本分布、加密/保留策略和恢复演练结果，不记录正文。
- **短写：** 在业务确认的窗口先停止新写请求并返回明确维护/重试语义；禁止用前端 flag 代替服务端单源锁。目标≤5分钟是建议目标，15分钟是当前技术硬上限候选；未确认前不得启用。
- **切换：** `PLANNED → FROZEN → SNAPSHOT_VERIFIED → TARGET_VERIFIED → SINGLE_SOURCE_SWITCHED → OBSERVING → ACCEPTED`；每步需要 receipt 和人工批准。
- **回滚触发：** 对账差异、数据损失/重复、关系断裂、version 非单调、D2/D8 门控回退、备份无法恢复、观察期关键错误、短写超时，任一出现立即停止新目标写并回到最后 source-only 版本。
- **业务验收：** 100% 对账、无未授权写、备份可恢复、72小时观察、业务确认，全部满足才可关闭 S1。

### 3.4 RED-first 测试清单

首条 RED：`a revoked session or rotated AUTH_SESSION_SECRET is still accepted by a write route`。下一条并列 RED：`two concurrent verify requests can both consume the same email code`。它们必须在现状上真实失败，不能先降低断言。

完整本地测试契约：

1. `session rotation rejects old key and revocation epoch`：旧签名、撤销 epoch、跨租户/跨用户 cookie 均拒绝；合法新会话仍可用。
2. `every write route rejects missing or foreign Origin`：Origin 缺失、不同 host、非安全方法、OPTIONS 语义分别覆盖；不能只测 middleware。
3. `body and nested field limits fail before business handler`：超 bytes、超数组/深度、Unicode NFKC 边界、恶意对象和重复字段；业务 writer 调用数为0。
4. `email code consume is atomic under concurrent verification`：两个并发请求仅一个 `usedAt`/登录成功，另一个得到明确失败；没有第二次邮件或第二个用户写。
5. `CSP/HSTS/cookie contract has no unreviewed unsafe relaxation`：逐 header 断言 unsafe-inline/eval、max-age、Secure/HttpOnly/SameSite；任何放宽需要显式 allowlist。
6. `layered limiter separates account ip device and action windows`：同账号多 IP、同 IP 多账号、设备 session 重放、验证码发送和登录动作分别计数；超过任一层 fail closed。
7. `correlation and audit redaction never retain secret/contact/minor正文`：日志字段白名单、敏感 key/正文/Authorization 扫描、告警 sink 不输出原文。
8. `backup restore receipt proves RPO/RTO and no partial restore`：注入备份缺块、digest 不符、恢复中断，均阻止 accept。
9. `minor public projection and retention policy`：公开列表/详情只返回批准字段；删除/过期/legacy 读隔离；未获业务批准的字段默认拒绝公开。
10. `IDOR/Origin/contact negative matrix`：非 owner、未登录、伪 source、跨会话、删除态请求统一安全语义；联系方式卡和授权 profile 不泄露。
11. `dependency/SBOM and SQL/SSRF inventory`：静态结果可追溯，未知依赖/URL/SQL sink fail review，不把“未发现”写成“零风险”。

## 4. S3 — ISSUE-0032 邮箱验证码发送前服务端人机验证

### 4.1 目标与非目标

**目标：** 在验证码邮件发送前，由服务端对 provider-neutral challenge 做完整核验、一次性消费和分层限流；任何 token 缺失、伪造、过期、重放、hostname/action/context 不匹配、超时、provider 不可达或 secret 缺失均 fail closed，邮件发送计数为0。

**非目标：** 不把浏览器 checkbox/隐藏字段当授权；不在客户端验证后直接发邮件；不把 Turnstile 或任何供应商写死在领域层；不在缺少业务/外部凭据时启用生产 provider，不修改登录页“账号密码登录”方案。

### 4.2 当前接入点与接口

当前验证码链路：

- `Code文档/server/email-auth.ts:L1-L117,L233-L430`：验证码 TTL、attempts、一次性标记和邮件发送领域逻辑；当前约5分钟 TTL、5次尝试、60秒冷却，实际消费与用户写入存在分步路径。
- `Code文档/server/email-auth-api.ts:L25-L47,L60-L125`：`POST_SEND_CODE` 和 `POST_LOGIN` 的请求/失败状态映射。
- `Code文档/app/api/auth/email/send-code/route.ts`：发送 route 组装处，必须在调用 email delivery 前先完成 challenge/限流。
- 当前无 Turnstile/challenge route 或 provider adapter；D6 已冻结的是接口参数默认，不是生产密钥授权。

provider-neutral 接口（门禁通过后首个可实现形状）：

```ts
type ChallengeContext = {
  expectedHostname: string;
  expectedAction: "email_send_code";
  requestId: string;
  accountKey: string;
  ipDigest: string;
  deviceKey: string;
  issuedAt: string;
  now: number;
};

type ChallengeResult =
  | { ok: true; provider: "test" | "turnstile" | "equivalent"; tokenId: string; hostname: string; action: string; score?: number }
  | { ok: false; reason: "missing" | "invalid" | "expired" | "replay" | "hostname" | "action" | "timeout" | "unreachable" | "secret-missing" | "rate-limited" };

interface ChallengeVerifier {
  verify(input: { token: string; context: ChallengeContext }): Promise<ChallengeResult>;
}
```

真实 provider adapter 只接收 token 和最小 context，固定 `siteverify` hostname/action/timeout；不向领域层暴露 Secret 或原始响应。测试 adapter 是模块私有的 test-only factory，生产路径固定加载 provider 配置并 fail closed。

### 4.3 D6 参数与服务端顺序

D6 当前技术默认：生产 hostnames 仅 `ungraduedu.eu.cc`、`www.ungraduedu.eu.cc`；action `email_send_code`；provider token TTL 候选300秒，应用 freshness≤120秒；服务超时目标2秒、硬上限5秒；account 3次/15分钟、10次/24小时；IP 10次/15分钟；不向 provider 发送 `remoteip`；IP HMAC digest 保留24小时；测试/生产 widget 和 secret 分离；secret rotation 候选90天；语言 auto/zh-cn。它们是已冻结技术默认/建议，实际生产启用仍需 D6/D7 与业务门禁。

发送顺序必须固定：

1. 解析并限制 request body；建立 correlation/requestId；服务端取得认证主体、匿名 IP HMAC digest、设备/session/action key。
2. 校验 token 存在、长度/字符集安全；调用 `ChallengeVerifier`，验证 provider `success`、hostname、action、TTL/issuedAt、context 和服务超时。
3. 以 `challengeId + account + action + window` 的服务端原子记录消费 token；重放或并发第二次失败。
4. 依次检查 account/IP/device/session/action 计数；任一超限直接返回脱敏错误。
5. 只有上述全部成功才调用现有 email code 生成/发送。邮件发送前失败路径的 `emailDelivery.callCount` 必须为0。
6. 邮件发送结果和验证码文档写入必须使用 requestId/idempotency 语义；失败不泄露 provider 原文、邮箱正文或 challenge token。

### 4.4 RED-first 测试、fixture 与故障注入

首条 RED：`missing or fake challenge still invokes email delivery`。当前代码没有 challenge seam，fixture 应证明邮件 mock 被调用一次；实现后应转为0并返回明确 fail-closed 错误。

1. `send-code requires server verified challenge before delivery`：缺 token、checkbox 伪造、格式异常；delivery=0。
2. `provider result requires hostname action success and fresh issuedAt`：hostname/action 不符、TTL 边界、未来时间、provider success=false；delivery=0。
3. `token is atomically consumed once under concurrent requests`：并发两次只一个成功；第二次 replay；delivery 最多一次。
4. `timeout unreachable or missing secret fails closed`：2秒目标、5秒硬上限、Abort；provider 失败不触发 email。
5. `layered rate limits fail closed and do not leak account existence`：account/IP/device/session/action 各层边界、跨账号同 IP、同账号换 IP；错误语义一致。
6. `context binding rejects cross-host action account or request replay`：固定 hostname/action/account/requestId；跨上下文 token 不能换用途。
7. `successful challenge preserves current code TTL and one-time login semantics`：现有5分钟/attempts/冷却边界保留；验证码消费并发只有一个成功。
8. `audit/log redaction excludes token email code and contact fields`：输出 key allowlist、token/邮箱正文扫描、correlation 可追踪但不可还原。
9. `provider-neutral adapter has no production network in local tests`：fake provider 之外的 network 方法未调用；test/prod key 配置分离且缺任一 secret fail closed。
10. `accessibility and failure UI`：错误 aria/live region、重试语义、无障碍 label；不把客户端勾选成功显示为服务端授权。

# MVP 家教对接平台 Spec

日期：2026-06-19
状态：初版
阶段：MVP

## 1. 背景与目标

本项目是面向东莞大学城及周边区域的家教双边平台 MVP，连接需要家教的家长与想做家教的大学生。第一版目标不是做完整交易平台，而是验证一个可自助运转的最小功能闭环：

家长发布需求，大学生发布家教信息，双方可搜索筛选对方信息，进入站内聊天，在双方同意后交换联系方式。

MVP 首要验收标准是核心功能流程可以完整走通且不出现异常，尤其要保证联系方式和私密数据不会被未授权访问。

## 2. 产品定位

### 2.1 一句话定位

一个面向本地家教供需的自助撮合平台，让家长和大学生通过结构化信息、筛选、聊天和双向同意交换联系方式完成初步对接。

### 2.2 MVP 范围

第一版采用“标准 MVP 版”：

- 手机号注册登录。
- 登录后主页面提供家长端和大学生端身份入口。
- 家长发布家教需求。
- 大学生发布个人家教信息。
- 双方可搜索筛选对方发布的信息。
- 双方可进入基础实时文字聊天。
- 双方可在聊天中请求交换联系方式。
- 对方同意前必须二次确认。
- 同意后聊天界面展示双方已存档联系方式。
- 大学生可填写能力说明，并可选上传证明图片。
- 使用腾讯云 CloudBase 免费额度优先完成数据端、后端和部署验证。

### 2.3 不做范围

MVP 不包含：

- 在线支付。
- 平台抽佣。
- 人工撮合。
- 人工审核发布内容。
- 自动推荐算法。
- 复杂排课。
- 试课记录。
- 成交追踪。
- 评价体系。
- 已读/未读状态。
- 图片、语音、撤回等复杂聊天能力。
- 举报、拉黑、封禁后台。
- 全国多城市复杂地址系统。
- 每项能力强制绑定图片证明。

## 3. 用户角色

### 3.1 访客

未登录用户。可访问首页和平台说明内容，是否允许浏览公开列表由后续实现阶段根据安全和转化策略决定，但发布、聊天、请求交换联系方式必须登录。

### 3.2 注册用户

通过手机号注册和登录的平台用户。一个手机号账号可以同时使用家长端和大学生端能力。

### 3.3 家长端用户

有找家教需求的用户。可发布家教需求、搜索大学生家教信息、发起聊天、请求交换联系方式。

### 3.4 大学生端用户

想做家教的大学生。可发布个人家教信息、搜索家长需求、发起聊天、请求交换联系方式。

## 4. 核心业务闭环

### 4.1 家长找大学生

1. 用户用手机号注册或登录。
2. 在主页面选择“我要找家教”。
3. 家长填写并发布结构化需求。
4. 家长进入家教信息广场。
5. 家长按科目、学段、价格、性别筛选大学生家教信息。
6. 家长查看某个大学生家教信息详情。
7. 家长发起站内聊天。
8. 双方通过文字聊天沟通具体情况。
9. 任意一方请求交换联系方式。
10. 对方点击同意后，系统弹出二次确认。
11. 二次确认通过后，双方在聊天界面看到彼此存档联系方式。

### 4.2 大学生找需求

1. 用户用手机号注册或登录。
2. 在主页面选择“我要做家教”。
3. 大学生填写并发布个人家教信息。
4. 大学生进入需求广场。
5. 大学生按科目、学段、预算、性别偏好筛选家长需求。
6. 大学生查看需求详情。
7. 大学生发起站内聊天。
8. 双方通过文字聊天沟通具体情况。
9. 任意一方请求交换联系方式。
10. 对方点击同意后，系统弹出二次确认。
11. 二次确认通过后，双方在聊天界面看到彼此存档联系方式。

## 5. 页面范围

### 5.1 首页/主页面

首页应承担身份入口和平台主导航职责。

核心模块：

- 平台名称和简短说明。
- “我要找家教”入口。
- “我要做家教”入口。
- 需求广场入口。
- 家教信息广场入口。
- 个人页面入口。
- 平台规则/费用说明入口。
- 反馈/联系客服入口。

登录后，用户应能回到主页面重新选择身份。

### 5.2 手机号注册登录页

核心能力：

- 手机号注册。
- 手机号登录。
- 验证码或其他适合 CloudBase 的手机号验证方式。
- 登录后进入主页面。

安全要求：

- 登录态必须由后端可信机制维护。
- 不能仅依赖前端判断用户身份。

### 5.3 个人页面

核心模块：

- 基础账号信息。
- 家长端资料入口。
- 大学生端资料入口。
- 联系方式管理入口。
- 我发布的需求。
- 我发布的家教信息。
- 我的聊天。

### 5.4 联系方式管理页

用户维护专门用于交换的存档联系方式。

字段：

- 手机号：必填。
- 微信号：选填。

规则：

- 存档联系方式默认不公开。
- 未完成双方授权前，任何页面和接口都不得返回对方存档联系方式。
- 用户没有填写手机号时，不能完成联系方式交换同意动作。

### 5.5 家长发布需求页

采用结构化发布，不做自由发帖。

字段：

- 希望老师性别：固定选项。
- 所需科目：固定选项，多选。
- 学段/年级：固定选项。
- 可接受预算区间：必填，单位为元/小时。
- 可上课时间段：固定选项，多选，例如周一至周日搭配上午、中午、下午、晚上。
- 地址：固定选项选择省、市、镇街、区等层级。
- 具体位置：最多填写到小区或村，不填写门牌号。
- 孩子简介：最多 100 字。

规则：

- 孩子简介不得填写手机号、微信号或详细门牌地址。
- 具体上课时间和详细地址由双方聊天后确认。
- MVP 不做人工审核，但应做基础字段校验和敏感信息校验。

### 5.6 大学生发布家教信息页

字段：

- 性别：固定选项。
- 学校：填写或固定选项，MVP 可先从东莞大学城相关学校开始。
- 专业：文本填写。
- 可教科目：固定选项，多选。
- 可教学段：固定选项，多选。
- 可上课时间段：固定选项，多选。
- 按学段和科目填写课时费区间。
- 能力说明：文字填写。
- 证明图片：可选上传。

规则：

- 能力说明可包含成绩、证书、擅长科目、过往家教经验。
- MVP 不强制每项能力都上传证明图片。
- 上线后根据家长反馈和虚假信息情况，再决定是否升级为每项能力必须绑定证明图片。

### 5.7 需求广场

面向大学生浏览家长需求。

筛选条件：

- 科目。
- 学段。
- 预算区间。
- 性别偏好。

列表展示：

- 科目。
- 学段。
- 区域。
- 预算区间。
- 性别偏好。
- 孩子简介摘要。

不做：

- 时间段筛选。
- 智能排序。
- 地图找需求。

### 5.8 家教信息广场

面向家长浏览大学生家教信息。

筛选条件：

- 科目。
- 学段。
- 课时费区间。
- 性别。

列表展示：

- 姓名或昵称。
- 性别。
- 学校。
- 专业。
- 可教科目。
- 可教学段。
- 课时费区间摘要。
- 能力说明摘要。

不做：

- 时间段筛选。
- 智能推荐。
- 认证排序。

### 5.9 详情页

需求详情页展示家长需求完整结构化信息，但不展示家长联系方式。

家教信息详情页展示大学生家教信息、能力说明和可选证明图片，但不展示大学生联系方式。

详情页提供发起聊天入口。

### 5.10 聊天页

MVP 只做基础实时文字收发。

核心能力：

- 发送文字消息。
- 按时间展示消息。
- 展示当前聊天对象基础信息。
- 发起“请求交换联系方式”。
- 处理对方的交换联系方式请求。
- 点击同意后弹出二次确认。
- 二次确认通过后展示双方存档联系方式。

不做：

- 已读/未读。
- 撤回。
- 图片消息。
- 语音消息。
- 表情包。
- 消息通知中心。
- 拉黑举报。

## 6. 数据对象

### 6.1 用户

关键字段：

- 用户 ID。
- 手机号。
- 创建时间。
- 最近登录时间。

### 6.1.1 账号异常状态

MVP 需要定义基础账号异常状态：

- 用户注销或账号不可用后，其已发布需求和家教信息应停止公开展示。
- 已存在聊天会话保留历史消息，但聊天页应展示“对方账号已不可用”，并禁止继续发送新消息。
- 已发出的联系方式交换请求在对方账号不可用后自动失效。

### 6.2 存档联系方式

关键字段：

- 所属用户 ID。
- 联系手机号。
- 微信号。
- 更新时间。

### 6.3 家长需求

关键字段：

- 需求 ID。
- 发布用户 ID。
- 老师性别偏好。
- 科目列表。
- 学段/年级。
- 预算最低值。
- 预算最高值。
- 可上课时间段。
- 地址层级。
- 小区或村。
- 孩子简介。
- 创建时间。
- 状态。

### 6.4 大学生家教信息

关键字段：

- 家教信息 ID。
- 发布用户 ID。
- 性别。
- 学校。
- 专业。
- 可教科目。
- 可教学段。
- 可上课时间段。
- 学段科目课时费区间。
- 能力说明。
- 证明图片列表。
- 创建时间。
- 状态。

### 6.5 聊天会话

关键字段：

- 会话 ID。
- 参与用户 A。
- 参与用户 B。
- 关联来源类型：需求或家教信息。
- 关联来源 ID。
- 创建时间。

### 6.6 聊天消息

关键字段：

- 消息 ID。
- 会话 ID。
- 发送用户 ID。
- 文本内容。
- 创建时间。

### 6.7 联系方式交换请求

关键字段：

- 请求 ID。
- 会话 ID。
- 发起用户 ID。
- 接收用户 ID。
- 状态：待处理、已同意、已拒绝。
- 二次确认时间。
- 创建时间。

规则：

- 只有已同意且完成二次确认后，聊天界面才能展示双方存档联系方式。
- 请求发起方可以在对方处理前撤回请求。
- 待处理请求从创建时间起算，7 天未处理则自动过期；后续聊天活跃度不重置过期时间。
- 请求过期、被拒绝或被撤回后，双方仍可重新发起新的联系方式交换请求。
- 已过期或已撤回的请求不能再被同意。
- 发起方或接收方任一账号注销或不可用后，待处理交换请求自动失效，另一方应看到对应状态提示。
- 关联需求或家教信息被删除后，已有聊天会话保留，但不能再从被删除内容发起新的聊天或交换请求。

## 7. 权限与安全要求

### 7.1 登录要求

以下动作必须登录：

- 发布家长需求。
- 发布大学生家教信息。
- 发起聊天。
- 发送消息。
- 请求交换联系方式。
- 同意交换联系方式。
- 查看已授权交换的联系方式。

### 7.2 数据归属

后端必须校验数据归属：

- 用户只能修改自己发布的需求。
- 用户只能修改自己发布的家教信息。
- 用户只能查看自己参与的聊天会话。
- 用户只能发送消息到自己参与的会话。
- 用户只能处理发给自己的联系方式交换请求。

### 7.3 防越权要求

必须防止：

- 修改 URL 或 ID 查看他人聊天。
- 修改 URL 或 ID 查看他人未授权联系方式。
- 调用接口修改他人需求或家教信息。
- 枚举用户 ID、需求 ID、会话 ID 获取私密数据。
- 前端隐藏按钮但后端无权限校验。

### 7.4 联系方式保护

联系方式保护是 MVP 核心安全要求：

- 存档联系方式默认不公开。
- 需求详情和家教信息详情不得返回联系方式。
- 聊天接口在未授权前不得返回对方联系方式。
- 同意交换联系方式必须二次确认。
- 二次确认通过后，只向该会话双方展示联系方式。

### 7.5 发布内容校验

MVP 不做人工审核，但要做基础自动校验：

- 必填字段不能为空。
- 孩子简介最多 100 字。
- 孩子简介不得出现手机号、微信号等联系方式。
- 地址不得填写详细门牌号。
- 预算区间和课时费区间必须合理。

### 7.6 最小反馈入口

MVP 不做完整举报、拉黑、封禁后台，但需要提供最小反馈入口。

要求：

- 首页、个人页面或聊天页至少有一个“反馈/联系客服”入口。
- 入口可以是邮箱、表单或外部收集链接。
- 反馈入口用于处理联系方式滥用、虚假信息、骚扰和功能异常。
- MVP 不要求开发完整工单后台，但必须在页面中明确反馈接收渠道。
- 反馈由项目运营负责人或开发负责人人工查看处理。
- 页面文案应说明反馈将在 3 个工作日内人工查看；这不是正式 SLA，但作为 MVP 阶段内部处理承诺。

## 8. 技术栈与系统架构

### 8.1 技术栈结论

MVP 采用以下技术栈作为默认开发方向：

- 前端框架：Next.js。
- 编程语言：TypeScript。
- UI 层：React 组件化开发。
- 样式方案：优先使用 Tailwind CSS，具体组件库可在开发前技术验证中确定。
- 数据端：腾讯云 CloudBase 数据库。
- 后端能力：腾讯云 CloudBase 云函数或云托管 API。
- 用户认证：手机号注册登录，优先验证 CloudBase 可用认证能力；如 CloudBase 手机号能力不足，则使用云函数对接国内短信验证码服务。
- 文件存储：腾讯云 CloudBase 存储，用于大学生证明图片。
- 聊天能力：MVP 默认采用后端 API 校验后的轮询或准实时方案；只有在 CloudBase 数据库安全规则经过专项验证后，才允许使用客户端直连实时监听。
- 部署环境：腾讯云 CloudBase 云托管或 Web 应用托管，优先使用免费额度。
- 代码管理：Git + GitHub。

### 8.2 前端技术要求

前端使用 Next.js + TypeScript 实现。

要求：

- 页面使用 App Router 或开发时确认的 Next.js 主流路由方式。
- 表单必须有前端校验，但前端校验不能替代后端校验。
- 页面组件按业务模块拆分，例如登录、身份入口、需求发布、家教信息发布、广场筛选、聊天、联系方式交换。
- 所有与权限、联系方式、聊天相关的敏感动作必须通过后端接口完成，不能只在前端本地处理。
- 筛选条件使用 URL query 或明确的状态管理方式，便于分享、刷新和回溯。

### 8.3 后端技术要求

后端优先使用 CloudBase 云函数或云托管 API，不单独自建传统服务器。

后端负责：

- 手机号登录或登录态校验。
- 用户身份与数据归属校验。
- 家长需求创建、更新、查询。
- 大学生家教信息创建、更新、查询。
- 聊天会话创建和消息写入。
- 联系方式交换请求、同意、拒绝和二次确认。
- 未授权联系方式过滤。
- 发布内容基础校验。
- 文件上传授权和证明图片访问权限控制。

后端必须保证：

- 所有写操作校验当前登录用户。
- 所有读取私密数据的接口校验访问权限。
- 联系方式字段默认不返回。
- 只有完成双方授权和二次确认后，才允许在对应聊天会话中返回双方存档联系方式。

### 8.4 数据库技术要求

数据库优先使用 CloudBase 数据库。

核心集合或表：

- users：用户账号。
- contact_profiles：存档联系方式。
- parent_needs：家长需求。
- tutor_profiles：大学生家教信息。
- conversations：聊天会话。
- messages：聊天消息。
- contact_exchange_requests：联系方式交换请求。
- local_regions：本地地址选项。
- subject_options：科目选项。
- grade_options：学段/年级选项。

数据设计要求：

- 所有业务数据必须记录 ownerUserId 或明确的参与用户 ID。
- 聊天会话必须记录双方参与者。
- 消息必须绑定会话和发送者。
- 联系方式交换请求必须绑定会话、发起方和接收方。
- 地址、科目、学段等固定选项应使用可维护的基础数据，不写死在多个页面里。
- MVP 阶段不做基础数据管理后台，地址、科目、学段等基础数据由开发或运营人员直接维护数据库或种子数据文件。
- 新增科目、调整地址层级、调整学段选项时，必须同步更新基础数据并完成一次发布/筛选回归验证。

### 8.5 认证与权限方案

MVP 使用手机号注册登录。

权限边界：

- 未登录用户不能发布、聊天、请求交换联系方式。
- 用户只能修改自己发布的需求。
- 用户只能修改自己发布的家教信息。
- 用户只能进入自己参与的聊天会话。
- 用户只能处理发给自己的联系方式交换请求。
- 用户不能直接读取对方存档联系方式。

实现要求：

- 权限必须在 CloudBase 安全规则、云函数或云托管 API 中校验。
- 不允许只依赖前端隐藏按钮实现权限控制。
- 对 IDOR/越权引用攻击必须做专项验证。
- 如果某个功能采用客户端直连 CloudBase 数据库，必须把数据库安全规则纳入权限测试范围。
- MVP 聊天默认不采用未经安全规则验证的客户端直连数据库读取。

### 8.6 聊天技术方案

MVP 聊天只支持基础文字收发。

推荐实现：

- conversations 记录聊天双方和来源对象。
- messages 记录文本消息。
- 前端进入聊天页后通过后端接口轮询或准实时获取当前 conversation 的 messages。
- 发送消息时由后端校验发送者是否属于该 conversation。
- 不实现已读、未读、撤回、图片、语音、推送通知。

验收要求：

- 双方能看到新消息。
- 非会话参与者无法读取消息。
- 消息按创建时间排序。
- 联系方式交换系统与聊天会话绑定。
- 在普通网络环境下，新消息发送后应在 5 秒内被对方看到。
- MVP 初始性能基线为同时在线 50 人时核心流程可正常使用。

### 8.7 文件存储方案

MVP 文件上传只用于大学生能力证明图片。

要求：

- 使用 CloudBase 存储或腾讯云可访问的国内存储能力。
- 限制文件类型，例如 JPG、PNG、WebP。
- 限制单张图片大小。
- 图片记录必须绑定上传用户和家教信息。
- 非授权场景下不得暴露可枚举的永久公开链接。

不做：

- 聊天图片上传。
- 视频上传。
- 文件上传。
- 自动 OCR 或图片内容审核。

### 8.8 部署与运行环境

部署优先使用腾讯云 CloudBase 免费额度。

需要准备：

- 腾讯云账号。
- CloudBase 环境。
- CloudBase 数据库。
- CloudBase 存储。
- 云函数或云托管服务。
- 短信验证码能力或替代登录验证能力。
- 本地地址基础数据。

必要环境变量待技术验证后确定，预计包括：

- CloudBase 环境 ID。
- CloudBase 访问配置。
- 登录认证相关配置。
- 短信服务配置。
- 文件存储配置。
- 应用运行环境标识。

真实密钥不得提交到 Git 仓库。

### 8.9 本地开发与验证命令

当前仓库尚未创建业务代码，具体命令需在技术验证和项目初始化后补充。

后续代码项目至少应提供：

- 安装依赖命令。

- `dev`：本地开发。

### 8.10 测试技术要求

测试框架在项目初始化时确定，但 MVP 必须覆盖关键业务和安全路径。

建议测试方向：

- 单元测试：表单校验、价格区间校验、联系方式展示判断。
- 接口测试：发布、筛选、聊天、交换联系方式。
- 权限测试：越权访问聊天、越权读取联系方式、越权修改他人数据。
- 端到端测试：家长发布需求到双方交换联系方式的完整流程。
- 基础压测：模拟 50 个并发用户执行发布、筛选、聊天、交换联系方式等核心流程，验证系统在该负载下正常响应。

建议候选工具：

- 单元测试：Vitest。
- 端到端测试：Playwright。
- 轻量压测：k6 或 Artillery。

### 8.11 技术验证重点

进入开发前必须验证：

- 开发主体是个人还是公司，是否满足国内短信验证码服务商资质和模板报备要求。
- CloudBase 是否能满足手机号注册登录，且该能力是否对当前开发主体开放。
- 如果 CloudBase 手机号认证不可用，是否存在合规的个人开发者可用短信方案。
- 如果短信验证码短期不可用，M1 可采用临时测试登录方案用于本地或测试环境开发。
- 临时测试登录方案不得出现在生产环境配置中。
- 正式上线前必须替换为合规手机号短信登录。
- CloudBase 权限规则和云函数能否可靠支持数据归属校验。
- CloudBase 是否能支撑基础实时或准实时文字聊天。
- 聊天最终采用“后端 API 轮询/准实时”还是“客户端直连数据库实时监听”；如果采用后者，必须单独完成数据库安全规则设计和权限测试。
- CloudBase 存储是否适合证明图片上传和权限控制。
- CloudBase 免费额度是否足够 MVP 早期使用。
- Next.js 部署到 CloudBase 的流程是否稳定。
- 中国大陆访问速度和稳定性是否满足 MVP 要求。

### 8.12 暂不采用

MVP 暂不采用：

- Supabase 等海外优先的数据服务。
- 独立自建服务器。
- 独立 PostgreSQL/MySQL RDS。
- 复杂微服务架构。
- 第三方 IM SDK。
- 在线支付能力。

原因：

- 当前核心目标是用最低成本打通功能闭环。
- 数据服务需要保证中国大陆访问稳定。
- MVP 聊天能力较轻，不需要引入完整 IM 系统。
- 支付和交易不属于当前版本范围。

## 9. 验收标准

MVP 首要验收标准是功能闭环稳定可走完。

### 9.1 家长流程验收

- 用户可以手机号注册登录。
- 用户可以从主页面进入家长端。
- 用户可以发布结构化家教需求。
- 发布时必填字段校验正常。
- 孩子简介超过 100 字时阻止提交。
- 家长可以浏览大学生家教信息广场。
- 家长可以按科目、学段、价格、性别筛选。
- 家长可以进入家教信息详情。
- 家长可以发起聊天。
- 家长可以请求交换联系方式。
- 对方同意并二次确认后，家长可以看到双方存档联系方式。

### 9.2 大学生流程验收

- 用户可以从主页面进入大学生端。
- 用户可以发布家教信息。
- 用户可以按学段和科目填写课时费区间。
- 用户可以填写能力说明。
- 用户可以可选上传证明图片。
- 大学生可以浏览需求广场。
- 大学生可以按科目、学段、预算、性别偏好筛选。
- 大学生可以进入需求详情。
- 大学生可以发起聊天。
- 大学生可以请求交换联系方式。
- 对方同意并二次确认后，大学生可以看到双方存档联系方式。

### 9.3 聊天与联系方式验收

- 双方可以实时或准实时发送文字消息。
- 新消息发送后应在 5 秒内被对方看到。
- 同时在线 50 人时，发送消息、拉取消息和交换联系方式流程应正常可用。
- 消息按时间顺序展示。
- 未同意交换联系方式前，聊天界面不展示联系方式。
- 未同意交换联系方式前，接口不返回对方联系方式。
- 点击同意交换联系方式后必须出现二次确认。
- 二次确认通过后，聊天界面展示双方存档联系方式。
- 未填写必填手机号的用户不能完成同意交换联系方式动作。
- 联系方式交换请求可以在对方处理前撤回。
- 联系方式交换请求 7 天未处理应自动过期。
- 7 天过期从请求创建时间起算，不因后续聊天活跃而重置。
- 请求过期、撤回或拒绝后，允许重新发起新的联系方式交换请求。

### 9.3.1 异常流程验收

- 短信验证码发送失败时，页面应提示失败原因或通用失败文案，并允许用户稍后重试。
- 短信验证码发送应有频率限制，避免接口滥用。
- 聊天对象账号不可用时，聊天页应展示对方账号不可用状态，并禁止继续发送消息。
- 联系方式交换请求的发起方或接收方账号不可用时，待处理请求应自动失效。
- 需求或家教信息删除后，已有聊天历史可保留，但不能从已删除内容继续发起新聊天。
- 用户能在首页、个人页面或聊天页找到反馈/联系客服入口。
- 反馈入口应明确反馈接收渠道，并提示 3 个工作日内人工查看。

### 9.4 安全验收

- 用户不能通过修改 ID 查看他人聊天。
- 用户不能通过修改 ID 查看他人联系方式。
- 用户不能修改他人发布的需求。
- 用户不能修改他人发布的家教信息。
- 用户不能处理不属于自己的联系方式交换请求。
- 前端隐藏不等于权限控制，关键权限必须在后端校验。

## 12. 当前已确认决策

- MVP 类型：标准 MVP。
- 撮合方式：自助撮合，不做人工介入。
- 登录方式：手机号注册登录。
- 身份体系：同一个账号可选择家长端或大学生端。
- 数据端：腾讯云 CloudBase 优先，使用免费额度启动。
- 数据区域：优先保证中国大陆访问稳定。
- 聊天：基础实时文字收发，不做已读未读。
- 联系方式：个人页存档，手机号必填、微信号选填。
- 联系方式交换：聊天内请求，对方同意后还需二次确认。
- 家长发布：结构化字段，孩子简介 100 字以内。
- 大学生发布：能力文字说明加可选图片证明。
- 筛选：科目、学段、价格、性别。
- 收费：MVP 免费上线。
- 成功标准：功能闭环可完整走通且无异常。

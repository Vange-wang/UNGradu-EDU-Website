# S5 优先级与任务拆分表

日期：2026-06-30

关联任务：`RELEASE-S5-VNEXT-2026-06-30-001`

## 1. 优先级排序

| 排序 | 专项 | 优先级 | 建议动作 |
| --- | --- | --- | --- |
| 1 | 智能 Agent 客服专项 | P0 | 产品经理先出独立 Spec，不直接开发 |
| 2 | 举报 / 投诉最小闭环 | P0 | 产品经理出 Spec，代码开发员做技术方案核查 |
| 3 | 风险提示组件统一化 | P1 | 可作为低风险前端实现候选 |
| 4 | 老师资料审核状态 | P1 | 先确认展示文案与数据状态 |
| 5 | 运营后台最小版 | P1 | 依赖举报、审核、反馈数据结构 |
| 6 | 生产观察记录持续化 | P1 | 延续 S2 模板，暂不做复杂看板 |
| 7 | 支付 / 担保 / 退款 | P3 | 暂缓，需要合规和风控配套 |
| 8 | 自动推荐算法 | P3 | 暂缓，当前样本不足 |

## 2. 推荐推进顺序

### 第一步：S5 产品拆解

完成智能 Agent 客服专项和举报 / 投诉最小闭环专项的 Spec 边界。

### 第二步：S5 技术可行性核查

代码开发员只读核查现有代码数据基础，列出后续实现可能涉及的集合、API、页面和权限风险。

### 第三步：S5 Issue 规则确认

ISSUE 管理员确认新风险从 `ISSUE-0016` 起编号，无明确问题时不创建空 Issue。

### 第四步：决定 S5-DEV 是否进入实现

只有当产品 Spec 和技术核查都通过后，才决定是否把某个低风险项进入代码实现。

优先候选为：

- 风险提示组件统一化。
- 举报 / 投诉表单最小记录能力。

不建议第一批直接实现：

- 对外智能 Agent 客服。
- 人工客服工作台。
- 老师认证后台。
- 支付 / 担保 / 退款。

## 3. 当前总负责人建议

S5 当前先以“规划与可行性核查”启动，不直接进入代码开发。

若业务方希望 S5 必须产出可见功能，建议优先选择“风险提示组件统一化”或“举报 / 投诉表单最小记录能力”，不要优先做智能 Agent 客服上线。

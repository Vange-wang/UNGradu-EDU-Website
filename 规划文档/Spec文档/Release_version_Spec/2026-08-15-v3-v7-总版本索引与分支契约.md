## 4. 通用 base commit 与分支创建契约

### 4.1 精确 base 证据

每个 Vx 分支创建前必须有独立 base receipt，至少包含：

- 上一已验收版本的完整 commit SHA、ref/branch、parent 和生成时间；
- 该 commit 对应的验收版本、技术/产品/独立复核/适用生产/业务层级；
- 构建输入、Spec/Issue 绑定 hash、部署 provenance（如适用）；
- 创建前 HEAD、index、工作树、staged、unstaged、untracked 和分支图的只读快照；
- 明确没有把其他 Issue 的代码、文档 debt、测试产物、平台配置或 dirty/staged 文件带入；
- 对应的回滚 commit/配置和失败恢复触发。

上述材料合并为 `BRANCH_BASE_RECEIPT`。代码 owner 负责准备精确 SHA/ref/parent/tree、构建输入和验收版本映射；独立技术复核 owner 负责验证 commit 内容与被引用验收证据一致；项目总负责人只在两者可复读且无冲突后冻结 receipt。`ISSUE_CLOSURE_RECEIPT` 则只能由 Issue 管理员维护，记录 canonical 关单操作、证据范围、精确路径/hash 和时间。前者证明“可从哪个已验收 commit 创建分支”，后者证明“某 Issue 已被 canonical 关闭”；任何一份都不能证明另一份。

### 4.2 known HEAD 的限制

33314857da0f2d72066443965454d23fc70a16d3 只是当前接续事实。即使它已经推送或在某个平台出现，也不能据此宣称“上一已验收版本确定 base”，不能由 DeployId、BuildId、Worker version、CloudBase version、短 SHA 或时间推断 Git provenance。

### 4.3 V3 精确 base 的建立与失败回退

V3 的精确 base 不是用户凭空选择的值，必须按以下可核验程序建立：

1. 项目总负责人向代码 owner、产品/业务验收 owner 和独立技术复核 owner索取上一已验收版本的只读 provenance 包；
2. 代码 owner 从发布/验收 receipt、push/构建输入、ref/parent/tree 和分支图中列出唯一候选 commit，并提供第 4.1 节全部字段；
3. 产品/业务验收 owner 标明该候选 commit 对应的已验收范围和未通过门禁；不得把部署编号、平台版本或时间相关性当作 Git 绑定；
4. 独立技术复核 owner 逐项核对候选 commit 的 tree/输入与验收证据，确认无其他 Issue、dirty/staged/untracked 产物混入；
5. 项目总负责人仅在候选唯一、来源一致且复核通过后，登记完整 `BRANCH_BASE_RECEIPT` 的路径、SHA-256、字节数、行数、owner 和时间。

已知 HEAD `33314857da0f2d72066443965454d23fc70a16d3` 仅可作为待核对事实，不能预填为候选或已验收 base。若候选不唯一、来源冲突或 provenance 缺失，状态只能是 UPSTREAM_GATE_BLOCKED。若穷尽上述来源仍无法恢复 provenance，只能由项目总负责人向用户提出“重新建立已验收基线”或“对明确缺失项作具名风险接受”的选择；两条路径都须冻结范围、回滚点和新 receipt，并由用户明确确认。用户确认不能把一个未经核验的 SHA 直接变成已验收 base。

### 4.4 创建状态

本任务只形成作者草案，不创建、切换、合并、rebase、cherry-pick、push 或删除任何分支。分支创建必须由后续授权 owner 在对应入口门通过后执行，并保存 exact receipt。

## 9. 关闭定义与禁止结论

五个分支都必须遵循同一关闭顺序：范围/用户确认 → 精确 base → 实现或文档产物 → 本地 → 集成/预生产 → 独立复核 → 适用部署/生产 → 产品 → 业务 → Issue 管理员。任何一层缺失，分支只能报告相应阶段完成，不能报告 Issue 关闭。

不得声称：

- V3–V7 分支已经创建；
- known HEAD 已经是上一已验收版本确定 base；
- 文档审查、技术 PASS、平台部署或分支完成自动关闭 Issue；
- V4 已选择 provider 或拥有 Secret；
- V5 已拥有生产人工 owner/AI/DPA；
- V6/V7 的文档矩阵已替代功能、生产或业务证据；
- ISSUE-0031 因被延期而已解决；
- 项目 workflow 已 COMPLETE。

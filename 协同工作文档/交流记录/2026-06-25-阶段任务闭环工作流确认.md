# 2026-06-25 阶段任务闭环工作流确认交流记录

参与方：

- 项目总控制人
- 项目总负责人 Agent

## 1. 项目总控制人确认的工作流

项目总控制人确认阶段任务工作流：

1. 项目总控制人向项目总负责人下达阶段任务，例如完成 MVP 阶段的 M5。
2. 项目总负责人先让产品经理根据 MVP Spec 确认阶段规划、待完成事项和验收标准。
3. 产品经理将说明打包给代码开发员。
4. 代码开发员根据 Spec 和说明完成任务，并提交一次当前代码分支 GitHub 仓库链接。
5. 同一阶段内后续默认沿用首次提交的代码仓库链接。
6. 代码开发员表达完成后，项目总负责人把代码仓库链接交给产品经理做第 N 次审查。
7. 产品经理输出第 N 次审查验收报告 Markdown，并放入对应阶段验收报告文件夹。
8. 项目总负责人打开 Claude Code 新会话，提供代码仓库链接和产品经理审查报告，要求 Claude Code 出复核版本审查报告。
9. 项目总负责人使用 computer use 插件手动将 Claude Code 报告 `download as MD` 到同一验收报告文件夹。
10. 项目总负责人将复核报告交给产品经理。
11. 产品经理合并两份报告为最终版报告，并删除前两份中间报告入口，只保留最终报告入口。
12. 项目总负责人将最终报告交给代码开发员修复完善。
13. 按实现、审查、复核、合并最终报告、修复的循环持续推进，直到所有报告均允许验收。
14. 阶段完成后，项目总负责人提醒代码开发员和产品经理提交文件更新 Git。
15. 项目总负责人最终向项目总控制人简短总结：改了什么、验证了什么、还有什么风险。

## 2. 允许暂停询问的例外

只有以下情况项目总负责人可以暂停询问项目总控制人：

- 需要账号、密钥、外部权限。
- 有多个高风险产品决策无法合理默认。
- 继续执行可能破坏数据或产生不可逆后果。
- 需要项目总控制人手动重新部署网站或代码配置。

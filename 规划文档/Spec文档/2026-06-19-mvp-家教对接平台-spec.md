# MVP 家教对接平台 Spec

日期：2026-06-19
状态：初版
阶段：MVP

## 1. 背景与目标

本项目是面向东莞大学城及周边区域的家教双边平台 MVP，连接需要家教的家长与想做家教的大学生。第一版目标不是做完整交易平台，而是验证一个可自助运转的最小功能闭环：

家长发布需求，大学生发布家教信息，双方可搜索筛选对方信息，进入站内聊天，在双方同意后交换联系方式。

MVP 首要验收标准是核心功能流程可以完整走通且不出现异常，尤其要保证联系方式和私密数据不会被未授权访问。

## 2. 产品定位

### 2.1 一句话定位

一个面向本地家教供需的自助撮合平台，让家长和大学生通过结构化信息、筛选、聊天和双向同意交换联系方式完成初步对接。

### 2.2 MVP 范围

第一版采用“标准 MVP 版”：

- 手机号注册登录。
- 登录后主页面提供家长端和大学生端身份入口。
- 家长发布家教需求。
- 大学生发布个人家教信息。
- 双方可搜索筛选对方发布的信息。
- 双方可进入基础实时文字聊天。
- 双方可在聊天中请求交换联系方式。
- 对方同意前必须二次确认。
- 同意后聊天界面展示双方已存档联系方式。
- 大学生可填写能力说明，并可选上传证明图片。
- 使用腾讯云 CloudBase 免费额度优先完成数据端、后端和部署验证。

### 2.3 不做范围

MVP 不包含：

- 在线支付。
- 平台抽佣。
- 人工撮合。
- 人工审核发布内容。
- 自动推荐算法。
- 复杂排课。
- 试课记录。
- 成交追踪。
- 评价体系。
- 已读/未读状态。
- 图片、语音、撤回等复杂聊天能力。
- 举报、拉黑、封禁后台。
- 全国多城市复杂地址系统。
- 每项能力强制绑定图片证明。

## 3. 用户角色

### 3.1 访客

未登录用户。可访问首页和平台说明内容，是否允许浏览公开列表由后续实现阶段根据安全和转化策略决定，但发布、聊天、请求交换联系方式必须登录。

### 3.2 注册用户

通过手机号注册和登录的平台用户。一个手机号账号可以同时使用家长端和大学生端能力。

### 3.3 家长端用户

有找家教需求的用户。可发布家教需求、搜索大学生家教信息、发起聊天、请求交换联系方式。

### 3.4 大学生端用户

想做家教的大学生。可发布个人家教信息、搜索家长需求、发起聊天、请求交换联系方式。

## 4. 核心业务闭环

### 4.1 家长找大学生

1. 用户用手机号注册或登录。
2. 在主页面选择“我要找家教”。
3. 家长填写并发布结构化需求。
4. 家长进入家教信息广场。
5. 家长按科目、学段、价格、性别筛选大学生家教信息。
6. 家长查看某个大学生家教信息详情。
7. 家长发起站内聊天。
8. 双方通过文字聊天沟通具体情况。
9. 任意一方请求交换联系方式。
10. 对方点击同意后，系统弹出二次确认。
11. 二次确认通过后，双方在聊天界面看到彼此存档联系方式。

### 4.2 大学生找需求

1. 用户用手机号注册或登录。
2. 在主页面选择“我要做家教”。
3. 大学生填写并发布个人家教信息。
4. 大学生进入需求广场。
5. 大学生按科目、学段、预算、性别偏好筛选家长需求。
6. 大学生查看需求详情。
7. 大学生发起站内聊天。
8. 双方通过文字聊天沟通具体情况。
9. 任意一方请求交换联系方式。
10. 对方点击同意后，系统弹出二次确认。
11. 二次确认通过后，双方在聊天界面看到彼此存档联系方式。

## 5. 页面范围

### 5.1 首页/主页面

首页应承担身份入口和平台主导航职责。

核心模块：

- 平台名称和简短说明。
- “我要找家教”入口。
- “我要做家教”入口。
- 需求广场入口。
- 家教信息广场入口。
- 个人页面入口。
- 平台规则/费用说明入口。

登录后，用户应能回到主页面重新选择身份。

### 5.2 手机号注册登录页

核心能力：

- 手机号注册。
- 手机号登录。
- 验证码或其他适合 CloudBase 的手机号验证方式。
- 登录后进入主页面。

安全要求：

- 登录态必须由后端可信机制维护。
- 不能仅依赖前端判断用户身份。

### 5.3 个人页面

核心模块：

- 基础账号信息。
- 家长端资料入口。
- 大学生端资料入口。
- 联系方式管理入口。
- 我发布的需求。
- 我发布的家教信息。
- 我的聊天。

### 5.4 联系方式管理页

用户维护专门用于交换的存档联系方式。

字段：

- 手机号：必填。
- 微信号：选填。

规则：

- 存档联系方式默认不公开。
- 未完成双方授权前，任何页面和接口都不得返回对方存档联系方式。
- 用户没有填写手机号时，不能完成联系方式交换同意动作。

### 5.5 家长发布需求页

采用结构化发布，不做自由发帖。

字段：

- 希望老师性别：固定选项。
- 所需科目：固定选项，多选。
- 学段/年级：固定选项。
- 可接受预算区间：必填，单位为元/小时。
- 可上课时间段：固定选项，多选，例如周一至周日搭配上午、中午、下午、晚上。
- 地址：固定选项选择省、市、镇街、区等层级。
- 具体位置：最多填写到小区或村，不填写门牌号。
- 孩子简介：最多 100 字。

规则：

- 孩子简介不得填写手机号、微信号或详细门牌地址。
- 具体上课时间和详细地址由双方聊天后确认。
- MVP 不做人工审核，但应做基础字段校验和敏感信息校验。

### 5.6 大学生发布家教信息页

字段：

- 性别：固定选项。
- 学校：填写或固定选项，MVP 可先从东莞大学城相关学校开始。
- 专业：文本填写。
- 可教科目：固定选项，多选。
- 可教学段：固定选项，多选。
- 可上课时间段：固定选项，多选。
- 按学段和科目填写课时费区间。
- 能力说明：文字填写。
- 证明图片：可选上传。

规则：

- 能力说明可包含成绩、证书、擅长科目、过往家教经验。
- MVP 不强制每项能力都上传证明图片。
- 上线后根据家长反馈和虚假信息情况，再决定是否升级为每项能力必须绑定证明图片。

### 5.7 需求广场

面向大学生浏览家长需求。

筛选条件：

- 科目。
- 学段。
- 预算区间。
- 性别偏好。

列表展示：

- 科目。
- 学段。
- 区域。
- 预算区间。
- 性别偏好。
- 孩子简介摘要。

不做：

- 时间段筛选。
- 智能排序。
- 地图找需求。

### 5.8 家教信息广场

面向家长浏览大学生家教信息。

筛选条件：

- 科目。
- 学段。
- 课时费区间。
- 性别。

列表展示：

- 姓名或昵称。
- 性别。
- 学校。
- 专业。
- 可教科目。
- 可教学段。
- 课时费区间摘要。
- 能力说明摘要。

不做：

- 时间段筛选。
- 智能推荐。
- 认证排序。

### 5.9 详情页

需求详情页展示家长需求完整结构化信息，但不展示家长联系方式。

家教信息详情页展示大学生家教信息、能力说明和可选证明图片，但不展示大学生联系方式。

详情页提供发起聊天入口。

### 5.10 聊天页

MVP 只做基础实时文字收发。

核心能力：

- 发送文字消息。
- 按时间展示消息。
- 展示当前聊天对象基础信息。
- 发起“请求交换联系方式”。
- 处理对方的交换联系方式请求。
- 点击同意后弹出二次确认。
- 二次确认通过后展示双方存档联系方式。

不做：

- 已读/未读。
- 撤回。
- 图片消息。
- 语音消息。
- 表情包。
- 消息通知中心。
- 拉黑举报。

## 7. 权限与安全要求

### 7.1 登录要求

以下动作必须登录：

- 发布家长需求。
- 发布大学生家教信息。
- 发起聊天。
- 发送消息。
- 请求交换联系方式。
- 同意交换联系方式。
- 查看已授权交换的联系方式。

### 7.2 数据归属

后端必须校验数据归属：

- 用户只能修改自己发布的需求。
- 用户只能修改自己发布的家教信息。
- 用户只能查看自己参与的聊天会话。
- 用户只能发送消息到自己参与的会话。
- 用户只能处理发给自己的联系方式交换请求。

### 7.3 防越权要求

必须防止：

- 修改 URL 或 ID 查看他人聊天。
- 修改 URL 或 ID 查看他人未授权联系方式。
- 调用接口修改他人需求或家教信息。
- 枚举用户 ID、需求 ID、会话 ID 获取私密数据。
- 前端隐藏按钮但后端无权限校验。

### 7.4 联系方式保护

联系方式保护是 MVP 核心安全要求：

- 存档联系方式默认不公开。
- 需求详情和家教信息详情不得返回联系方式。
- 聊天接口在未授权前不得返回对方联系方式。
- 同意交换联系方式必须二次确认。
- 二次确认通过后，只向该会话双方展示联系方式。

### 7.5 发布内容校验

MVP 不做人工审核，但要做基础自动校验：

- 必填字段不能为空。
- 孩子简介最多 100 字。
- 孩子简介不得出现手机号、微信号等联系方式。
- 地址不得填写详细门牌号。
- 预算区间和课时费区间必须合理。

## 8. 技术栈初步决策

### 8.1 推荐技术栈

MVP 初步技术栈：

- 前端：Next.js。
- 数据端和后端能力：腾讯云 CloudBase。
- 数据库：CloudBase 数据库优先。
- 后端逻辑：CloudBase 云函数或云托管能力优先。
- 部署：腾讯云 CloudBase 免费额度优先。

### 8.2 技术验证重点

进入开发前需要验证：

- CloudBase 是否满足手机号登录需求。
- CloudBase 权限规则是否能支持需求、家教信息、聊天、联系方式交换的数据权限边界。
- CloudBase 是否能支撑基础实时或准实时文字聊天。
- CloudBase 免费额度是否足够 MVP 早期访问量。
- 图片证明上传和存储是否可在免费额度或低成本范围内实现。
- Next.js 部署到腾讯云 CloudBase 的流程是否稳定。

### 8.3 暂不采用

MVP 暂不默认采用海外数据库服务，避免中国大陆访问不稳定。

## 9. 验收标准

MVP 首要验收标准是功能闭环稳定可走完。

### 9.1 家长流程验收

- 用户可以手机号注册登录。
- 用户可以从主页面进入家长端。
- 用户可以发布结构化家教需求。
- 发布时必填字段校验正常。
- 孩子简介超过 100 字时阻止提交。
- 家长可以浏览大学生家教信息广场。
- 家长可以按科目、学段、价格、性别筛选。
- 家长可以进入家教信息详情。
- 家长可以发起聊天。
- 家长可以请求交换联系方式。
- 对方同意并二次确认后，家长可以看到双方存档联系方式。

### 9.2 大学生流程验收

- 用户可以从主页面进入大学生端。
- 用户可以发布家教信息。
- 用户可以按学段和科目填写课时费区间。
- 用户可以填写能力说明。
- 用户可以可选上传证明图片。
- 大学生可以浏览需求广场。
- 大学生可以按科目、学段、预算、性别偏好筛选。
- 大学生可以进入需求详情。
- 大学生可以发起聊天。
- 大学生可以请求交换联系方式。
- 对方同意并二次确认后，大学生可以看到双方存档联系方式。

### 9.3 聊天与联系方式验收

- 双方可以实时或准实时发送文字消息。
- 消息按时间顺序展示。
- 未同意交换联系方式前，聊天界面不展示联系方式。
- 未同意交换联系方式前，接口不返回对方联系方式。
- 点击同意交换联系方式后必须出现二次确认。
- 二次确认通过后，聊天界面展示双方存档联系方式。
- 未填写必填手机号的用户不能完成同意交换联系方式动作。

### 9.4 安全验收

- 用户不能通过修改 ID 查看他人聊天。
- 用户不能通过修改 ID 查看他人联系方式。
- 用户不能修改他人发布的需求。
- 用户不能修改他人发布的家教信息。
- 用户不能处理不属于自己的联系方式交换请求。
- 前端隐藏不等于权限控制，关键权限必须在后端校验。

## 12. 当前已确认决策

- MVP 类型：标准 MVP。
- 撮合方式：自助撮合，不做人工介入。
- 登录方式：手机号注册登录。
- 身份体系：同一个账号可选择家长端或大学生端。
- 数据端：腾讯云 CloudBase 优先，使用免费额度启动。
- 数据区域：优先保证中国大陆访问稳定。

## 复核结果

### 1. 首屏主体

结论：通过。

`/customer-service` 页面主体验已固定渲染站内客服 `CustomerServiceChat`，不再由外部 iframe 替代。站内客服组件初始即包含欢迎消息、快捷问题列表和输入框，用户进入页面后可以直接点击快捷问题或输入问题发送。

### 2. Dify 入口

结论：通过。

Dify 已从首屏 iframe 改为侧栏可选外链。配置 `NEXT_PUBLIC_DIFY_CUSTOMER_SERVICE_URL` 时仅显示“打开 Dify 客服”入口；未配置时不影响站内离线客服出现。页面源码和测试均未命中 `<iframe` 或 `customer-service-dify-frame`。

### 3. 390px 移动端

结论：通过。

CSS 已在 `max-width: 860px` 下将 `.customer-service-main` 设置为 `order: -1`，移动端优先展示客服主体；`max-width: 720px` 下输入区改为单列，按钮满宽，消息区最小高度降低到 160px，并对页面、侧栏、主区、聊天卡片设置宽度和断行保护。开发员本地冒烟记录显示 390x844 下快捷问题和输入框均在首屏内，`scrollWidth` 等于 `clientWidth`，无横向溢出。

### 4. 开发员本地冒烟证据

结论：接受为 UI 验收证据。

本问题核心是“用户点开后是否立刻能看到并操作站内客服”。开发员回执包含桌面 1440x900 和移动 390x844 的可见性、可输入、可发送、快捷问题点击、iframe 数量、console 和横向溢出检查；这些证据与源码结构、CSS 规则和测试断言互相吻合。因此 UI 侧接受该本地冒烟作为本轮验收证据。
